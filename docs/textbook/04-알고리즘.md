# 4장. 알고리즘 — `core.js` 가 계산하는 것

`core.js` 는 하나의 UMD 모듈이다(브라우저 `window.DefDB`, Node `require('./core.js')`). 파일 입출력은 하지 않는다 — 모든 함수는 **데이터베이스 객체를 받아 결과를 돌려준다**. 함수 이름은 실제 이름이다.

| 절 | 알고리즘 | 주 함수 | 입력 → 출력 |
|---|---|---|---|
| 4.1 | 정규화 | `normalize` · `norm*` | 임의 JSON → 정해진 모양의 db |
| 4.2 | 이름·참조·어휘 매핑 | `normName` · `resolveRef` · `mapVocab` | 이름·별칭·외부 ID·별칭 값 → 번호·표준 키 |
| 4.3 | 병합 | `merge` | db + 패치 → 새 db + 보고(추가·수정·매핑·오류) |
| 4.4 | 검사 | `validate` (`validateSense`·`validateStep`·`validateLimitation`·`checkBundle`) | db → 오류·경고 |
| 4.5 | 관문 | `gate` | 이전 db + 병합 결과 → 통과 여부 |
| 4.6 | 색인 | `index` · `mechIndex` | db → 이름·위계·사슬·규칙·한계 조회 |
| 4.7 | 사건 기반 시뮬레이션 | `simulate` | db + 경로 → 발화 기록·도달·유도 경로 |
| 4.8 | 혼합 해상도 계획 | `resolutionPlan` · `siteRefsOf` | db + 경로 → 단계별 필요/갖춘 해상도 |
| 4.9 | 속도 기반 시뮬레이션 + 생애 주기·대사물 저장소 (v7) | `simulateRate` · `kineticIssues` · `moietyOf` · `sccs` | db + 경로 + 시나리오 → 시계열·원장·저장소·고갈/재생·자원 순환·감사 |
| 4.10 | 패턴 검출 | `findMotifs` · `MOTIFS` | db + 경로 → 상위 패턴 |
| 4.11 | 한계 상태·후보 | `limitationStatus` · `needMet` · `detectGaps` | db → 상태·미등록 후보 |
| 4.12 | 감사 | `auditRun` · `gapSuggest` · `massSuggest` | db + 경로 (+시나리오) → Audit Error + 교정 제안 |

## 4.1 정규화 `normalize(input)`

- `emptyDB()` 를 만들고 `terms`·`senses`·`steps`·`limitations` 를 `normTerm`·`normSense`·`normStep`·`normLimitation` 으로 하나씩 옮긴다.
- 각 `norm*` 는 문자열을 NFC·trim, 배열은 빈 값 제거, 숫자는 `Number`, 알 수 없는 필드는 버린다. 하위 구조도 `normDesc`·`normSite`·`normRule`(→`normKinetics`)·`normObs`·`normNeed`·`normEvidence`·`normContext` 로.
- 버전이 `VERSION` 과 다르면 숨은 표시 `_version` 을 남겨 `validate` 가 오류를 낸다.
- `normSense` 는 숨은 `_given` 에 *패치에 실제로 적힌 최상위 필드*를 기록한다 → 병합 때 그 필드만 교체(4.3).

## 4.2 매핑

- **이름 정규화 `normName`**: NFKC → 소문자 → α·β… 를 alpha·beta… 로 → 공백·하이픈·괄호·점·쉼표·슬래시·콜론 제거. 같은 정규형 = 같은 이름.
- **참조 해석 `resolveRef(ix, ref)`** — 순서대로 시도:
  1. 정의항 번호 `D…` 2. (패치 안) 임시 번호 3. 개념 번호 `T…`(뜻이 하나일 때) 4. `이름#n` 5. 외부 ID(`CHEBI:15422`, UniProt…) 6. 구조 지문 7. 이름·별칭.
  뜻이 여러 개면 거부하고 후보를 보이고, 없으면 비슷한 이름(`similar`, 편집 거리 ≤2)을 제안한다.
- **어휘 매핑 `mapVocab(table, value)`**: 표준 키 → 그대로, 별칭·라벨 → 표준 키(`mapped`), 없으면 가까운 값과 함께 오류.

## 4.3 병합 `merge(db, patch)`

```
0. 이전 형식 패치(terms 가 객체, definientia, states, limitations 가 객체) → 거부
1. 개념     : 기존 번호면 이름 갱신(옛 이름 → 별칭) / 같은 이름의 기존 개념이면 그 개념으로 합침 / 아니면 새 T 배정
              이름 소유 검사(claimNames): 정규화한 이름이 다른 개념의 것이면 오류
2. 정의항   : 기존 번호면 _given 필드만 교체(나머지 유지) / 새 뜻이면 이미 뜻이 있는 개념에는 distinction 필수 / 새 D 배정
3. 단계     : 기존 번호면 교체 / 새 S 배정
3b. 한계    : 기존 번호면 교체 / 새 L 배정
4. 참조·어휘 매핑 (모든 새 번호가 정해진 뒤):
   정의항의 kind·종·막·구성 요소·설명 연결·부위·규칙(효과·속도 법칙·조절자·위치)·관찰 → 번호·표준 키
   (단백질·핵산의 reference_species 를 생략하면 9606)
   단계의 rule 참조, 묶음(객체 { ref, features, location } → 정렬된 키), part_of
   한계의 target(이름/site/키 → 번호/site/키), needs(on·site·rule·cell·location·property), addresses 의 임시 L
5. 삭제     : 단계·한계·개념(그 뜻 전부)·정의항(마지막 뜻이면 개념도). 지운 정의항을 가리키던 연결은 끊는다
```
보고(`report`)에는 `added`·`updated`·`removed`·`idmap`(임시 → 실제)·`mapped`(이름·별칭 → 번호·키)·`errors`(매핑 오류)가 담긴다. 번호 배정(`alloc`)은 `meta.next` 를 올리기만 한다.

## 4.4 검사 `validate(db)`

전역 → 개념 → 정의항 → 위계 순환 → 단계 → 한계 순서로 돈다. 오류(`errors`)와 경고(`warnings`) 목록을 돌려준다.

**전역**: 형식 버전, `meta.next` > 쓰인 최대 번호, 이름 충돌(정규형 하나가 두 개념), 외부 ID·구조 지문 중복.

**정의항 `validateSense`**
- kind·종(필수/금지)·외부 ID(형식·kind 별 필수/허용, 모르면 unmapped)·지문(형식·kind)
- 막 위상: 막 결합이면 2D 위치, 주변성·지질 고정은 면 필요
- 구성 요소: complex 만, 분자 종류만, 없으면 경고
- 설명: 문장·분야·맥락, 연결의 관계 kind 제약(`relationRules`), `span` 이 문장에 있는지(없으면 오류, 비면 경고)
- 부위: 키 형식, 종류·특징 어휘, 단백질·핵산의 수식 부위는 기준 종 잔기 번호 또는 `residue_unknown`, 면은 그 막에 있는 면, `on` 은 구성 요소, 리간드는 분자, 구조 참조는 PDB 이면서 정의항 xrefs 에도 있어야(해상도 일관성)
- 규칙: 상태 의미(부위·특징 존재) / 전이(변화 종류의 허용 효과·반드시 더하거나 뺄 특징, 효과별 필드, 전제 조건, 속도 무결성 `kineticIssues`, `convert`·`degrade` 의 **부분 구조 수지** `moietyImbalance`) / 공급 `validateSupply`(where 3D 하나, 생성물, 소비 없으면 source, 법칙 zero_order|mass_action·차수 = 소비 분자 수, 부분 구조 수지 — source 면 면제) / 분해 `validateDegradation`(fate, recycled 면 recycle_to, n 양수 또는 sequence_length, when·where; 속도는 1차 k 또는 half_life, 둘 다면 ln2/t½ 일치). 분자 종류가 아닌 정의항은 공급 규칙만
- 층 `tier`(v8): 분자 종류 필수 T1|T2, T1 은 단백질·복합체·핵산 불가·부위 불가, T3 불가. 관찰: `requiresLocation`·SI `units`·값 범위. kinetics `thermoIssues`: k0·dG_act 짝, k ≈ k0·e^{−dG_act/RT}, 가역 k/k_r ≈ e^{−dG0/RT}
- 부분 구조 `moieties`: 분자 종류만, ref 는 structure_feature, n 은 1 이상의 정수. 부위 `ligands`: 특징은 그 부위의 것, 리간드는 분자
- 상위 개념: motif 는 kind process 만, `addresses` 또는 `gap_review` 필수
- 관찰: 속성 어휘, 종 의존이면 `context.species`, 값 종류·단위

**단계 `validateStep`** — 단계는 규칙의 한 번 적용:
1. 규칙이 원천의 전이 규칙인가, `part_of` 가 pathway 인가
2. 묶음 `checkBundle`: 키 형식·정렬, 바탕이 참여 가능한 종류, 위치가 막 위상과 맞나, 부위·특징이 바탕에 정의돼 있나
3. 행위자: agent 규칙이면 소유자의 묶음이 agents 에 있고, 상태 의미 규칙상 **비활성이 아님**
4. 변화량 = 규칙 효과 (효과 종류별 — 3장 표). 수송 외에는 위치가 바뀌면 오류
5. 전제 조건(`requires`), 보조 기질(`with`), 조절자는 규칙에 정의된 것만
6. 위치 조건(`where`)과 **공간 접촉**(`locCompatible`): 반응 중심(행위자, 없으면 대상)과 모든 참여자가 맞닿을 수 있어야 함. 3D–3D 같은 부피(부모·자식 포함), 2D–3D 는 그 막 면이 맞닿은 부피, 2D–2D 는 같은 막·같은 면. 수송된 대상은 제외
7. **동일성 보존**(`entityTally`): 결합(partner)·해리·결합체·전달·분해·수송에서 입력과 출력을 기본 실체로 펼쳐 센 수가 같아야 함. 복합체 → 구성 요소(재귀), 채워진 부위 → 그 리간드(부위가 구성 요소 위면 그 개수만큼, 리간드가 복합체면 다시 펼침). 행위자·보조 기질 제외, 분해는 분해된 구성 요소·산물 제외
8. 속도 법칙이 있으면 차수·두 분자 결합 검사

**한계 `validateLimitation`**: 번호, target 존재(부위·규칙까지), 종류 어휘, 요구 문장, needs 하나 이상과 각 종류별 검사(관찰 속성·정의항, 부위, 외부 ID 가 그 kind 에 허용되는지, 규칙·속도 상수 이름), resolution 의 근거.

## 4.5 관문 `gate(before, result)`

이전 db 와 병합 결과를 둘 다 검사하고, **새로 생긴** 오류·경고만 센다(이미 있던 문제로 새 패치를 막지 않기 위해).
통과 = 바뀐 것이 있고 ∧ 매핑 오류·새 오류 0 ∧ (새 경고 0 ∨ `allowWarnings`). `dbtool merge` 는 통과할 때만 `db.json` 을 쓰고 `data/patches/` 에 기록한다.

## 4.6 색인 `index(db)`

한 번 만들어 여러 조회에 쓴다(쓰지 않음 — 읽기 전용).
- 이름 → 개념(`names`), 외부 ID·지문 → 정의항, 개념 → 뜻 목록, `label`(사람용 꼬리표: 이름, 뜻이 여럿이면 `이름#n`, 단계·규칙은 규칙 라벨)
- **개념 위계** `edges`: 설명 연결(is_a·part_of·instance_of 는 축, 나머지는 옆) + 구성 요소를 has_part 로. `parents`·`children`·`sides`
- `ruleOf`·`ruleOwner`, `activityOf(묶음 키)` — 상태 의미 규칙을 위에서부터 적용해 첫 일치
- `bundleLabel`·`siteLabel`(기준 종 잔기 번호 붙임), `limitsOf(정의항)`·`addressedBy(한계)`
- **기전 색인 `mechIndex`**: 묶음 키 → 그것을 쓰는/만드는 단계. `next`(출력 키 = 다른 단계의 입력·행위자·조절자 키, minor 제외)·`prev`·`order`(위상 정렬, 순환은 남은 것부터)·`stepsIn(경로)`(part_of 위계 아래 모든 경로의 단계, 구성 요소 위계는 제외)·`roles`

## 4.7 사건 기반 시뮬레이션 `simulate(db, 경로, opt)`

**시작 풀**
1. 어느 단계에서든 부산물(minor)이거나 보조 기질(with)이거나, 어떤 단계도 만들지 않는 변환 기질이면 → 대사물 풀(`bulk`, 기본 1000)
2. 어떤 단계도 만들지 않는 입력·행위자(원천 묶음) → 시작량: `opt.init` > **데이터**(구획 농도 모델: 정의항의 `copy_number` 관찰, 없으면 `concentration` × 구획 부피 × N_A) > 기본값(`amount`, 10, "농도 공백"으로 표시)
3. **순환의 휴지 상태 보충**: 묶음 의존 그래프(입력·행위자 → 출력)의 강결합 요소(Tarjan)를 구하고, 도달 가능성 고정점에서 막힌 단계가 필요로 하는 순환 안의 묶음 중 **가장 상류 순환의, 특징이 가장 적은 것 하나**만 보충 → 다시 계산. (예: Gs[GDP], 빈 LBP)

**발화**: 라운드마다 단계 순서대로, 각 단계를 `k = min(행위자 수, 입력이 허락하는 횟수)` 번 발화(촉매는 소비되지 않음). 목표 묶음이 생기면 멈춘다.

**유도 경로**: 목표 묶음을 처음 만든 단계에서 거꾸로, 그 단계가 쓴 (minor 아닌) 묶음을 처음 만든 단계를 따라간다. 생산자가 없는 묶음이 뿌리. `--from` 이 뿌리에 있으면 "출력이 입력에서 유도됨".

## 4.8 혼합 해상도 계획 `resolutionPlan(db, 경로)`

단계마다:
- `siteRefsOf`: 규칙이 건드리는 부위 — effect.site(대상), from_site, partner_site, via_site, requires 의 부위
- **필요 해상도**: 부위가 있으면 R1(**T1** 부위 사건), 결합체·해리·분해면 R1(**T2** 화학량), 대사물 풀이 아닌 같은 묶음을 두 단계 이상이 소비하면 **T3** 경쟁 — 그 규칙에 속도 상수가 없으면 R2
- **갖춘 해상도**: 건드리는 부위가 모두 `structure` 를 가지면 R2, 부위·구성 요소가 있으면 R1, 아니면 R0
- `ok` = 갖춤 ≥ 필요, 또는 (필요 R2 ∧ 속도 상수 있음 — 경쟁을 속도로 해결)

하향 전환(반응 중심 → 풀)은 별도 계산이 없다: 바뀐 부위는 묶음 키에 남고(무손실), 수송·해리의 특징 보존은 `validateStep` 이 검사한다.

## 4.9 속도 기반 시뮬레이션 `simulateRate(db, 경로, { scenario, t_end, dt, reservoirs, stochastic, seed })`

v7 부터 이 함수는 **생애 주기·대사물 저장소** 엔진이다.

**준비**
1. 시작 풀은 4.7 과 같다(`simulate` 를 0 라운드로 불러 재사용, 시나리오의 `reservoirs`·`amounts` 를 init 으로). 저장소 묶음(보조 기질·부산물·만들어지지 않는 변환 기질)의 시작량은 시나리오 → 데이터(copy_number, 농도 × 부피) → 기본값 1000(농도 공백).
2. **분해 규칙 붙이기**: 범위 안 묶음마다 바탕 정의항의 `degradation` 규칙 중 `when`(부위:특징)·`where`(위치)가 맞는 것. k_deg = `k` 또는 ln2/`half_life`. 재활용 단위의 묶음(`단위|위치`)은 저장소로 추가 — `n: "sequence_length"` 는 관찰에서 읽고, 없으면 그 단위는 소실로 처리하고 AUDIT_RESOURCE.
3. **공급 규칙 켜기 (닫힌 집합)**: 모든 정의항의 `supply` 규칙 중, `소비·생성 분자|where` 묶음이 시뮬레이션에 하나라도 있는 것을 켜고, 그 규칙의 나머지 분자도 저장소로 추가 — 더 켜질 것이 없을 때까지 반복. 그래서 GTP 를 쓰는 경로에 NDPK(GDP + ATP → GTP + ADP)가 켜지면 ATP·ADP 저장소가 생기고, 그것에 닿는 ATP 재생 공급도 켜진다.
4. 단계마다 반응 부피(4.9 v6 와 같음: 첫 3D 위치 — 시나리오 `volumes` > `compartment_volume` 관찰; 막(2D) 참여자는 그 3D 부피로 환산). 속도 법칙: 시나리오 `kinetics[규칙]` > 규칙의 `kinetics` > 없음(즉시).
5. **질량 감사 준비**: 묶음 → 기본 실체 벡터(`entityTally`: 복합체는 구성 요소로, 채워진 부위는 `ligands[특징]` 또는 `ligand` 로), 실체 → 부분 구조(`moietyOf`). 단계마다 한 번 일어날 때의 국소 Δ(실체, 그 규칙의 화학 실체 제외 / 부분 구조)를 미리 계산. 화학 실체 = 변환 기질·산물, 분해 구성 요소, `with`, 그리고 수식 부위에서 특징과 함께 바뀌는 리간드(Gs 의 GTP → GDP).

**매 Δt**
1. **반응 단계** — 유한 저장소(`finite`, 기본)면 저장소 입력·출력도 화학량대로 셈. 속도 법칙에는 비가산(minor 아닌) 입력만, minor 는 한도로만.
   - `mass_action`: v = k·Π[입력]^n·Π[행위자] − (가역이면) k_r·Π[출력]^n · `binding`: v = k_on·[A][B] − k_off·[AB] · `michaelis_menten`: v = kcat·[E]·[S]/(Km+[S])
   - 즉시: 저장소가 아닌 자기 입력이 허락하는 만큼(없으면 행위자 수만큼), 저장소는 한도로만.
   - 진행량 ξ = v·N_A·V·Δt 를 입력 가용량으로 자른다. 원하던 것보다 덜 일어났고 원인이 저장소면 **멈춤(stalled)** 사건. 첫 발화 때 국소 수지 위반이면 AUDIT_MASS(단계·시각). 공유 결합 수식(리간드 없는 부위의 modify)의 부분 구조 Δ 는 '공유 결합' 경로로 원장에.
   - 무한 풀(`infinite`)이면 v6 처럼 저장소를 빼고 교환 원장(`exIn`·`exOut`)에.
2. **공급 규칙** — `zero_order` v = k, `mass_action` v = k·Π[소비]^n. ξ 를 소비 가용량으로 자른다. 화학 실체가 아닌 산물(합성된 단백질 등)은 생성 원장에, `source` 공급의 부분 구조는 '계 밖' 경로에.
3. **분해 규칙** — 결정론 x = N(1 − e^{−kΔt}) 또는 확률적 x ~ 이항(⌊N⌋, p) (+ 소수부 베르누이; `seed` 로 재현). 묶음에서 빼고 그 실체를 소멸 원장에, 재활용 단위는 저장소에 더하고 생성 원장에. 부분 구조는 '소실'·'재활용' 경로에.
4. **전역 질량 감사** — 실체(화학 실체 제외): 시작 + 생성 − 소멸 (+ 교환) = 지금? 부분 구조(유한 저장소): 시작 + 공유 결합 + 계 밖 + 소실 + 재활용 = 지금? 처음 어긋난 시각을 기록.
5. **고갈·재생** — 저장소가 1 분자 아래로 내려가면 `exhausted`, max(2, 시작의 1%) 이상으로 돌아오면 `regenerated` (처음부터 비어 있던 산물 저장소가 채워지는 것은 사건 아님). 음수면 엔진 오류로 AUDIT_MASS.

6. **정지 감지** — 단계 순환(저장소가 아닌 비가산 묶음으로 이어진 단계의 SCC, `sccs`)의 진행 = min(누적 ξ). 창 동안 1 바퀴 미만(또는 `death_frac` × 최고 속도 미만)이면 정지 — 한 바퀴 이상 돈 뒤에만. 마지막으로 바퀴 수가 정수로 늘어난 시각을 기록. `until_death` 면 정지 확인 즉시 끝. 속도 법칙 단계가 한 Δt 에 입력의 몇 %를 쓰려 했는지(적분 안정성)도 기록.

**사후 분석** (`postMortem`): 끝까지 고갈된 감시 입력 저장소 중 가장 먼저 고갈된 것 = 제한 요인(cause exhaustion, t_death = 그 고갈 시각). 고갈이 없으면 가역 질량 작용 단계의 역/정 비가 가장 큰 단계 = 병목(> 0.5 이면 equilibrium), 아니면 끝까지 0 인 중간물(intermediate_drained), 아니면 kinetic_stall (t_death = 마지막 바퀴 시각). 폐기물·소비/생산 비·0 에 닿은 순서를 붙이고, AUDIT_RESOURCE 로 Resource_Gap/Kinetic_Gap 교정 제안.

**끝**: 평형 일치(닫힌 두 분자 결합, 분해가 끼면 건너뜀), 저장소 분류(켜진 소비자·생산자로 closed · consumed_only · produced_only · idle), 저장소 분자 그래프(반응·켜진 공급의 소비 → 생성)의 강하게 연결된 성분 = **자원 순환**, AUDIT_RESOURCE(재생 경로 없음)·AUDIT_CONCENTRATION(저장소 시작량 기본값)·AUDIT_KINETIC_GAP(즉시 단계, 적용 안 한 공급·분해 규칙)·2D 환산 → 감사 목록. 결과에 `ledger`(묶음별 Δ 반응·공급·분해·재활용), `reservoirs`, `events`, `stalls`, `cycles`, `supplies`, `degradations`, `channels`.

## 4.9A 열역학 (v8) `rateAt` · `thermoLoops`
- `rateAt(kin, {pH, eps})` → `{kf, kr, dG_env}`: kf = k0·e^{−(dG_act+ΔG_env)/RT} (없으면 k·e^{−ΔG_env/RT}), kr = kf·e^{dG0/RT} — 환경과 무관하게 kf/kr = e^{−dG0/RT}.
- `thermoLoops(db, 경로)`: 비가산 묶음으로 이어진 단계의 SCC 마다 순 화학량(모든 입력·출력) 계산 → 0 이면 닫힌 고리, 모든 단계에 dG0 가 있으면 |ΣdG0| ≤ loop_tolerance 여야 함 (`auditRun` 이 AUDIT_THERMO 로).
- 실행 층(`engine/hmse.js`, 지식 밖): `applyLedgerTx`(인접 두 원장만, 버전 충돌·멱등·정수), `sampleTransfer`(포아송·나머지 이월·pending), `domainScore`/`decideTransition`(S = w1⟨|∇²C|⟩ + w2 ∂S/∂t, 히스테리시스·t_min), `conservativeProject`, `distributeCounts`.

## 4.9B 실행 층 P3 — `engine/devs_scheduler.js` · `engine/fv_solver.js`
- **스케줄러** `createScheduler(handle)`: t_next = min(모델 tn) → 같은 시각의 모델(Parallel DEVS 묶음) → λ 출력 패킷을 (source, target, species) 로 정렬 → 경계 엔진이 정수 거래로 커밋 → 영향받은 모델을 id 순서로 δconf/δint/δext. 매 사건 전에 safeTime = min_u(tLast_u + lookahead_u) 를 넘으면 오류, 시각 역행도 오류 (롤백 없음).
- **경계 엔진** `makeBoundaryEngine`: μ_out·μ_in(양방향 분리) → `sampleTransferFixed`(나머지 1e-9 정수, 부족분 pending) → 순 이동이 0 이 아니면 `applyLedgerTx`, 버전 충돌이면 다시 읽고 seq 를 올려 재시도.
- **영역 모델(T3)**: `fv_solver` — 기준 경계 마스크 안의 면 유속(확산 중심 차분, 이류 MUSCL+minmod), 칸 안 1차 반응, 부분 단계 수 = 안정 조건. 반응량은 이월로 정수화해 `applyLocalTx`(부분 구조 검사)로 원장에, 그 뒤 종마다 Σ칸 = 원장으로 재척도.
- **노드 모델(T2)**: 성향 a = k·Π C(n,ν). a·Δt_min > leap_threshold 인 통로는 적응 τ-도약(τ ≤ ε / max k_eff, 성향 동시 계산, μ > 10³ 이면 CLE), 나머지는 SSA. ta ≤ Δt_min 이라 시간축이 멈추지 않음.
- 검증: `node tests/p3_end_to_end.js` (영역 10⁴ 단계, |N_initial − N_final| < 1).

## 4.9C 실행 층 P4 — 대리 모델·OOD·비동기 대체
- `fno_surrogate`: `calibrate` 가 P3 FV 로 무작위 장 K 개를 한 거시 단계 보내 모드별 이득 g = Σŷx̂/Σx̂² 를 학습 (상자에서는 FV 를 정확히 재현). `integrate` = ½반응(행렬 지수) → DCT·g·역 DCT → ½반응, 반응 쌍의 순 진행량을 돌려줌. `reconcileMass` = max(0,·) → Σ = N_ledger.
- `ood_detector`: 학습 = 워밍업 FV 스냅숏의 E_spec·V_grad 최댓값 × 1.5. `evaluate(det, region, sur, 'pre'|'post', { fields, E })` → S_ood, 즉시 OOD 사유(template·advection·reaction_pairs·non_finite·negative_mass).
- `async_fallback_worker`: `submit`(inline 즉시 / worker 공유 메모리) → `join`(Atomics.wait) → `FV.reconcile` 로 원장. 영역 모델은 다음 사건의 λ 직전에 join.
- 영역 모델 `solver: { mode: 'surrogate', warmup, executor }`: 워밍업 동안 FV + 스냅숏 → 학습 → 매 단계 대리 추론 + 사전·사후 탐지 → OOD 면 출력 폐기·FV. 측정: `node tests/p4_benchmark.js`, 종단: `node tests/p4_end_to_end.js`.
## 4.9D 실행 층 P5 — 동적 승격·강등 관문 `engine/p5_dynamic_gate.js`
- 영역 모델 `solver: { mode: 'dynamic', gate: { K_up, K_down, M, W } }`. 매 거시 단계: `stiffness(spec, Δt)` → N_sub (FV `substepsFor` 와 같은 연산, C_CFL = 6/0.4 = 15) → `decide(gate, step, N_sub, γ함수)` → 경로 fv | surrogate.
- 상태 기계: FV_ONLY 에서 N_sub ≥ K_up(15) 이 M(5) 단계 연속이고 γ ≤ γ_max 이면 승격. PROMOTED 에서 N_sub < K_down(8) 이면 강등. 8 ≤ N_sub < 15 대역에서는 현재 상태 유지 → 떨림 없음.
- 사전 필터 `shockGamma` γ = max|∇²u|/(ū + ε), O(N), 승격 상태·승격 후보일 때만 계산. γ_max = 워밍업 스냅숏 최댓값 × 3. γ > γ_max 또는 대리 출력 OOD → 같은 단계 강제 강등(출력 폐기, FV) + W(20) 단계 냉각.
- 전이 질량 협정 `exactAnchor`: 음수 0 으로 → 보상(Kahan) 합 → N_ledger 로 재척도 → 남은 부동 소수 차이를 가장 큰 칸에 → 보상 합으로 검증. |Σu − N|/N ≤ 1e-15. 승격 직전(드리프트 기록 후 제거)·강등·매 동적 단계 뒤.
- 이득 `fno_surrogate.analyticGains`: g = (1 + Δt_sub·D·λ_k)^{n_sub}, λ_k = −(2/h²)Σ(1 − cos πk_d/n). 최소 제곱 학습값과 같고, D 가 바뀌면 재학습 없이 O(N).
- `mode: 'fv'`(P3) 는 비트 단위로 바뀌지 않는다. 동적 모드의 FV 경로는 FV.step + 정밀 닻(P3 닻은 ~1e-13 표류). 종단: `node tests/p5_dynamic_promotion.js`.
## 4.9E 세포 운명 (v9) — `engine/fate_engine.js` `simulateFate(db, 세포 상태, { scenario, mode })`
- 조립: 시작 상태에서 `transitions` 로 닿는 상태 집합 → 규칙 = 상태들의 대사 프로그램 + 표지 정의항의 공급 규칙 + 계 안 묶음의 분해 규칙, 조절 = 이 규칙들을 대상으로 하는 모든 modulation. 표지를 만들거나 없애는 규칙 = 느린 층, 나머지 = 빠른 층.
- 빠른 층은 반응 진행량 ξ 로 적분 (N = N₀ + S·ξ, 원장도 ξ 에서) → 부분 구조 수지는 구성상 맞고 매 느린 단계 감사(시작 + 공급 − 소실 = 지금).
- P5 관문: 느린 단계 Δ 마다 N_sub = ⌈λ_max·Δ / 0.1⌉. FV_ONLY ↔ 명시 부분 단계 N_sub 번, PROMOTED ↔ 역방향 오일러 한 번(진행량 뉴턴, 감쇠로 음수 금지 — 빠른 층의 준정상 상태). 신호 급변·저장소 고갈 = 충격 → 같은 단계 강등 + W 냉각, 뉴턴 실패 → 그 단계 명시 대체.
- 느린 층: 배율을 고정하고 정확한 지수 해 N' = N·e^{−kΔ} + (s/k)(1 − e^{−kΔ}).
- 상태 거리: 표지마다 문턱 밖 로그 부족분(0–1)의 평균, 0 = 그 상태. 결정(withdrawal): 스냅숏에서 신호를 끊고 horizon(24 h) 동안 돌려 목표 상태로 끝나면 결정 — 2 h 격자(단조성 확인) + 이분 탐색.
- 분화 정지: 잘리지 않은 로그 거리의 진전이 창(6 h) 동안 0.01 미만. 사후 분석은 실패한 표지 → 합성 규칙의 조절 점유율 → 가장 약한 활성화 인자 → 그것을 만드는 빠른 규칙을 너비 우선으로 → 고갈된 저장소(고갈 시각 = 실패 지점). 원인 resource_exhaustion · signal_insufficient · antagonist_dominance · alternative_fate · kinetic_stall, 교정 제안은 그 종류의 열린 한계.
- 시험: `node tests/fate_suite.js` (충실도·경쟁·결정 비가역성·분화 정지·다른 운명·다중 규모 정확도·질량, 30 검사). 명령: `node dbtool.mjs fate <세포 상태> --scenario s.json`.

## 4.10 패턴 검출 `findMotifs(db, 경로)`

`MOTIFS` 의 검출기마다 단계 목록에서 구조를 찾는다. 사슬은 순환이 있어도 찾도록 모든 단계에서 출발하고, 다른 사슬에 포함되거나 같은 순환을 다른 곳에서 시작한 사슬은 버린다.

| 패턴 | 검출 조건 |
|---|---|
| receptor_signaling | 세포 밖 입력 → 세포막 출력 |
| ligand_relay | 전달(transfer) 단계가 묶음으로 이어짐 |
| receptor_clustering | 전제 조건이 있는, 행위자 없는 결합체 형성 |
| scaffold_assembly | 행위자가 있는 결합체 형성 |
| second_messenger | 효소의 변환 산물(저분자)을 다른 비변환 단계가 씀 |
| kinase_cascade | 인산화 단계의 출력이 다음 인산화 단계의 행위자 |
| gtpase_timer | 서로 먹이는 두 단계 중 하나가 가수분해 modify |
| inhibitor_degradation_release | 분해 단계의 출력이 수송 단계로 |
| nuclear_translocation_transcription | 핵질로 수송 → 3단계 안에 전사 |
| membrane_to_nucleus | 위치 궤적에 세포 밖·막과 핵질, 그리고 수송 |

`trajectory`: 단계 순서대로 처음 나타나는 위치의 순서. kind process 정의항의 `motif` 가 이 키를 가리키면 그 정의항의 사례 경로는 이 계산 결과다.

## 4.11 한계 상태 `limitationStatus` · 후보 `detectGaps`

- `needMet` 이 need 하나씩 충족 여부를 본다(3.5 표). 모두 충족 → resolved, manual 이 resolution 으로 닫힘 → resolved_manual, 아니면 open. `done/total` 도 함께. 분해 규칙의 kinetics need 에서는 `k` 와 `half_life` 가 서로를 대신한다.
- `detectGaps`: (1) `residue_unknown` 부위 중 어떤 한계의 target·needs 에도 없는 것 → Structural_Gap 후보, (2) 속도 상수가 없는 공급·분해 규칙 중 어떤 한계의 target·needs.rule 에도 없는 것 → Kinetic_Gap 후보, (3) `recycle_to` 가 `sequence_length` 를 쓰는데 관찰이 없고 그 관찰을 요구하는 한계도 없는 정의항 → Structural_Gap 후보.

## 4.12 감사 `auditRun(db, 경로, opt)`

`validate` 오류(AUDIT_SCHEMA) + `resolutionPlan` 에서 ok 가 아닌 단계(AUDIT_RESOLUTION) + `simulateRate` 의 감사(AUDIT_KINETIC·KINETIC_GAP·CONCENTRATION·MASS·RESOURCE·RESOLUTION 2D)를 모은다. 각 항목에 교정 제안:
- `gapSuggest(type, hint)`: 같은 종류의 열린 한계 중 힌트(예: `/2D|면적/`)에 맞는 것 → 대상이 같은 것 → 아무것이나, 그 한계의 **아직 없는 데이터**를 나열. 없으면 "등록할 것: [대상 | 종류 | …]".
- `massSuggest(실체)`: 그 실체를 구성 요소·부위 리간드로 가진 정의항까지 넓혀, 그것을 대상으로 한 열린 한계.
