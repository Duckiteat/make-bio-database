# 8장. 한계와 진화 — 시스템이 자기 한계를 설계도로 쓰는 방식

## 8.1 왜 한계를 데이터로 두나

실패를 로그 한 줄로 넘기면 같은 실패가 다른 경로에서 반복되고, 무엇을 채우면 나아지는지 아무도 모른다. 이 시스템은 실패·우회·추정·단순화를 **대상이 정해진 구조화된 기록**(L…)으로 남기고, 각 기록에 **해결 경로**(정확히 어떤 데이터가 들어오면 닫히는지)를 둔다. 그러면

- 한계는 데이터가 들어오는 순간 **자동으로** 닫히고(`limitationStatus`),
- 감사 오류는 **어느 한계를 채우면 되는지**를 제안하며(`gapSuggest`·`massSuggest`),
- 새 개념은 **어느 한계를 겨냥하는지** 적어야만 저장된다(`addresses`/`gap_review`).

## 8.2 세 종류

| 종류 | 무엇이 모자라나 | 해결 경로의 전형 |
|---|---|---|
| Kinetic_Gap | 속도(kcat·Km·k_on·k_off), 친화도(Kd), 시간 상수 | `kinetics` (규칙의 상수) |
| Concentration_Gap | 몰 농도, 세포당 분자 수, 구획 부피, 질량 수지 | `obs` (copy_number·concentration·compartment_volume) |
| Structural_Gap | 3차원 좌표, 잔기 번호, 화학량, 막 위상 | `residue`, `xref`(PDB), `manual` |
| Identity_Gap | 필수 외부 ID (unmapped) | `xref`(ChEBI …), 어휘에 없는 ID 체계면 `manual` |

## 8.3 진화 루프

```
① 발견    simulate · simulate --rate · audit-run · 변환 · 시연에서 실패·우회·단순화
② 기록    patch.limitations[] → merge → limitations --write
③ 설계    새 개념을 만들기 전에 limitations.md 를 읽고, 그 개념이 무엇을 어떻게 해결하는지 addresses 에
④ 구현    개념이 '이름'에 그치지 않도록 엔진이 그 개념을 쓰게 한다 (필드·검사·시뮬레이터)
⑤ 채움    확인된 데이터(관찰·잔기·ID·속도 상수)가 들어오면 해당 한계가 자동 resolved
⑥ 감사    audit-run 이 남은 위반을 다시 한계로 연결 → ①
```

## 8.4 지금까지의 진화 기록 (실제로 일어난 것)

| 발견 | 기록 | 개념·엔진 변화 |
|---|---|---|
| 순환 안에서만 생기는 Gs[GDP] 때문에 연쇄가 시작되지 않음 | (엔진 수정) | 순환의 휴지 상태 보충 — 가장 상류 순환부터 하나씩 |
| PDE 가 cAMP 를 먼저 다 먹어 PKA 가 켜지지 않음 | L000005 Kinetic_Gap | 촉매 수만큼 발화(사건 기반) → 반응 속도 모델(속도 기반) |
| NFKBIA 를 붙이자 TNF 가 NF-κB 를 다 차지 (순서 의존) | L000001 Concentration, L000004 Kinetic | 구획 농도 모델 (copy_number → 시작량) |
| 뉴클레오타이드 10개가 바닥나 두 번째 전사가 막힘 | L000002 Concentration | 만들어지지 않는 변환 기질 = 대사물 풀 |
| 두 경로에 반복되는 구조 (키네이스 연쇄 등) | — | 상위 개념 10개 (motif 로 사례 계산) |
| 막 분자를 3D 부피 농도로 환산 | L000017 Concentration | (다음: 면적 농도 모델) |
| 질량 감사가 Gs 를 AC 의 리간드·행위자로 이중 계산함을 발견 | L000018 Structural | (다음: Gαs–Gβγ 해리 모델, L000015 와 함께) |
| L000011 의 해결 경로가 엉뚱한 구조로 잘못 닫힐 수 있음 | L000011 교정 | 해결 경로는 구체적으로, 형식으로 확인 못 하면 manual |
| 3차원을 어디까지? | 혼합 해상도 모델 | R0·R1·R2, 전환 문턱 — 지금 R2 가 필요한 단계는 cAMP 경쟁 2개뿐 |
| 무한 풀(bulk)이라 고갈·재생을 말할 수 없음 | L000002 (부분), L000019–L000023 Kinetic_Gap | **대사물 저장소 모델**: 유한 저장소 + 공급 규칙(Metabolic_Supply_Rule) + 자원 순환 |
| 분자가 사라지지 않아 신호가 끝나지 않음 | L000006 (부분), L000024·25 Kinetic_Gap, L000026 Structural_Gap | **생애 주기 모델**: 분해 규칙(Degradation_Rule, k_deg, lost/recycled, 서열 길이 화학량) |
| Traceable Evolution Protocol: unmapped 값도 한계여야 함 | L000028–L000033 Identity_Gap | 한계 종류 Identity_Gap, detectGaps 가 후보로, 병합은 후보 0 일 때만 |
| 부분 구조 수지가 AC 의 피로인산, 유비퀴틴 활성화의 피로인산, 프로테아좀의 Pi 누락을 잡음 | L000027 Structural (프로테아좀 ATP 화학량) | 규칙 교정 + 피로인산 정의항 — 검사가 데이터의 빠진 산물을 드러냄 |

## 8.5 다음 진화의 후보 (열린 한계에서 읽은 것)

- **반응 속도 데이터**: L000004·5·6 — 확인된 Kd·kcat·Km 이 들어오면 경쟁·시간이 데이터로 정해진다(엔진은 준비됨).
- **면적 농도 모델**: L000017 — 막 면적·분자/µm²·2D 속도 상수 어휘.
- **Gs 해리 모델**: L000015·L000018 — Gαs·GTP 의 AC 결합과 가수분해 후 방출.
- **유비퀴틴 사슬 길이**: L000003 — 질량 수지를 정확히.
- **세포당 분자 수·구획 부피**: L000001·2·16 — 구획 농도 모델이 바로 쓴다. 저장소 시작량(ATP·GTP·뉴클레오타이드)도 같은 관찰로 데이터가 된다.
- **공급·분해 속도**: L000019–L000025 — 확인된 재생 속도·반감기가 들어오면 고갈·재생·신호 종료가 시간으로 계산된다.
- **서열 길이**: L000026 — TNF mRNA 길이가 들어오면 분해 산물이 뉴클레오타이드 저장소로 돌아간다.

지금 열린 한계의 전체 목록은 [`limitations.md`](../../limitations.md), 숫자는 [9.1절](90-부록-자동생성.md).
