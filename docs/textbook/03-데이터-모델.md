# 3장. 데이터 모델 — `data/db.json` 의 표들

```
db.json (형식 v12)
├── meta.next = { T, D, S, L, O, V }    다음 번호 (줄지 않음)
├── terms        T…  개념(피정의항) = 이름 묶음
├── senses       D…  정의항(뜻) = 원천. 구조·규칙·설명을 소유 (수치는 값 층에 — 보기로만 obs·kinetics)
├── steps        S…  기전 단계 = 원천의 전이 규칙 한 번 적용 + 묶음
├── limitations  L…  한계 = [Target | Type | Requirement]
├── observations O…  관찰 = 측정한 것 (정량 · 정성) — 바꾸지 않음, 철회만
├── values       V…  값 기록 = (대상, 속성, 맥락) 의 수치 — 바꾸지 않음, 대체·철회만 (3.7)
└── moved             이동된 번호 → 지금 번호 (있을 때만, 3.9)
```

## 3.1 식별자 문법

| 형태 | 예 | 저장되나 | 뜻 |
|---|---|---|---|
| `T` + 6자리 | `T000042` | 표의 키 | 개념 |
| `D` + 6자리 | `D000044` | 표의 키 | 정의항 |
| `S` + 6자리 | `S000009` | 표의 키 | 기전 단계 |
| `L` + 6자리 | `L000004` | 표의 키 | 한계 |
| `D…/site/키` · `D…/rule/키` | `D000044/site/reg_phos` | 경로(소유자 안의 객체) | 하위 항목 — 새 번호를 만들지 않는다 |
| `D…/desc/n` · `D…/obs/n` | `D000044/desc/1` | 경로(배열 순번, 1부터) | 설명·관찰 |
| `D…|부위:특징|…|위치` | `D000044|reg_phos:phosphorylated|cytosol` | 단계 안의 문자열 | 묶음 — 내용에서 계산되는 키, 번호 없음 |
| `T+x` `D+x` `S+x` `L+x` | `D+gp` | 패치 안에서만 | 임시 번호 → 병합 때 실제 번호 |

**접두어의 논리**: 한 글자 = 자기 번호 공간과 생애 주기(생성·수정·삭제·결번)를 가진 최상위 기록 하나. 소유된 것은 경로(`/`), 계산되는 것은 키(`|`). 새 최상위 기록(예: 가설 층)이 생길 때만 새 글자를 정한다(`core.js` 의 `ID_RE`). `# @ | /` 는 참조 문법이라 이름에 쓸 수 없다.

## 3.2 개념 `terms[T…]`

```json
"T000042": { "names": { "ko": "글리코겐 인산화효소", "en": "glycogen phosphorylase" }, "aliases": ["포스포릴레이스"] }
```
- 이름은 정규화(NFKC → 소문자 → 그리스 문자를 이름으로 → 공백·하이픈·괄호 제거) 뒤 **저장소 전체에서 하나의 개념만** 가리킨다(`normName`).
- 이름을 바꾸면 옛 한국어 이름은 별칭으로 남는다. 개념은 뜻(정의항)이 하나도 없으면 오류.

### 필드 묶음별 의미

| 묶음 | 필드 | 해석 |
|---|---|---|
| 정체성 | `kind`, `reference_species`, `xrefs`, `unmapped`, `fingerprint` | 무엇인가. 외부 ID 는 kind 별 필수·허용이 정해져 있다. 확인 못 하면 `unmapped` 에 사유 |
| 구조 | `components`, `membrane`, `site` | 무엇으로 이루어졌고 어디에 어떤 면으로 박혀 있고 어떤 부위를 갖나. 부위가 바뀔 수 있는 특징(`features`)을 정한다 |
| 규칙 | `rule[]` | **상태 의미**: 특징 조합 → 활성 (위에서부터 첫 일치, `when: {}` 은 기본값). **전이**: 이 정의항이 일으키는 변화 (효과·보조 기질·조절자·위치 조건·속도). **공급**(v7, Metabolic_Supply_Rule): 저장소의 소비 → 생성 — 경로·과정 정의항도 가질 수 있는 유일한 규칙. **분해**(v7, Degradation_Rule): 이 정의항의 묶음이 1차로 분해되고 산물이 사라지거나(lost) 저장소로 돌아감(recycled) |
| 층 (v8) | `tier`, 관찰 `diffusion_coefficient`·`pH`·`ionic_strength`·`relative_permittivity`, kinetics `k0`·`dG_act`·`dG0`·`env` | 3 층 엔진에서 이 분자가 사는 기본 층(T1 연속 장 / T2 규칙 행위자)과 Tier 1 환경·열역학 — 역 상수는 ΔG° 로만 정한다 (SCHEMA 8F) |
| 부분 구조 | `moieties`, `site.ligands` | (v7) 반응에서 깨지지 않는 부분(아데노신·인산기 …)의 개수. 변환·분해·공급 규칙의 부분 구조 수지를 검사하고, 시뮬레이터가 매 Δt 합계를 감사한다. 특징별 리간드는 채워진 부위가 품은 분자 |
| 설명 | `desc[]` | 맥락별 정의 문장. 연결의 `span` 은 문장 속 원문 구절 |
| 관찰 | `obs[]` | 종·세포·위치에 따라 달라지는 값 (Km, 분자 수, 구획 부피 …) |
| 상위 개념 | `motif`, `addresses`, `gap_review` | 경로에서 자동으로 찾는 패턴, 해결하려는 한계 |
| 외부 ID 의 역할 (v10 확장) | `xrefs[].role`: `physiological`(pH 7.3 우세 종 — 엔진·상호 운용이 읽는 번호) · `parent`(중성 모체) · `class`(중합체·불균일 물질) | ChEBI 는 같은 물질에 세 종류 항목을 둔다. 규약을 적지 않으면 섞이고, 분류 항목은 화학식이 없어 수지 대조가 건너뛰어진다 (SCHEMA 8J) |
| 세포 상태 (v9·v10 확장) | kind `cell_state` 의 `signature`(표지·high/low·위치 — 수용성은 3D, 막 분자는 그 막), `metabolome`(공급 규칙·수준), `mechanisms`(그 상태에서 돌아가는 경로 — 그 단계가 결합 적분의 반응이 됨), `transitions`(대상 상태·신호·결정 기준 withdrawal/threshold) | 분자가 아니라 상태 — 어떤 표지가 높고 낮은지로 정의되고, 신호가 다른 상태로 옮긴다. 문턱 값(분자 수)은 시나리오 `thresholds` (SCHEMA 8G) |
| 조절 (v9) | 규칙 `type: modulation` — `target`(D…/rule/키), `effect`, `at`, `via`, kinetics `hill`(K·n·fmax/fmin); 공급 소비 `saturating` | 조절자(소유자) 농도가 대상 규칙의 속도를 곱한다 — 신호 → 대사(IL-12 → 해당과정), 대사 → 유전자 조절(피루브산 → T-bet 합성), 전사 인자 상호 억제. 포화 보조 기질은 화학량대로 소비되지만 차수에서 빠진다 |

### 전이 규칙의 효과 `effect.type`

| type | 필드 | 묶음에서 일어나야 하는 일 |
|---|---|---|
| `modify` | target, site, add, remove, partner | 대상의 그 부위만 `remove → add`. partner 는 부위에 흡수 |
| `convert` | consumes, produces | 기질 묶음 → 산물 묶음 (화학 변환) |
| `associate` / `dissociate` | complex, partner, partner_site | 구성 요소 ⇄ 복합체, 개수가 정의와 맞아야 함 |
| `transfer` | partner, from_site, target, site | 리간드가 소유자의 부위에서 대상의 부위로 |
| `degrade` | complex, component, produces | 한 구성 요소를 분해 산물로, 나머지를 풀어 줌 |
| `transport` | target, from, to | 위치 변화 — 위치를 바꾸는 유일한 방법 |

`effect.requires: [{ ref, site, feature }]` — 입력 묶음이 이미 가져야 하는 특징(전제 조건).

`convert`·`degrade` 효과는 `with` 까지 합쳐 부분 구조 수지가 맞아야 한다 (v7). 예: AC 의 고리화는 ATP(아데노신 1·인산기 3) → cAMP(1·1) + **피로인산**(0·2) — 피로인산을 빼면 거부된다.

### 근거 `evidence` (설명·규칙·관찰·속도마다)

| level | 필요한 것 | 뜻 |
|---|---|---|
| `curated` | `sources: [{ db: DOI|PMID, id, citation: "저자, 연도" }]` | 실제로 확인한 문헌 |
| `abstracted` | `basis` | `[Abstracted Logic: Derived from the inferred mechanistic flow]` — 문헌이 직접 말하지 않고 흐름에서 추론 |
| `asserted` | — | 출처 없이 적은 일반 지식 |
| `computed` | `tool` | 도구로 계산 |
| `predicted` | `confidence` 0–1 | 예측 모델 출력 (시나리오 값도 여기) |

## 3.4 기전 단계 `steps[S…]` — 결과

```json
"S000009": { "rule": "D000043/rule/gp_phos",
  "agents":  [{ "b": "D000043|pka_phos:phosphorylated|cytosol" }],
  "inputs":  [{ "b": "D000044|cytosol" }, { "b": "D000032|cytosol", "minor": true }],
  "outputs": [{ "b": "D000044|reg_phos:phosphorylated|cytosol" }, { "b": "D000033|cytosol", "minor": true }],
  "regulators": [], "part_of": ["D000051"] }
```
- 단계에는 라벨·설명·위치를 따로 두지 않는다 — 규칙(`rule.label`·`text`)과 묶음 키(위치)에 있다.
- 참여자 `{ b, n, minor }`: `n` 화학량(기본 1), `minor` 부산물·보조 기질(사슬 연결에서 제외).
- **사슬 연결**: 한 단계의 출력 묶음 키가 다른 단계의 입력·행위자·조절자 묶음 키와 같으면 이어진다. 저장된 링크가 아니라 키의 일치로 계산된다.
- `part_of` 는 pathway 정의항. 작은 경로가 큰 경로의 `part_of` 이면 큰 경로의 단계에 포함된다.

### 묶음 키 `D…|부위:특징|…|위치`
- 바탕 정의항 + (부위:특징 — 부위 이름순, 빈 특징은 생략) + 위치.
- 활성은 바탕 정의항의 상태 의미 규칙으로 계산한다 (`activityOf`).
- 막 결합 분자는 자기 막(2D)에, 수용성 분자는 3D 위치에만 있을 수 있다.

## 3.5 한계 `limitations[L…]`

```json
"L000004": { "target": "D000100/rule/kb_binding", "type": "Kinetic_Gap",
  "requirement": { "text": "NF-κB 가 여러 프로모터의 κB 자리를 두고 경쟁하는데 결합 친화도가 없어 …",
                   "needs": [{ "kind": "kinetics", "rule": "D000100/rule/kb_binding", "params": ["Kd"] }] },
  "found_in": "재사용 시연(NFKBIA 표적 추가)", "resolution": { "note": "…", "evidence": { … } } }
```
- **Target**: `D…`, `D…/site/키`, `D…/rule/키`, `S…`.
- **Type** (`vocab.js gapTypes`): `Kinetic_Gap` · `Concentration_Gap` · `Structural_Gap` · `Resource_Gap` · `Regulatory_Gap` · `Observation_Gap` · `Identity_Gap` · `Consensus_Gap`(저장된 값이 더 새 원본의 합의와 다름 — 값을 지우지 않고 등급이 `legacy` 로 내려간다, 6장 추세 축).
- **구조 필드 (가 스키마, 선택)**: `symptom`(키 → 수, 단위는 키 끝) · `downstream_blocked`(막는 하류 번호) · `resolution_trigger`(`manual`·`observation_added`·`value_recorded`, 자동은 `at` 필수) · `prohibited_bypasses`(저장만). `text` 는 그대로 — 칸은 더하기만. 예: L000113 `symptom {sim_time_s: 60, wall_time_exceeded_s: 60, species_n: 42, steps_n: 22}` · `downstream_blocked [D000103, D000104, D000105]`.
- **Requirement**: 사람이 읽는 `text` + 기계가 확인하는 `needs`:

| need kind | 충족 조건 |
|---|---|
| `obs` (property, on, cell?, location?) | 그 정의항에 그 관찰이 (맥락이 맞게) 있다 |
| `residue` (site) | 그 부위에 기준 종 잔기 번호가 있고 `residue_unknown` 이 아니다 |
| `xref` (db, on) | 그 정의항에 그 외부 ID 가 있다 |
| `kinetics` (rule, params) | 그 규칙의 `kinetics` 에 그 상수들이 양수로 있다 |
| `manual` (text) | 형식으로 확인할 수 없음 — `resolution` 으로만 닫힘 |

- **상태는 저장하지 않는다**: needs 가 모두 충족 → `resolved`, manual 이 resolution 으로 닫힘 → `resolved_manual`, 아니면 `open`.
- 상위 개념은 `addresses: [{ limitation, how }]` 로 한계를 가리킨다 (역방향 색인 `addressedBy`).

## 3.6 참조 그래프 — 무엇이 무엇을 가리키나

```
terms(T) ◀── senses.term
senses(D) ◀── desc.links.to · components.ref · site.on · site.ligand · rule.effect.(target|partner|complex|component|consumes|produces)
            · rule.with · rule.regulators.ref · steps.part_of · 묶음 키의 바탕 · limitations.target · needs.on · addresses (D → L)
rules(D…/rule/키) ◀── steps.rule · needs.rule
sites(D…/site/키) ◀── 묶음 키의 부위 · rule.effect.site · requires.site · limitations.target · needs.site
limitations(L) ◀── senses.addresses.limitation
```
모든 화살표의 끝은 `validate` 가 존재·종류를 검사한다. 끊긴 참조가 있으면 관문을 통과할 수 없다.


## 3.7 값 층 `values[V…]` (형식 v12, SCHEMA §8N)

정의 그래프(T·D·S)는 안정적이고, 가장 많이 늘고 자주 바뀌는 것은 수치다. 그래서 수치를 값 층으로 뺐다.
- **기록 하나** = `{ subject: D… | D…/rule/키, property, value { dist: point | normal | lognormal | interval | categorical, … }, unit?, context?, evidence, from? [O…], derivation, recorded_at, evidence_at?, supersedes?, retracted? }`.
- **현재 값** = 철회되지 않았고 다른 기록이 대체하지 않은 기록. 정규화가 현재 값으로 정의항 `obs`·규칙 `kinetics` 를 **열거되지 않는 보기**로 붙인다 — 읽는 코드와 패치 작성법은 예전 그대로이고, JSON 에는 값 층만 나간다.
- **바꾸지 않는다**: 패치가 obs·kinetics 를 바꾸면 병합이 새 기록(`supersedes`)으로, 빠지면 철회로 접는다. 그래서 값의 이력이 남고 `model.asOf(db, 날짜)` 가 그날의 값을 다시 세운다.
- **두 시간**: `recorded_at`(이 저장소에 기록한 때 — 병합 전에 dbtool 이 패치에 찍는다, 재생 결정론) · `evidence_at`(근거가 말하는 때).

## 3.8 관찰 `observations[O…]` — 정량과 정성

- **정량**(기존): 측정량(`observable`)·값(SI)·불확도(크기·유형·잡음 모형)·반복 수·조건·용도(estimation | validation).
- **정성**(`kind: 'qualitative'`, v12 §4): 교란(`perturbation` — knockout · block · inhibit · clamp)·읽을 거리(`readout`)·기대(`expect` — 늘어남·줄어듦·같음·있음·없음·단조·순서). 값·불확도가 없는 대신 **1차 문헌(DOI·PMID) 출처와 원문 구절(`quote`)이 필수**다. 교과서·추론은 정성 관찰이 될 수 없다. 용도는 validation 만, 어떤 수치의 근거도 될 수 없다.
- 공통: `experiment`(같은 논문의 같은 실험계를 묶음 — 독립 판정의 단위) · `evidence_at` · `recorded_at`(병합이 찍음) · `provenance { sha256?, source? }`(수신함 원본 사본의 해시).

## 3.9 맥락 열쇠와 번호 이동

- **맥락 열쇠**(`vocab.contextKeys`): species · cell · location · condition · temperature_K · pH 여섯 칸. `model.contextKey(맥락)` 이 빈 칸을 null 로 채우고 조건을 정렬해 하나의 문자열을 만든다 — 같은 열쇠의 현재 값은 하나뿐. `condition` 은 정의항 번호 목록이고, 자유 문장은 `scope`(맥락 설명, 열쇠 밖)에 둔다.
- **번호 이동**(`moved`): 정의항·개념·단계를 합치거나 나눌 때 지우고 새로 만들지 않고 패치 `moved: { 옛 번호: { to, kind: merge | split, why } }` 로 옮긴다. 번호는 재사용하지 않고, 조회(`resolveRef`)는 이동을 따라가며, 이동된 번호를 가리키는 패치·정의는 관문이 대상을 알려 주며 거부한다.
