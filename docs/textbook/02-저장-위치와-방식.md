# 2장. 저장 위치와 저장 방식

## 2.1 저장 분류 — 열한 가지

저장소의 모든 파일은 아래 분류 중 하나에 속한다. 분류는 **누가 쓰는가**, **어떻게 바뀌는가**, **무엇을 믿어도 되는가**를 정한다. 파일별 분류는 [`storage-map.json`](storage-map.json)(기계가 읽는 원본)과 [9.3절](90-부록-자동생성.md)(그 표)에 있다.

| 분류 | 키 | 쓰는 방식 | 믿는 방식 |
|---|---|---|---|
| 원천 데이터 | `source` | **패치 → `merge` 로만.** 직접 편집 금지 | 지식의 유일한 원본. 다른 모든 것은 여기서 계산 |
| 기록 | `log` | 병합 성공마다 하나 추가. 고치지·지우지 않음 | 당시 형식·번호 그대로. "언제 무엇이 어떤 번호로 들어갔나" |
| 규칙 정의 | `law` | 사용자 요청 시만. 테스트·SCHEMA·교과서 함께 | 무엇이 허용되는지의 기준. 문서와 어긋나면 이쪽이 맞음 |
| 도구·화면 | `interface` | 사람·AI | 규칙을 갖지 않는 입구 (규칙은 core.js 에만) |
| 생성물 | `generated` | **명령으로만 생성**. 손으로 고치지 않음 | CI 가 최신인지 검사. 고칠 일이 있으면 원천·생성기를 고침 |
| 명세·안내 | `spec` | 사람·AI (코드를 바꿀 때 함께) | 현재 규칙의 설명 |
| 설계 기록 | `history` | 동결 | 결정의 배경. 현재 규칙의 근거 아님 |
| 형식 변환 | `migration` | 형식을 올릴 때 한 번 | 다시 실행하지 않음 |
| 검증 | `verification` | 규칙을 바꿀 때 거부 테스트 추가 | 규칙이 느슨해지면 실패 |
| 예시·시나리오 | `scenario` | 사람·AI | **지식이 아님.** `hypothetical: true` 값은 결론에 쓰지 않음 |
| 설정 | `config` | 사람·AI | — |

## 2.2 디렉터리 지도

```
make-bio-database/
├── data/
│   ├── db.json                 [source]   지식 원본 — T·D·S·L 네 표 + meta.next
│   └── patches/*.json          [log]      병합된 패치 + 매핑 결과 (시각-이름.json)
├── vocab.js                    [law]      통제 어휘 (허용 값·별칭·형식·문턱)
├── core.js                     [law]      매핑·검사·관문·색인·시뮬레이션·감사 (브라우저·Node 공용)
├── dbtool.mjs                  [interface] 명령줄 (파일 입출력만, 규칙은 core.js)
├── viewer.html                 [interface] 화면 / index.html [generated] = 복사본
├── limitations.md              [generated] 한계 등록부 표 (db.json limitations 에서)
├── SCHEMA.md · CLAUDE.md · README.md   [spec]
├── DESIGN-v4.md · FEATURES.md          [history]
├── docs/textbook/              [spec]     이 교과서 + storage-map.json
│   └── 90-부록-자동생성.md     [generated]
├── migrations/                 [migration] 001 … 005 (+ 002-id-map.json)
├── tests/rules.test.mjs        [verification]
├── .github/workflows/check.yml [verification] CI
└── examples/                   [scenario]  예시 패치 · scenarios/ 가상 시나리오
```

## 2.3 원천 데이터 `data/db.json` 의 저장 방식

- **형식**: JSON 하나, 2칸 들여쓰기, 맨 끝 줄바꿈. `merge` 와 `migrations/` 만 쓴다.
- **최상위**: `format`("definition-db"), `version`(정수, 지금 7), `meta.next`(다음 번호), 그리고 네 표 `terms`·`senses`·`steps`·`limitations` — 각각 `번호 → 객체` 사전.
- **번호 배정**: `meta.next.T/D/S/L` 이 다음 번호. 병합 때만 늘어나고 줄지 않는다. 지운 번호는 영구 결번(`validate` 가 `meta.next` > 쓰인 최대 번호인지 검사).
- **정규화**: 읽을 때 `normalize` 가 모든 필드를 정해진 모양으로 맞춘다(빈 배열 채움, 문자열 다듬기, 알 수 없는 필드 버림). 그래서 저장된 JSON 과 메모리 속 객체는 같은 모양이다.
- **저장하지 않는 것** (매번 계산 — 원칙 P6):

| 계산되는 것 | 계산하는 함수 | 근거 데이터 |
|---|---|---|
| 묶음 키의 활성 | `index().activityOf` | 원천 정의항의 상태 의미 규칙 |
| 개념 위계(위·아래·옆) | `index().parents/children/sides` | 설명의 연결 + 구성 요소 |
| 기전 사슬(앞·뒤 단계) | `mechIndex().next/prev/stepsIn` | 단계의 묶음 키가 같음 |
| 상위 개념의 사례 경로 | `findMotifs` | 단계·규칙의 구조 |
| 한계의 상태(open/resolved) | `limitationStatus` | 해결 경로(needs)의 데이터가 있는지 |
| 해상도 계획(R0·R1·R2) | `resolutionPlan` | 규칙이 건드리는 부위, 경쟁, 속도 상수 |
| 시뮬레이션 결과 | `simulate`·`simulateRate` | 단계·규칙·관찰·시나리오 |

## 2.4 기록 `data/patches/` 의 저장 방식

- 파일 이름: `YYYYMMDD-HHMMSS-<원래 패치 이름>.json`
- 내용: `{ applied_at, result: { added, updated, removed, mapped }, …패치 원문 }`. `mapped` 는 "이 패치에서 `'NF-κB'` → `D000089` (이름)" 같은 매핑 기록이다.
- 이 기록으로 데이터베이스를 다시 만들 수는 없다(형식 변환·번호 배정이 그 사이에 바뀌었기 때문) — **감사 추적용**이다. 원본은 언제나 `db.json`.

## 2.5 생성물의 저장 방식

| 생성물 | 만드는 명령 | 원천 | CI 검사 |
|---|---|---|---|
| `limitations.md` | `node dbtool.mjs limitations --write` | `db.json` limitations + 계산된 상태 | `limitations --check` |
| `docs/textbook/90-부록-자동생성.md` | `node dbtool.mjs textbook --write` | `db.json`, `vocab.js`, `core.js` 상수, `storage-map.json`, `dbtool.mjs` 주석 | `textbook --check` (+ 모든 파일 분류 여부) |
| `index.html` | `cp viewer.html index.html` | `viewer.html` | `cmp index.html viewer.html` |

생성물은 **결정적**이다 — 같은 원천이면 같은 결과(시각·난수 없음). 그래서 CI 가 바이트 단위로 비교할 수 있다.

## 2.6 저장하지 않는 곳 (경계)

- **브라우저 localStorage**: 화면에서 반영한 패치는 그 브라우저에만 남는다. 저장소에 넣으려면 그 패치를 `dbtool merge` 로.
- **스크래치 폴더**: AI 는 패치 JSON 을 저장소 밖에서 작성·`--dry` 한다(병합되면 원문이 `data/patches/` 에 남는다).
- **시나리오의 가상 값**: `examples/scenarios/*.json` 은 `db.json` 에 들어가지 않는다. 속도 기반 시뮬레이션이 덧씌워 쓸 뿐이다.
- **외부 데이터베이스(UniProt·PDB·ChEBI…)**: 내용을 복사하지 않고 ID 만 `xrefs` 에 둔다. 원본과 대조했으면 `status: verified`, 아니면 `asserted`. 3차원 좌표도 저장하지 않고 PDB ID 로 가리킨다(`site.structure`).

## 2.7 형식 버전과 변환

- `db.json` 의 `version` ≠ `core.js` 의 `VERSION` 이면 `validate` 가 오류를 낸다.
- 형식을 바꾸면: `migrations/NNN-설명.mjs` 추가 → 실행해 `db.json` 변환 → `SCHEMA.md` 변경 기록 → 교과서 해당 장 → 테스트.
- 옛 패치 기록(v2 이전)은 옛 이름 ID 로 적혀 있다 → `migrations/002-id-map.json` 으로 읽는다.
