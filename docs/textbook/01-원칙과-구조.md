# 1장. 원칙과 구조

## 1.1 무엇을 하려는가

생명과학의 **정의(뜻)**와 **기전(분자가 바뀌는 사슬)**을 한 저장소에 넣고,

1. 정의끼리 *뜻 단위*로 이어 맥락을 잃지 않게 하고 (메모 한 장 = 노드가 아니라 정의항 하나 = 노드),
2. 기전을 규칙대로 실행해(시뮬레이션) 입력에서 출력이 실제로 유도되는지 확인하고,
3. 모르는 것을 지어내지 않고 **한계로 기록**해 다음 확장의 설계도로 삼는다.

데이터는 AI 가 넣고, 사람은 규칙(어휘·검사)을 검토한다.

## 1.2 일곱 원칙

| # | 원칙 | 구현된 곳 |
|---|---|---|
| P1 | **정의항이 원천이다.** 구성 요소·막 위상·부위·규칙·설명·관찰은 그것을 가진 정의항(D)이 하위 번호로 소유한다. 다른 것은 이를 참조할 뿐이다. | 3장 정의항, `normSense`·`validateSense` |
| P2 | **두 해상도.** 지식 해상도(D: 가능한 가장 높은 구조적 진실)와 시뮬레이션 해상도(묶음·단계: 의미 있는 변화만)를 나누고, 규칙이 다리를 놓는다. | 3장, `validateStep` |
| P3 | **번호로만 잇는다.** 모든 참조는 의미 없는 고정 번호. 이름은 꼬리표다. 지운 번호는 다시 쓰지 않는다. | `merge`(번호 배정), `resolveRef` |
| P4 | **엄격한 관문.** 패치는 매핑 → 검사 → 관문을 통과해야 저장된다. 하나라도 어기면 전체 거부. | `merge`·`validate`·`gate` |
| P5 | **지어내지 않는다.** 외부 ID·잔기 번호·구조 지문·속도 상수·인용은 확인한 것만. 모르면 `unmapped`·`residue_unknown`·한계로 명시한다. 추론은 `[Abstracted Logic]` 로 표시한다. | 근거 수준, 한계 등록부 |
| P6 | **계산할 수 있는 것은 저장하지 않는다.** 묶음 키, 활성, 상위 개념의 사례, 한계의 상태, 해상도 계획은 매번 계산한다 — 원천과 어긋날 수 없게. | `activityOf`, `findMotifs`, `limitationStatus`, `resolutionPlan` |
| P7 | **혼합 해상도와 감사.** 3차원은 경쟁을 속도 상수로 가를 수 없는 반응 중심에만. 모든 시뮬레이션·갱신은 질량 보존·해상도 일관성·속도 무결성 감사를 받는다. | `resolutionPlan`, `simulateRate`, `auditRun` |

## 1.4 지식 해상도와 시뮬레이션 해상도

| | 지식 해상도 — 정의항 D | 시뮬레이션 해상도 — 묶음 B · 단계 S |
|---|---|---|
| 담는 것 | 구성 요소, 막 위상, 부위(종별 잔기 번호·면·리간드·구조 참조), 규칙(상태 의미·전이·속도), 설명, 관찰 | 어느 정의항이, 어느 부위에 어떤 특징을 갖고, 어디 있나 / 어느 규칙이 어느 묶음들에 적용되었나 |
| 우선순위 | 완전성·구조적 깊이 | 효율·참조 무결성 |
| 형태 | 하위 번호를 가진 객체 | 파생 키 `D…|부위:특징|위치` / `{ rule, agents, inputs, outputs, regulators, part_of }` |

**규칙이 다리다.** 상태 의미 규칙은 묶음의 특징 조합이 원천에게 무엇을 뜻하는지(활성) 정하고, 전이 규칙은 원천이 일으키는 변화량을 정한다. 단계는 규칙을 가리키기만 하고, 검사가 단계의 묶음이 규칙과 맞는지 확인한다.

## 1.5 세 겹의 해상도 (공간·구조)

| 해상도 | 무엇으로 다루나 | 언제 |
|---|---|---|
| R0 위상 | 위치·상태만 | 풀 안에서 확산·대기·수송하는 분자, 부위 없는 변환 |
| R1 부위 | 이름 붙은 부위·특징·잔기 번호·막 면 | 결합·수식·전달 같은 부위 사건, 구성 요소 화학량 |
| R2 구조 | 반응 중심의 3차원 구조 참조(PDB) | 같은 묶음을 두고 단계들이 경쟁하는데 속도 상수가 없을 때만 |

전체를 3차원으로 다루지 않는다. 전환 문턱(T1–T3)은 4.8절.

## 1.6 버전의 흐름 (왜 지금 모양인가)

| 형식 | 바뀐 것 | 이유 |
|---|---|---|
| v1 | 정의항·연결·단계 | 링크만 있는 메모장을 정의 단위로 |
| v2 | 상태 객체, kind·field·외부 ID, 통제 어휘·관문 | 규칙 없이 쌓이면 같은 개념이 여러 이름으로 생김 |
| v3 | 의미 없는 고정 번호 T/D/S | 이름이 바뀌면 연결이 끊김 |
| v4 | 원천 중심 소유, 두 해상도, 묶음 키에 위치 | 정의항이 구조의 원천이어야 하고, 위치가 기전을 바꿈 |
| v5 | 한계 등록부 L, 상위 개념(motif), 구획 농도 모델 | 실패를 데이터로 남기고 그것으로 진화 |
| v6 | 혼합 해상도, 반응 속도, 감사 | 3차원 남용 없이 정밀도와 효율의 균형, 사건 기반 → 속도 기반 |
| v8 | 3 층(tier T1/T2 + T3 영역), Tier 1 환경·전이 상태 이론·ΔG°, 미시적 가역성·Wegscheider 검사, 실행 층(정수 원장·인접 경계 거래) | 공간·연속·이산을 한 엔진에서 — 질량은 정수 원장이, 에너지는 ΔG° 가 보존을 보증 |
| v7 | 생애 주기(분해 규칙)·대사물 저장소(유한 저장소·공급 규칙)·부분 구조 수지·매 Δt 질량 감사 | 물질은 무한하지 않고 사라지고 돌아온다 — 고갈과 순환 재생을 계산하고, 그 계산이 질량을 어기지 않음을 매 단계 증명 |
| v9 | 세포 상태(`cell_state`: 표지 서명·대사 프로그램·전이), 조절 규칙(`modulation`, 힐 배율), 포화 보조 기질, `Regulatory_Gap`, 운명 엔진(다중 속도 + P5 관문 + 결정 탐침 + 분화 정지 사후 분석) | 대사만이 아니라 세포의 정체성 — 신호 → 대사 → 전사 인자 사슬이 상태를 옮기고, 그 사슬이 스스로를 유지하면 비가역 결정 |

자세한 변경 기록은 `SCHEMA.md` 끝.

## 삼권 분립 (형식 9 확장 4)

코드는 세 권력과 공유 층으로 나뉜다 (`docs/design/tripartite-governance.md`, 강제는 `tests/governance.test.mjs`).

| 층 | 파일 | 한다 | 하지 않는다 |
|---|---|---|---|
| 공유 | `vocab.js` · `model.js` | 형식·정규화·색인·참조·부분 구조 셈·속도 법칙 정의 | 시뮬레이션·판정·쓰기 |
| 행정 | `core.js` · `engine/` | 읽기·질의·시뮬레이션 — 원자료만 | 쓰기·검사·승인·`verified`·감사 코드 |
| 입법 | `legislative/` | merge·패치 초안, 쓰기는 서기 `clerk.mjs` 만 (사법부 봉인이 있을 때) | 스스로 검사·시뮬레이션 |
| 사법 | `judicial/` | validate·관문·감사·독립 질량 검증·운명 판정·보고서·비교 판정·신원 확인·증명 도장 | 엔진 실행·데이터·엔진 수정·쓰기 |

`verified` 는 사법부가 발급하고 서기가 `attestations/registry.json` 에 기록한 도장으로만 성립한다. 되먹임은 읽기 전용이다 — 판결·보고서 → 에이전트가 새 패치 → 다시 검증.


### 쓸 자격과 쓸 자리 (구역)

삼권 분립이 **누가** 쓰는지를 정하면(입법 서기만), 구역은 **어디에** 쓸 수 있는지를 정한다. 둘은 직교하고 둘 다 통과해야 쓴다.

- 서기의 모든 쓰기는 `put(구역, 파일)` 하나를 지난다 — 구역 없이 쓸 길이 없다(`legislative/clerk.mjs` `ZONES`).
- 저장소 **안**에서 그 구역의 자리가 아니면 **봉인이 유효해도 거부**된다. 막는 것은 '저장소 안인데 다른 구역' 이다 — 병합이 `judicial/` 에, 받기가 `compiler/` 에 쓰려는 경우.
- 저장소 **밖**(tmp 사본, `--db` 로 가리킨 다른 저장소)은 구역 표가 다루지 않는다.
- 경로를 경계로 쓸 수 있는 자리는 여기뿐이다. 폴더 이름만 나누면 어느 모듈이든 그 경로로 쓸 수 있어 표시에 그친다 (`docs/design/tripartite-governance.md` §1.1).
