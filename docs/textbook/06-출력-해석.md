# 6장. 출력 해석 — 무엇을 결론으로 써도 되나

## 6.1 신뢰의 등급

출력의 모든 값은 아래 중 하나에서 온다. **위로 갈수록 결론에 쓸 수 있다.**

| 등급 | 어디서 | 결론에 쓰는 법 |
|---|---|---|
| 1 | `curated` 근거가 붙은 설명·규칙·속도 상수 (DOI/PMID + 저자·연도) | 인용과 함께 사실로 |
| 2 | `verified` 외부 ID, `computed` 지문 | 정체성으로 |
| 3 | `asserted` (출처 없는 일반 지식), `asserted` 외부 ID (원본 대조 안 함) | "확인 필요"를 붙여서 |
| 4 | `abstracted` — `[Abstracted Logic: Derived from the inferred mechanistic flow]` | 추론으로 표시하고 `basis` 를 함께 |
| 5 | 시뮬레이션의 **기본값** 시작량, **즉시** 처리 단계, **2D 환산** | 도달 여부(질적)만. 양·시간은 말하지 않음 |
| 6 | 시나리오의 **가상 값** (`hypothetical: true`) | 엔진이 작동한다는 것만. 생물학적 결론 금지 |

## 6.2 상태와 표시

| 표시 | 뜻 |
|---|---|
| `● 활성` / `● 비활성` / `● 부분 활성` | 묶음의 특징 조합에 원천의 상태 의미 규칙을 적용한 결과 |
| `[부위(Ser14):인산화됨]` | 묶음의 부위:특징. 괄호는 기준 종 잔기 번호 |
| `@세포질` | 묶음의 위치 |
| `*` (단계 텍스트) | 부산물·보조 기질(minor) — 사슬 연결에 쓰지 않음 |
| `×n` | 화학량 (단계) / 발화 횟수 (시뮬레이션) |
| 외부 ID `?` (화면) · `(미대조)` | asserted — 원본과 대조 안 함 |
| `잔기 모름` | `residue_unknown` — 지어내지 않고 비워 둠 |
| `미매핑` | 필수 외부 ID 를 확인 못 해 `unmapped` 에 사유 |
| 한계 `open n/m` | 해결 경로 m 개 중 n 개의 데이터가 들어옴 |
| `resolved` / `resolved_manual` | 데이터로 자동 해결 / 사람이 resolution 으로 닫음 |
| `R0` · `R1` · `R2` | 위상 · 부위 · 구조 해상도 (4.8) |
| `T1` · `T2` · `T3` | 부위 사건 · 구성 요소 화학량 · 경쟁 |

## 6.3 사건 기반 시뮬레이션 (`simulate`) 읽기

```
시작 풀(원천 묶음) — 세포 대식세포:
  2× TNF 유전자@핵질  [data: copy_number 2 (1번 관찰)]     ← 데이터에서 온 시작량
  10× NF-κB–IκBα 복합체@세포질  [기본값 — 농도 공백]          ← 기본값: 양적 의미 없음
  ⚠ 농도 공백: … (등록된 한계: L000001, …)                 ← 결과는 도달 여부만
  (순환의 휴지 상태라 자동 보충: LBP@세포 밖, CD14@세포막)   ← 순환을 시작하려고 넣은 것 (활성형은 넣지 않음)
발화 순서: [라운드 n] ×k S… …                              ← 라운드는 시간이 아니다
✓ 목표 도달 · 유도 경로 (n단계) · 유도의 뿌리 · ✓ 출력이 입력 'X' 에서 유도됨
```
- **결론으로 쓸 수 있는 것**: 규칙만으로 입력에서 출력이 유도되는가(도달·유도 경로), 무엇이 빠지면 막히는가(`--init "키=0"` 음성 대조).
- **쓸 수 없는 것**: 라운드 수, 끝 풀의 양, 경쟁 결과(어느 표적이 먼저 차지했나 — 단계 순서에 좌우됨).

## 6.4 속도 기반 시뮬레이션 (`simulate --rate`) 읽기

- 맨 위에 시나리오 이름과 `⚠ 가상 시나리오 값` 이 있으면 등급 6.
- `단계별 속도 법칙`: `[data]` 는 데이터베이스의 규칙, `[scenario]` 는 덧씌운 값, `속도 상수 없음 → 즉시`.
- `처음 1분자 이상이 된 시각`: 순서는 의미가 있을 수 있지만, 즉시 단계가 끼면 그 구간은 시간이 0 이다.
- 끝의 감사 목록이 비어 있지 않으면 결과보다 감사를 먼저 읽는다.

### 6.4.1 생애 주기·대사물 저장소 블록 (v7)

```
공급 규칙 (Metabolic_Supply_Rule):
  ● D000123/rule/gtp_regeneration 「GTP 재생」 공급: GDP + ATP → GTP + ADP @세포질 · mass_action [scenario] k=… ← 켜짐
  ○ D000126/rule/atp_supply … — 적용 안 함 (속도 상수·부피 없음)                         ← 꺼짐: Kinetic_Gap
분해 규칙 (Degradation_Rule):
  ● TNF mRNA@핵질 ← D000101/rule/turnover 재활용 … k_deg=3.851e-4 s⁻¹ [scenario]
대사물 저장소 (유한 저장소 …):
  GTP@세포질: 시작 20000 → 끝 0 (최소 0) · 소비만 — 고갈 위험 · 고갈 1회      ← 재생 경로 없음
  ATP@세포질: 시작 2e6 → 끝 1.986e6 · 순환(소비·재생)                         ← 소비자·생산자가 모두 켜짐
자원 순환 (… 강하게 연결된 성분):
  ⟲ GTP@세포질 · GDP@세포질 · ADP@세포질 · ATP@세포질 · …                  ← 서로 되돌아오는 저장소 분자 집합
고갈·재생 사건:
  t=0.02 s 고갈 GTP@세포질 · t=0.03 s 멈춤 S000002 Gs 활성화 ← GTP@세포질 부족
변화량 원장 Δ (반응 · 공급 · 분해 · 재활용):
  GTP@세포질: -1.011e+6 · 9.914e+5 · 0 · 0                                  ← 반응이 쓰고 공급이 채움
```
- **고갈(exhausted)·멈춤(stalled)은 오류가 아니라 결과**다. 엔진은 그 단계를 덜(또는 안) 일으키고 계속 돈다. 고갈 시각은 저장소 시작량과 속도가 데이터일 때만 양적으로 읽는다(기본값이면 `시작량 기본값(농도 공백)` 표시 — 등급 5).
- `소비만 — 고갈 위험` 은 **재생 경로가 꺼져 있다**는 뜻이다(공급 규칙이 없거나 속도가 없음) → AUDIT_RESOURCE 의 교정 제안(공급 규칙의 Kinetic_Gap)을 채운다.
- 자원 순환 성분은 "이 분자들이 서로 되돌아온다"는 구조이지 순환 속도가 아니다.
- 원장의 네 칸 합 = 끝 − 시작. 분해 칸이 음수인데 재활용 칸이 0 이면 산물이 소실로 처리된 것(lost 이거나 재활용 화학량을 모름 — 감사에 표시).
- `--stochastic` 결과는 seed 마다 다르다. 한 번의 결과가 아니라 여러 seed 의 분포로 읽는다.

### 6.4.2 사후 분석 블록 (`--until-death`)

```
단계 순환 (회로):  ⟳ S000031 → … → S000038 → … : 완료 1000바퀴
사후 분석 (Post-Mortem) — 정지:
  정지 시각 t=1 s (감지 t=2 s · 확인 창 1 s · Δt 0.01 s) · 원인: 자원 고갈
  마지막으로 완료한 바퀴: 1000 번째, t=1 s
  제한 요인: 아세틸-CoA@미토콘드리아 기질 — 굶은 단계 S000031 · 켜진 재생 경로 없음
  축적된 폐기물: +2000 CO₂ · +1000 GTP          소비/생산 비: 1.0000
```
- 정지 시각의 정밀도는 Δt. '감지' 는 창 길이만큼 늦다(확인하는 데 걸린 시간이지 정지 시각이 아님).
- 원인별 대응: 자원 고갈 → 제한 요인 저장소의 재생 경로(Resource_Gap: 공급 규칙 속도·시작량), 평형 → 병목 단계의 역반응 속도·산물 배출(Kinetic_Gap), 중간물 고갈·속도 정지 → 단계 속도 상수.
- 완료 바퀴 수·정지 시각은 시작량·속도가 데이터일 때만 양적 결론이다. 가상 시나리오에서는 **엔진이 화학량을 정확히 따르는지**(예: 아세틸-CoA 1000 → 1000 바퀴, NAD⁺ 3002 → 1000 바퀴 + 부분)만 말한다.
- `AUDIT_KINETIC … Δt 가 너무 큼` 이 있으면 정지 시각·평형 판정을 믿지 말고 Δt 를 줄여 수렴을 확인한다 (시트르산 회로 시험 3: Δt 0.05 에서는 21.9 s 에 가짜 평형, 0.005 이하에서 약 106 s 로 수렴).

## 6.5 감사 (`audit-run`) 읽기

| 코드 | 무엇이 문제인가 | 보통의 대응 |
|---|---|---|
| AUDIT_SCHEMA | 저장소가 규칙을 어김 | 패치를 고쳐 다시 병합 |
| AUDIT_RESOLUTION | 필요 해상도 > 갖춘 해상도 (경쟁인데 속도·구조 없음), 2D 환산 | 교정 제안의 한계(속도 상수·면적 모델)를 채움 |
| AUDIT_KINETIC | 속도 법칙·상수의 모순, 평형 불일치 | 값·법칙 수정 (협동 결합은 mass_action), dt·t_end 조정 |
| AUDIT_KINETIC_GAP | 속도 상수가 없어 즉시 처리 | Kinetic_Gap 한계의 kinetics 를 확인된 값으로 |
| AUDIT_CONCENTRATION | 반응 부피를 모름 | 구획 농도 모델에 compartment_volume 관찰 |
| AUDIT_MASS | 보존되어야 할 실체·부분 구조가 원장 밖에서 생기거나 사라짐. 단계 국소(`S… : t=… s 첫 발화에서 국소 수지 위반`)와 매 Δt 전역(`처음 어긋남`) 두 가지 | **모델 오류 신호**. 국소 위반을 먼저 고친다 — 빠진 부산물(minor)·보조 기질, 이중 계산. 교정 제안의 한계(대개 단순화)를 확인하고, 새 원인이면 한계로 등록 |
| AUDIT_RESOURCE | 재생 경로 없는 저장소(소비만), 재활용 화학량(서열 길이)을 모름 | 공급 규칙의 속도·서열 길이 관찰을 채움 (교정 제안) |

`→ 교정 제안:` 은 한계 등록부에서 찾은 것이다. "등록할 것" 이 나오면 그 한계가 아직 등록되지 않았다는 뜻이다 — 등록하는 것이 다음 작업이다.

✗ S000006 PKA 활성화: 필요 R2 / 갖춤 R1 — T1 부위 사건, T2 구성 요소 화학량, T3 경쟁 · 반응 중심 D000056/site/cnb_a …

- `✗` 는 "3차원 구조를 만들라"가 아니라 **"경쟁을 가를 정보가 없다"**는 뜻이다. 먼저 속도 상수(Kd·kcat·Km)를 찾고, 그래도 안 되면 구조.

## 6.8A 시나리오 맥락 선언 (`context`, MHC 실험)

- 시나리오는 이 실행이 무엇을 보이려는 것인지 선언한다: `cause`(그 상태에 이르는 **원인**) · `requirement`(같은 신호에서 무엇을 끊으면 이르지 못하는지 — **필수성**) · `baseline`(신호 없는 **일반 상황**).
- 사법부가 선언과 실행의 일관성을 판정한다 — cause·requirement 는 그 상태로 가는 전이의 신호가 켜져 있어야 하고, baseline 은 시작 상태이며 구동된 전이가 없어야 한다. 어긋나면 무결성 증명서가 **FAIL** 이다(보고서의 해석이 거짓이 되므로).
- 결과가 선언과 다르면(원인이라 했는데 도달하지 못함, 필수라 했는데 도달함, 일반 상황인데 머물지 못함) §4 "예측과의 차이" 에 나온다 — 선언이 틀린 것(FAIL)과 결과가 다른 것(차이)을 가른다.
- 요약 표에 맥락과 `note` 가 함께 나온다. `context` 는 입력 해시에 들어가므로 실행 뒤 바꿀 수 없다.

## 6.8B 신뢰 지표 (`dbtool grade`)

- 두 축을 독립으로 읽는다: **S**(출처 — 유효한 도장 4 · 문헌 식별자 3 · 그 밖 2 · 확인 불가 0)와 **D**(성질 — 실측·도구 계산 4 · 요약 상수 3 · 추론 2). 표에 곱(S×D)이 함께 나오지만 **판정에 쓰지 않는다**: (2,4) 와 (4,2) 가 둘 다 8 이라서 "출처가 약한 실측" 과 "권위 DB 에서 온 추론" 을 가르지 못한다.
- 등급은 권한이다 — `anchor` 기준값 · `parameter` 매개변수 · `bounded` 구간값(오차 막대와 함께) · `legacy` 지난값(비교에만) · `reference` 참고(계산 금지) · `blocked` 차단(한계로만).
- 점수는 저장되지 않는다. 도장(`attestations/registry.json`)·근거(`sources`·`tool`)·관찰 기록에서 계산되므로, 패치가 `status: verified` 만 적어도 등급은 오르지 않고 **blocked** 가 된다.
- 지금은 `anchor` 가 0 이다 — 추세 점검(시간 축)이 아직 없어 모든 항목의 `trend` 가 `unchecked` 이기 때문. 그리고 속도 상수는 데이터에 하나도 없으므로(가상 시나리오 값) 시뮬레이션이 읽는 값의 등급은 따로 봐야 한다.

## 6.9 확률 앙상블 (`dbtool fate … --ensemble N`, 4단계)

- **궤적 하나는 결론이 아니다.** 확률 실행(시나리오 `stochastic { seed }`)의 과정 보고서는 요약에 seed·궤적 번호와 이 경고를, 부록에 끝 방식(결정론·도약·SSA 규칙 수)·발화 수·막힌 SSA 발화·도약 되돌림·분할 전환·난수 소비를 적는다. 결정 탐침과 수치 L2(수렴 기준)는 확률 실행에서 하지 않는다.
- 앙상블 표: 끝 상태별 수·비율·95% Wilson 구간 / 도달 시각(도달한 궤적만 — 도달 수를 함께) 평균·sd·10·50·90% / 표지 끝 분포 평균·sd·Fano(분산/평균 — 포아송이면 1)·CV.
- 무결성: 궤적별 원장·재생 ≤ 1e-14·음수 없음·발화 수 정수(사법부 `stoch_audit.auditTrajectory`), seed 재현(궤적 0 을 다시 돌린 해시), 결정론 대비(같은 시나리오에서 stochastic 을 뺀 실행의 끝 상태·도달 시각). 결함(ENGINE_DEFECT)이나 재현 실패면 종료 코드 1.
- 분포가 말하는 것은 "이 기전이 그 (가상) 상수에서 어떻게 흔들리는가"다 — 근사 목록은 L000072.

## 6.10 관찰 판정 (`dbtool observe`, 4단계)

- 판정 셋: **CONSISTENT**(FINDING — 관찰이 예측 ⊛ 측정 잡음 안), **CONFLICT**(DOMAIN_CONFLICT — 모델과 관찰의 모순, 근거와 함께 데이터를 고칠 일), **INDISTINGUISHABLE**(DATA_GAP — 두 가설이 모두 맞아 가를 수 없음 → Observation_Gap 후보와 필요한 정밀도: 지금 반복 수에서의 sd, 지금 sd 에서의 반복 수).
- 표 칸: 가설별 예측 평균·표준 오차(측정 잡음/√반복 + 앙상블 몬테카를로)·z·p, 생물 변이(biological)면 F 검정의 모델 퍼짐 대 관찰 퍼짐. 결정론 예측(실행 1 개)은 퍼짐을 판정할 수 없다고 적는다.
- 한 가설이 측정량을 내지 않으면(도달 안 함) 관찰의 존재 자체로 가른다. 추정용(estimation)·철회된 관찰은 판정을 거부한다.
- 합성 관찰(`examples/observations/`, hypothetical)은 판정 시험용 — 데이터베이스에는 들어갈 수 없다.
