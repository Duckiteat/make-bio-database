## 9.3 저장 지도 (docs/textbook/storage-map.json)

### 원천 데이터 (`source`)

지식의 유일한 원본. 사람·AI 모두 직접 편집하지 않고 패치 → merge 로만 바뀐다. 다른 모든 생성물·출력은 여기서 계산된다.

| 경로 | 형식 | 쓰는 쪽 | 읽는 쪽 | 해석 |
|---|---|---|---|---|
| `data/db.json` | JSON (형식 버전은 version 필드, 지금 8) | node dbtool.mjs merge (core.js merge → gate 통과 시) | dbtool.mjs 모든 명령, viewer.html, tests | terms(T)·senses(D)·steps(S)·limitations(L) 네 표와 meta.next(다음 번호). 묶음 키·상태·사례 경로·한계 상태는 저장하지 않고 계산한다 — 3장. |

### 기록 (추가만) (`log`)

병합이 성공할 때마다 하나씩 늘어나는 기록. 고치거나 지우지 않는다. 당시 형식·번호로 적혀 있으므로 지금 형식으로 다시 읽지 않는다 (옛 ID 는 migrations/002-id-map.json).

| 경로 | 형식 | 쓰는 쪽 | 읽는 쪽 | 해석 |
|---|---|---|---|---|
| `data/patches/*.json` | JSON — 패치 원문(why 포함) + applied_at + result(added·updated·removed·mapped) + report(Patch Report: scope·why·impact·verification) | node dbtool.mjs merge (--dry 가 아닐 때) | 사람·AI (이력 추적), node dbtool.mjs report | 파일 이름 = 병합 시각-원래 이름. result.mapped 로 이름 → 번호가 어떻게 바뀌었는지 볼 수 있다. |
| `CHANGES.md` | Markdown 표 (맨 위가 최신, 추가 전용) | 사람·AI (코드·형식·어휘·문서 구조를 바꾸는 커밋마다 한 행) | AI (세션 시작 시 동기화), 사람 | 코드 수준 변경의 Patch Report: Scope(파일·함수·정의항) · Why · Impact(하류) · Verification. 데이터 패치의 보고서는 data/patches/ 기록의 report. |

### 외부 원본 사본 (수신함) (`evidence`)

권위 있는 원본(UniProt·ChEBI)에서 받은 응답을 그대로 둔 사본. 해석만 하고 실행하지 않으며 고치지 않는다. 패치의 xref note 가 파일 경로와 sha256 으로 가리킨다 — 지우면 출처 추적이 끊긴다.

| 경로 | 형식 | 쓰는 쪽 | 읽는 쪽 | 해석 |
|---|---|---|---|---|
| `data/fetched/*/*` | 원본 응답 (JSON · FASTA · UniProt 평문) 또는 간이 JSON | 입법 서기 fetchToInbox (curl) 또는 사람(수동 수집) | judicial/identity.js (확인), judicial/attestation.js (재확인) | 과제 하나에 파일 하나: uniprot/{번호}, uniprot-search/{D…}, chebi/{CHEBI_번호}, chebi-search/{D…}. |

### 증명 등록부 (사법부 도장) (`attestation`)

'verified' 의 유일한 근거. 사법부(judicial/attestation.js)가 발급한 도장을 입법 서기만 기록한다. 도장마다 digest·증거 파일 sha256·같은 확인 재실행으로 검증되며, 데이터는 스스로 verified 를 선언할 수 없다. 손으로 고치면 digest 가 깨져 무효가 된다.

| 경로 | 형식 | 쓰는 쪽 | 읽는 쪽 | 해석 |
|---|---|---|---|---|
| `attestations/registry.json` | JSON {format: definition-db-attestations, version, stamps[]} | 입법 서기만 (appendAttestations — 사법부 도장, 재검증 뒤) | judicial/attestation.js validStamps → validate(db, { attestations }) | 도장: subject(정의항·필드·종류:값) · claim verified · evidence(수신함 파일·sha256) · issuer(모듈·코드 sha256) · issued_at · digest. validate 는 status verified 마다 유효한 도장을 요구한다. |
