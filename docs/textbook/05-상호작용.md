# 5장. 상호작용 — 저장과 알고리즘이 맞물리는 방식

## 5.1 명령 × 저장 행렬

| 명령 | 읽는 것 | 쓰는 것 (입법 서기가) | 부르는 함수 (행정 core · 사법 J · 입법 LEG) |
|---|---|---|---|
| `status` | db.json | — | `normalize`, `validate` |
| `validate` | db.json | — (종료 코드) | `validate` |
| `merge <patch> [--dry]` | db.json, 패치 | db.json, data/patches/ (dry 가 아니고 관문 통과 시) | `merge`, `gate` |
| `map <참조>` | db.json | — | `resolveRef` |
| `context <정의항>` | db.json | — | `index`, `contextText` |
| `mechanism <경로|S…>` | db.json | — | `mechIndex`, `mechanismText` |
| `pattern <경로|상위 개념>` | db.json | — | `findMotifs`, `patternText` |
| `resolution <경로>` | db.json | — | `resolutionPlan` |
| `simulate <경로> [--until --from --init]` | db.json | — | `simulate` |
| `simulate <경로> --rate [--scenario --reservoirs --stochastic --seed]` | db.json, 시나리오 | — | `simulateRate` (유한 저장소·공급·분해·매 Δt 질량 감사) |
| `audit-run <경로> [--scenario]` | db.json, 시나리오 | — (종료 코드) | `auditRun` |
| `limitations [--write|--check|--detect|--open]` | db.json | limitations.md (`--write`) | `limitationsMarkdown`, `detectGaps` |
| `textbook [--write|--check]` | db.json, vocab, core 상수, storage-map.json, dbtool 주석, 파일 목록 | 90-부록-자동생성.md (`--write`) | (dbtool 의 `textbookAppendix`) |
| `audit` | db.json | — | `audit` (매핑·채움 현황) |
| `report <기록>` | data/patches/…json, db.json | — | `patchReportText` |
| `grade [<D…>] [--min 등급]` | db.json, 증명 등록부, 합의 수신함 | — (미달이면 종료 코드 1) | `reliability.items`·`summary`, `trend.verdicts` (S·D 쌍 + 추세 축 → 등급) |
| `trend [<D…>] [--fetch] [--write]` | db.json, 등록부, 합의 수신함 | 합의 수신함(`--fetch`), 등록부의 추세 도장(`--write`) | `trend.plan`·`check`·`issue`, `clerk.fetchToInbox`·`appendAttestations` |
| `vocab [표]` · `prompt` | vocab.js, db.json | — | `VOCAB`, `promptText` |
| 화면 `viewer.html` | db.json(웹 서버) 또는 불러온 파일 | 브라우저 localStorage, 저장 버튼으로 내려받기 | `merge`·`gate`·`index`·`findMotifs`·`limitationStatus` … |

파일은 입법 서기 `legislative/clerk.mjs` 만 쓴다 — `dbtool.mjs` 는 조정만 하고, db.json·patches 는 사법부 관문 봉인(통과 + 같은 db sha256)이 있을 때만, 증명 등록부는 도장 재검증 뒤에만 쓰인다. `core.js`·`judicial/`·`legislative/legislative.js` 는 파일을 모른다 — 그래서 같은 규칙이 브라우저와 Node 에서 똑같이 돈다. 표의 `validate`·`gate`·`limitationStatus`·`patchReport`·감사는 사법부(J), `merge` 는 입법부(LEG) 함수다.

추가 명령: `attest` — 등록부의 도장마다 digest·증거 sha256·같은 확인 재실행 (쓰기 없음, 무효가 있으면 종료 코드 1). 신원 도장(claim `verified`)과 추세 도장(claim `trend`)을 따로 세고, 합의 창을 넘긴 추세 도장은 무효가 아니라 **만료**(⌛)로 알린다.

도장 재검증은 **주체 하나로 좁혀서** 한다 — 그 정의항만 새로 만든 얕은 겹침 사본과 그 과제 하나(`identity.plan(opt.only)`), 정규화·색인은 등록부 전체에 한 번(`validStamps`, 객체 신원으로 기억). 중복 검사(같은 외부 ID 를 다른 정의항이 가져감)는 전체 db 의 색인으로 하므로 좁혀도 약해지지 않는다. 측정: 등록부 341 도장 12.1 s → 0.32 s.

## 5.2 쓰기 경로 — 패치 하나가 저장되기까지

```
AI 가 패치 작성 (스크래치 폴더)
   │  terms[] · senses[] · steps[] · limitations[] · remove[]   (이름·별칭·임시 번호로 써도 됨)
   ▼
merge ── 1 개념 → 2 정의항 → 3 단계 → 3b 한계 (번호 배정: meta.next++)
   │      4 매핑: 이름 → 번호, 별칭 값 → 표준 키, 묶음 객체 → 키
   │      5 삭제
   ▼
validate(새 db)  ──┐
validate(옛 db)  ──┴─▶ gate: 새로 생긴 오류·경고만 셈
   │
patchReport ──▶ Patch Report (Scope·Why·Impact·Verification) — 차단은 관문(patchPolicy: why 없음 · 미등록 한계 후보 > 0 · 새 정제 점검 문제)
   │
   ├─ 거부 → 메시지(어디·무엇) 를 보고 패치를 고침  ← 여기서 저장되는 것은 없다
   └─ 통과 → db.json 덮어씀 + data/patches/시각-이름.json 기록 (report 포함)
              ▼
        (생성물이 낡음) → limitations --write · textbook --write → CI 가 검사
```

## 5.3 읽기 경로 — 계산되는 것들의 의존

```
db.json ──normalize──▶ db ──index──▶ ix ─┬─ label · names · xrefs ─────────────▶ map, context
                                          ├─ edges(설명 연결 + 구성 요소) ─────▶ context 위계
                                          ├─ mechIndex(묶음 키 일치) ─────────▶ mechanism, simulate
                                          ├─ ruleOf · activityOf ─────────────▶ 행위자 활성, 화면
                                          └─ limitsOf · addressedBy ──────────▶ 화면, 한계 출력
db ──findMotifs──────▶ 상위 개념의 사례 (motif 정의항)
db ──limitationStatus▶ 한계 상태 ──▶ limitations.md, gapSuggest
db ──resolutionPlan──▶ pool·site·structure ──▶ auditRun
db ──simulate────────▶ 시작 풀(데이터·기본값·풀·순환 보충) ──▶ simulateRate ──▶ 감사
                                          ▲ 분해 규칙(묶음별) · 공급 규칙(닫힌 집합) · moieties/ligands(질량 감사)
```

## 5.4 무엇을 바꾸면 무엇이 따라 바뀌나 (전파 표)

| 바꾼 것 | 자동으로 바뀌는 것 (계산) | 다시 만들어야 하는 것 (생성물) | 함께 고칠 것 |
|---|---|---|---|
| 정의항에 관찰 `copy_number` 추가 | 시뮬레이션 시작량(데이터), 그 관찰을 요구하는 한계의 상태 | limitations.md, 부록 | — |
| 공급 규칙(`supply`) 추가 | 그 분자에 닿는 경로의 저장소 집합이 넓어지고(닫힌 집합), 속도가 있으면 재생이 계산됨 → 저장소 분류 consumed_only → closed, 자원 순환 성분 | limitations.md(--detect 후보), 부록 | 부분 구조 수지(아니면 source), 속도 없으면 Kinetic_Gap 등록 |
| 분해 규칙(`degradation`) 추가 | 그 정의항의 묶음이 매 Δt 줄고 원장(소멸·재활용)에 기록, 평형 검사에서 빠짐 | limitations.md(--detect 후보), 부록 | 속도·서열 길이가 없으면 한계 등록 |
| 정의항에 `moieties` 추가 | 그 분자가 낀 변환·분해·공급 규칙의 부분 구조 수지 검사가 켜짐 — 빠진 산물이 드러나면 **기존 규칙이 오류가 됨** | 부록 | 같은 패치에서 그 규칙·단계(부산물 minor)를 고칠 것 |
| 부위에 `ligands` 추가 | 질량 감사가 채워진 부위의 리간드를 실체로 셈, 리간드 교체(GTP → GDP)는 화학 실체 | — | — |
| 정의항 `tier` 변경 | (지금) 검사만 — 실행 층에서 그 분자의 기본 층 | 부록 | T1 이면 부위 없음 |
| kinetics `dG0`·`k0`·`dG_act`·`env` 추가 | 속도 기반 시뮬레이션의 k·k_r(구획 환경 반영), 미시적 가역성 검사, 고리 ΣΔG° 감사 | limitations.md(L000048 등 상태) | 같은 고리의 다른 단계 dG0 와 합이 0 인지 |
| 관찰 `sequence_length` 추가 | 재활용 화학량(`n: sequence_length`), 그 관찰을 요구하는 한계 | limitations.md | — |
| 규칙에 `kinetics` 추가 | 속도 기반 시뮬레이션의 그 단계(즉시 → 속도), competition 경쟁의 해상도(structure → site), kinetics 한계의 상태 | limitations.md, 부록 | — |
| 부위에 잔기 번호 추가 (`residue_unknown` 해제) | residue 한계의 상태, 묶음 꼬리표의 잔기 표시, detectGaps | limitations.md, 부록 | — |
| 부위에 `structure` 추가 | 그 부위를 쓰는 단계의 갖춘 해상도 → structure | 부록 | 정의항 xrefs 에 같은 PDB |
| 상태 의미 규칙 변경 | 모든 묶음의 활성 → 행위자 검사·시뮬레이션 | — | 그 정의항을 행위자로 쓰는 단계가 여전히 통과하는지 |
| 단계 추가 | 기전 사슬(next/prev), 경로의 단계·패턴·해상도, 시뮬레이션 | 부록 | `pattern` 으로 새 패턴 확인 |
| kind process 정의항에 `motif` | 그 개념의 사례 경로 (모든 경로에서 계산) | 부록 | `addresses` 또는 `gap_review` |
| 한계 등록 | 감사 교정 제안, 시뮬레이션 "등록된 한계" 표시 | limitations.md, 부록 | — |
| `vocab.js` 값 추가 | 허용되는 값, 별칭 매핑 | 부록 | SCHEMA 변경 기록 |
| `core.js` 규칙 변경 | 검사·계산 전부 | 부록(엔진 상수가 바뀌면) | 테스트(거부 테스트), SCHEMA, 교과서 4장 |
| 형식 변경 | — | db.json(마이그레이션) | migrations/NNN, SCHEMA 변경 기록, 교과서 3장 |
| 파일 추가·이동 | — | 부록 9.3 | storage-map.json (없으면 CI 실패) |
| `viewer.html` 변경 | — | index.html (복사) | — |

## 5.5 원천 ↔ 결과: 규칙이 다리를 놓는 방식

```
정의항 D000043 (인산화효소 키네이스)                       단계 S000009
  site.pka_phos [phosphorylated]                           rule: D000043/rule/gp_phos ─────┐
  rule.active  : pka_phos:phosphorylated → active  ◀─ 행위자 활성 검사 ─ agents: D000043|pka_phos:phosphorylated|cytosol
  rule.gp_phos : 인산화, agent, target D000044,             inputs : D000044|cytosol      ◀─ 변화량 = remove(없음) → add phosphorylated
                 site reg_phos, add phosphorylated   ───▶   outputs: D000044|reg_phos:phosphorylated|cytosol
                 with ATP → ADP                     ───▶   + ATP(minor) / ADP(minor)
정의항 D000044 (글리코겐 인산화효소)
  site.reg_phos [phosphorylated] (사람 Ser14) ◀─ 묶음의 부위:특징이 정의돼 있나
  rule.a_form : reg_phos:phosphorylated → active ──▶ 다음 단계 S000010 의 행위자 활성
```
단계는 "무엇이 바뀌었나"만 갖고, "왜 그렇게 바뀔 수 있나"는 원천의 규칙·부위에 있다. 검사가 둘을 맞춘다.

## 5.6′ MCP 서버 — 에이전트가 저장소와 말하는 길 (`mcp/`, 설계 `outsourcing-and-mcp.md` §4)

| 서버 | 기다리는 것 | 하는 일 | 쓰기 |
|---|---|---|---|
| `query` | 메모리 | db·색인·원장을 띄워 두고 읽기. db·원장 파일의 (크기, 수정 시각)이 바뀌면 다음 호출에서 다시 읽는다 | 없음 |
| `fetch` | 네트워크 | 접근 판정(open·free_read·paywalled) → 공개 전문·초록만 받기, 원천별 요청 간격 | 서기 받기(증거 구역) + 받기 기록 |
| `clerk` (입출력기) | 거의 없음 | 역할 확인 → 권위 쓰기는 dbtool 명령(사법부 재판정 → 서기) · 수집가는 핸드오프 붙이기만 · 잠금으로 하나만 | 유일한 작성자 |

요청 하나의 길: 클라이언트 → JSON-RPC 한 줄(`tools/call`) → 역할에 그 도구가 있나(없으면 거부) → 실행 → 글 + 구조 결과. 역할은 시작할 때 `BIODB_ROLE` 로 정하고, 기본은 `collector`.

## 5.7 CI (`.github/workflows/check.yml`)

푸시마다 순서대로: `node --test tests/*.test.mjs` → `node dbtool.mjs validate` → `limitations --check` → `attest`(도장 무효 0) → `limitations --detect`(미등록 후보 0) → `trend`(미등록 `Consensus_Gap` 후보 0 — 합의 수신함이 커밋되어 있어 네트워크 없이 돈다) → `textbook --check`(부록 최신 + 모든 파일 분류) → `cmp index.html viewer.html`. 하나라도 실패하면 빨간불. 생성물을 갱신하지 않고 데이터만 커밋하면 CI 가 잡는다.

> **CI 가 조용히 죽을 수 있다.** 2026-10-10 감사에서 워크플로의 `name:` 값에 `': '` 가 들어가 YAML 이 깨져 있었고(ccabd83 이후), 그동안 **GitHub Actions 가 아예 돌지 않았다**. 따옴표로 고치고 `tests/governance.test.mjs ④″` 가 그 실패 방식을 겨눠 검사한다 — 평문 스칼라의 `': '` 와, CI 가 돌려야 하는 명령 목록(`--test`·`validate`·`attest`·`limitations --detect`·`trend`·`textbook --check`·화면 사본 대조)이 줄지 않았는지. 검사기를 검사하지 않으면 검사가 없는 것과 같다.
