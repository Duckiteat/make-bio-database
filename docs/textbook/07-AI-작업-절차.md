# 7장. AI 작업 절차 (플레이북)

모든 명령은 저장소 최상위에서. 패치는 저장소 **밖**(스크래치 폴더)에 쓰고 `--dry` 부터.

## 7.0 세션을 시작할 때

```sh
node dbtool.mjs status                 # 규모·오류·다음 번호
cat limitations.md                     # 열린 한계 (새 개념을 설계할 거면 필독)
node dbtool.mjs prompt | less          # 작성 규칙·어휘·현재 색인
```

## 7.1 개념·정의항 넣기

1. 이미 있는지: `node dbtool.mjs map <이름|영문명|UniProt|CHEBI:…>` — 있으면 그 번호를 쓴다. 뜻이 여럿이면 `context` 로 맥락을 보고 고른다.
2. 패치:
```json
{ "format": "definition-db-patch", "version": 7,
  "terms":  [{ "id": "T+1", "names": { "ko": "…", "en": "…" }, "aliases": [] }],
  "senses": [{ "id": "D+1", "term": "T+1", "kind": "protein", "reference_species": "9606",
               "xrefs": [{ "db": "UniProt", "id": "확인한 것만" }],
               "desc": [{ "text": "…", "field": "생화학", "context": { "scope": "…" },
                          "links": [{ "to": "효소#1", "rel": "is_a", "span": "효소" }],
                          "evidence": { "level": "curated", "sources": [{ "db": "DOI", "id": "10.…", "citation": "Kim et al., 2020" }] } }],
               "site": { "s32": { "type": "modification_site", "features": ["phosphorylated"], "numbering": { "9606": "Ser32" } } } }] }
```
3. 지킬 것: 복합체는 구성 요소를 **빠짐없이**, 모르는 잔기는 `residue_unknown: true`, 모르는 필수 ID 는 `unmapped`, 인용은 서지를 확인한 것만(못 하면 `abstracted` + `basis`).

## 7.2 기전(경로) 넣기

1. 원천부터: 각 분자의 부위·상태 의미 규칙·전이 규칙을 정의항에 둔다(규칙 = 그 변화를 일으키는 쪽이 소유, 결합은 부위가 바뀌는 쪽).
2. 단계는 규칙 참조 + 묶음만:
```json
{ "id": "S+1", "rule": { "owner": "D+1", "id": "phos" },
  "agents": [{ "ref": "D+kin", "features": { "act": "phosphorylated" }, "location": "cytosol" }],
  "inputs": [{ "ref": "D+1", "location": "cytosol" }, { "ref": "ATP", "location": "cytosol", "minor": true }],
  "outputs": [{ "ref": "D+1", "features": { "s32": "phosphorylated" }, "location": "cytosol" }, { "ref": "ADP", "location": "cytosol", "minor": true }],
  "part_of": ["경로 이름"] }
```
3. 위치는 묶음마다. 막을 넘으면 수송 단계(`transport`). 공간 접촉 오류가 나면 위치·면을 고친다(규칙을 느슨하게 하지 않는다).
4. 병합 후:
```sh
node dbtool.mjs mechanism "<경로>"                       # 사슬이 이어졌나
node dbtool.mjs simulate "<경로>" --until <출력> --from <입력>   # 유도되나 (음성 대조: --init "키=0")
node dbtool.mjs pattern "<경로>"                         # 상위 패턴 — 상위 개념이 없는 패턴이 두 경로 이상이면 7.4
node dbtool.mjs resolution "<경로>"                      # R2 가 필요한 단계 = 경쟁
node dbtool.mjs audit-run "<경로>"                       # Audit Error → 7.3
```

## 7.3 한계 등록하기 (실패를 데이터로)

언제: 시뮬레이션 실패·우회, 감사 오류, 단순화(화학량 차용, 부위 묶기), 확인 못 한 값.
```json
{ "limitations": [{ "id": "L+1", "target": "TNF 유전자/rule/kb_binding", "type": "Kinetic_Gap",
    "requirement": { "text": "무엇이 모자라 무엇을 못 하나",
                     "needs": [{ "kind": "kinetics", "rule": "TNF 유전자/rule/kb_binding", "params": ["Kd"] }] },
    "found_in": "어디서 드러났나" }] }
```
- 해결 경로는 **잘못 닫히지 않게** 구체적으로 (예: "PDB 아무거나"가 아니라 그 결합면을 담은 구조 → 형식으로 확인할 수 없으면 `manual`).
- 병합 후 `node dbtool.mjs limitations --write`, `--detect` 후보 0 확인.

## 7.4 상위 개념 만들기 (Evolution Engine)

1. `limitations.md` 를 먼저 읽는다.
2. Step A (아래에서 위로): 반복되는 패턴 → kind process + `motif`:
```json
{ "id": "D+kc", "term": "키네이스 연쇄", "kind": "process", "motif": "kinase_cascade",
  "desc": [{ "text": "…", "field": "세포생물학", "context": { "scope": "신호 전달 일반" }, "links": [],
             "evidence": { "level": "abstracted", "basis": "D…·D… 경로의 단계 구조에서 검출" } }],
  "addresses": [{ "limitation": "L000006", "how": "…(부분)" }] }
```
   해결하는 한계가 없으면 `gap_review` 에 이유. 둘 다 없으면 거부된다.
3. Step B (한계에서): 한계를 해결하는 새 개념(원리·모델)을 설계할 때 **엔진이 그 개념을 실제로 쓰게** 만든다(예: 구획 농도 모델 → 시뮬레이터가 copy_number·부피를 읽음). `addresses.how` 에 어떻게 자동 해결되는지 적는다.

## 7.5 속도 상수 넣기

- 확인한 값만 규칙의 `kinetics` 에, SI 정준 단위로, 근거와 함께. 종·조건은 `kinetics.context`.
- 협동 결합(예: cAMP 4분자)은 `binding` 이 아니라 `mass_action` + `order`.
- `Kd` 와 `k_on`·`k_off` 를 함께 적으면 10% 안에서 맞아야 한다.
- 엔진만 시험하려면 `examples/scenarios/*.json` 에 `hypothetical: true` 로 — 데이터베이스에는 넣지 않는다.

## 7.5A 생애 주기·대사물 저장소 넣기 (v7)

- **부분 구조**: ATP 처럼 반응에서 부분이 옮겨 다니는 분자는 `moieties` 를 단다(`아데노신 부분`·`구아노신 부분`·`인산기 단위` 정의항). 달면 그 분자가 낀 변환·분해·공급 규칙의 수지가 검사되므로, **빠진 산물(피로인산·Pi)을 같은 패치에서 규칙(`effect.produces`·`with.produces`)과 단계(minor 출력)에 함께 넣는다.**
- **공급 규칙**: 소비만 되는 저장소(AUDIT_RESOURCE)를 닫으려면 그 반응을 일으키는 효소 부류나 과정 정의항에 `supply` 규칙을 둔다. 효소가 없다면(원료를 모델 밖에 둠) process 정의항에 두고 `evidence: abstracted`. 원료가 정말 계 밖이면 `source: true`. 속도를 모르면 `kinetics` 를 비우고 Kinetic_Gap 등록.
```json
{ "id": "D+ndpk", "term": "T+ndpk", "kind": "molecule_class", "xrefs": [{ "db": "EC", "id": "EC 2.7.4.6" }],
  "rule": [{ "id": "gtp_regeneration", "type": "supply", "label": "GTP 재생",
             "consumes": [{ "ref": "GDP", "n": 1 }, { "ref": "ATP", "n": 1 }], "produces": [{ "ref": "GTP", "n": 1 }, { "ref": "ADP", "n": 1 }],
             "where": ["cytosol"], "evidence": { "level": "asserted" } }] }
```
- **분해 규칙**: 분해되는 정의항에 `degradation` 규칙. 단위체로 돌아가면 `fate: recycled` + `recycle_to`(화학량을 서열 길이로 쓰려면 `n: "sequence_length"` + `sequence_length` 관찰). 반감기는 확인한 값만 `kinetics: { law: "mass_action", order: 1, half_life }`.
- 시험은 `examples/scenarios/` 의 가상 시나리오(`reservoirs`·공급·분해 kinetics). `node dbtool.mjs simulate <경로> --rate --scenario … [--stochastic --seed 7] [--reservoirs infinite]` 후 `audit-run`.

## 7.6 규칙·코드를 바꿀 때 (사용자 요청이 있을 때만)

1. `vocab.js`/`core.js` 수정 → 거부 테스트 추가(`tests/rules.test.mjs`)
2. 형식이 바뀌면 `migrations/NNN-…mjs` 작성·실행, `SCHEMA.md` 변경 기록
3. 교과서 해당 장(3·4·5·6) 수정
4. 확인:
```sh
node --test tests/*.test.mjs && node dbtool.mjs validate && node dbtool.mjs limitations --check && node dbtool.mjs textbook --check
```
