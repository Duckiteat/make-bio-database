# 생체 기전 데이터베이스·시뮬레이터 — 한 장 개요

> 바깥(지도교수·학과·협업자)에게 보여주기 위한 한 장짜리 설명. 과장 없이, 지금 참인 것만.
> 저장소: `make-bio-database`. 자세한 설계는 `docs/design/`, 작동은 `docs/RUNBOOK.md`.

## 문제
생물 기전 시뮬레이터 대부분은 **임의·미큐레이션 매개변수**로 돌아가고, 결과가 **감사 가능하지도 반증 가능하지도** 않다. "모델이 맞다"는 주장과 "어디서·왜 틀리는지"가 분리되지 않아, 연구·규제에서 신뢰하기 어렵다.

## 접근 — 차별점
살아 있는 생명체의 기전을, **등급 붙은 실측 데이터에 매인 채** 시뮬레이션한다. 네 기둥:
1. **신뢰 기층** — 모든 값에 출처·불확도·등급(S·D). 공백은 숨기지 않고 한계로 등록. 값을 지어내지 않는다(없으면 "가상"으로 명시).
2. **반증 가능한 검증** — 사전 등록된 모의 실험 규약 아래, **추정에 안 쓴 실측**과 대조(일치 / 충돌 / 구별 불가). "완벽히 맞으면 오히려 수상(순환·조작)"을 깃발로 잡는다.
3. **비트 정확·검증 가능 엔진** — 삼권 분립(실행·입법·사법)으로 독립 재검증, JS=Rust 비트 동일, **수치 오차·물리 요동·모델-현실 불일치를 구조적으로 분리**(섞으면 결론이 뒤틀리므로).
4. **사람이 읽는 증거·방법 보고서** — 인과 사슬(기질→효소→산물)·쓰인 값 전부(등급·출처)·실패한 시도·"바닥의 불안정함"까지. 분야 전문가가 하나를 읽고 결론을 이해하고 질문할 수 있게.

## 왜 중요한가
- 규제(FDA computational model credibility, ASME V&V 40)와 QSP(정량 시스템 약리)가 바로 이 **신뢰·감사 문서화**를 요구하는데, 기존 도구가 가장 약한 지점이다.
- LLM-for-science 의 **근거 사실 기층**(지어내지 않고 출처·등급이 추적되는) 으로도 쓰인다.

## 지금 상태 (정직하게)
- **신뢰·검증 파이프라인**: {효소 속도 상수 · 대사물 농도 · 정성 교란 결과} 에 대해 **완성·end-to-end**(등급·사전 등록 규약·동등성 검정·정성 판정·우연 기준선).
- **실측 코퍼스**: 아직 작다 — 사람 효소 상수 소수(예: TCA 회로 4/8 단계). **현실 검증 track record 를 지금 막 쌓기 시작.**
- **아직 아님**: 구획 pH·반응 흐름·시계열 측정(스키마 확장 필요), 불균일 공간(적분장) 엔진, 대규모화 — 모두 "등급 데이터 자원이 먼저" 라는 원칙에 따라 자원 뒤로.

## 다음
현실 검증 한 건을 end-to-end 로 돌려 **첫 신뢰 닻**을 만든다 → 등급 코퍼스·검증 이력 축적 → 특정 치료 영역의 검증된 모델 → 규제급 신뢰성 보고서. "현실과 맞나 · 연구가 되나 · 쓸 수 있나" 는 규모만 다른 같은 사다리이고, 그 첫 칸이 이 검증이다.
