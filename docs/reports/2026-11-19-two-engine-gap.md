# 두 엔진의 차이 측정 (PLAN-055) — 속도 엔진 대 운명 엔진

> 2026-11-19 · develop 모드 · 재현: `node --test tests/engine_gap.test.mjs` · 조정자 `orchestrator.engineGap(db, 경로, 세포 상태, 시나리오, { t_end, dt, matchStart })` · 판정 `judicial/engine_gap.js`

## 1. 한 줄 결론

두 엔진의 큰 차이는 **적분 방식이 아니라 입력 해석**(시작량 기본값 · '즉시' 단계 · 계의 경계)에서 나온다. 입력을 맞추면 LPS 경로의 공유 묶음 42 개가 1800 s 전 구간에서 상대 3.4e-6 안에서 같다 — 속도 엔진의 Δt 의존(≤ 4e-7)과 운명 엔진의 허용 오차(≤ 2.6e-6) 수준이다. PLAN-080(속도 엔진을 운명 엔진 앞단으로)은 수치를 바꾸는 일보다 **입력 해석을 하나로 정하는 일**이 먼저다.

## 2. 측정 (끝 값, 공유 묶음, 차 = |속도 − 운명| / max(1, |속도|, |운명|), 허용 1e-4)

|---|---|---|---|

## 3. 차이의 원인 다섯 — 코드에서 확인

| 원인 | 속도 엔진 (`core.js simulateRate`) | 운명 엔진 (`engine/fate_engine.js`) | 크기 · 보기 |
|---|---|---|---|
| ① 시작량 기본값 | 시나리오가 주지 않은 묶음을 세포 기본값으로(TNF 유전자 2), 보조 입력 · 보조 기질은 대사물 풀로(ATP 1e8, 309–313 행) | 시나리오가 주지 않으면 0 | 차 1 (한쪽이 0). 아래 §4 의 병리와 검증 결론 문제의 뿌리 |
| ② 속도 상수 없는 단계 · 막에서만 일어나는 단계 | '즉시'(사건 기반)로 처리 (approx) | 상수 없으면 끔(Kinetic_Gap), 막 단계는 시나리오 막 유효 부피로 속도 법칙 | MHC 에서 차 1 인 묶음 13 개. 한계 L000081 |
| ③ 계의 경계 | 경로 하나의 단계만 | 세포 상태의 기전 경로 전부 + 대사 · 표지 규칙을 한 계로 | MHC 에서 경로마다 1 (두 경로가 같은 항원을 나눠 씀) |
| ④ 적분 | 명시 오일러 · 고정 Δt · 단계 순차 갱신 · 가용량 자르기 | Rodas3 (L-안정, 오차 제어) | MHC II 에서 Δt 1e-3 → 1e-4 로 끝 값 1.8 % 바뀜. LPS 는 4.6e-7 |
| ⑤ 보조 입력의 가용량 | 대사물 풀로 넉넉히 두어 막히지 않음 | 화학량으로는 소비하지만 속도식에 들어가지 않음(minor) — 0 이어도 멈추지 않음 | §4 |

## 4. 찾은 것 — 사람이 정할 일 (RULE-0260 · 0262)

| 찾은 것 | 재현 | 왜 문제인가 | 어디서 고치나 (갈림) |
|---|---|---|---|
| `lps-tnf-validation` 운명 실행의 음수 거부 병리 — 5 s 에 받아들인 단계 473,891 · 음수 거부 473,895 · 최소 h 8.4e-7 s | `node -e` 로 `simulateFate(db, 'D000212', { scenario: (t_end 5, dt_slow 5) })` · 음수 묶음은 ATP(`D000032\|cytosol`) 하나, 최솟값 −1.9e-160 | 시나리오가 ATP 를 주지 않아 0 에서 시작 → 인산화 단계(S000018 · 20–27)가 ATP 를 보조 입력으로 소비하지만 속도식에는 없어 멈추지 않음 → 매 단계 음수 → 거부. 1800 s 실행은 사실상 끝나지 않는다 | 데이터(시나리오에 ATP 를 준다) 또는 코드(보조 입력이 0 이면 단계를 막거나, −atol 안의 음수를 받아들임). 결함 태그가 갈려 `NUMERICAL` 로 가정하고 물었다 → **사용자 결정 DEC-0063: 엔진에서 막기** — 고침: 컴파일러가 속도식 밖 반응물을 `mg` 로, 엔진(JS · Rust)이 속도에 Π min(1, N/n). 1800 s 를 45 단계 · 48 ms, ATP 는 0 에서 멈춤, 넉넉하면 ×1 이라 다른 궤적 비트 그대로 |
| 같은 시나리오에서 운명 엔진의 TNF 유전자(`D000100\|nucleoplasm`) 시작량이 0 | 위와 같음 — 속도 엔진은 2, 운명 엔진은 0 | 유전자가 0 이면 TNF 전사가 일어날 수 없다. 이 시나리오는 "fate 엔진에서 TNF mRNA 까지 흐르게 한다" 고 적힌 검증 대조군이다(풀린 시나리오의 정준 해시는 사전 등록부에 없음 — 지금은 탐색 실행) — 그 검증이 무엇에 기대는지 다시 봐야 한다 | 사용자 결정 DEC-0063: 시작량은 **명시만 허용** — 숨은 기본값을 없애고 빠진 시작량은 보고 · 거부(PLAN-080 에서). 이 시나리오에 TNF 유전자 수를 적는 일은 데이터 작업 |

## 5. PLAN-080 · 056 에 주는 것

- 속도 엔진을 같은 IR · Rodas3 앞단으로 옮기면 ④ 는 사라진다 — 측정상 ④ 는 LPS 에서 이미 작고(4.6e-7), MHC II 에서만 1.8 %.
- ① · ② · ⑤ 는 엔진을 하나로 해도 저절로 사라지지 않는다 — **기본값 · '즉시' · 보조 입력의 의미를 컴파일러 한 곳에서 정해야** 두 경로가 같은 계를 푼다. 지금 출하 시나리오 중 속도 엔진으로만 도는 경로(cAMP D000051 · TCA D000148 · LPS D000102)는 이 기본값에 기대어 있다 — 080 으로 옮기면 궤적이 바뀐다(기존 보고 결과와 대조 필요).
- ③ 은 대상의 차이(경로 대 세포 상태)라 판정의 몫 — `engineGap` 이 '계의 경계' 로 따로 센다.

## 6. 측정 도구

- 조정자 `orchestrator.engineGap` — 속도 엔진(Δt · Δt/10)과 운명 엔진(본 실행 · 허용 오차 1/1000 기준)을 돌려 원자료를 사법부에 넘긴다. `matchStart` 는 운명 엔진 시나리오에 없는 시작량을 속도 엔진의 시작 상태로 채워 ① 을 뺀다.
- 사법부 `judicial/engine_gap.js` — 공유 묶음마다 차 · Δt 의존 · 허용 오차와 원인(start_default · boundary · instant_step · dt · numerical · unexplained). unexplained 가 있으면 `ok` 거짓 — 새 구멍을 사람에게.
