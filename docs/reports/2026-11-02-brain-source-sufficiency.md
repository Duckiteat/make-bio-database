# 인공간뇌의 기초 데이터 원천으로서 엔진 형태의 충분도 판정 (2026-11-02)

> 질문(사용자): 엔진의 형태가 인공간뇌의 기초 데이터를 쌓아 올리는 원천 데이터베이스 역할을 하기에 충분한가.
> 사용자가 정한 틀(원문 요지): "결정론장을 가장 현실에 닿는 바닥(Ground Truth)으로 삼아 확률장을 단단하게 붙잡고, 궁극적으로 인공간뇌의 기초 데이터를 쌓아 올리는 **통합 시스템**" — 조회 · 실행 · 데이터 생성을 모두 쓰는 쪽(질문 선택지 4번)이고, 결과는 **충분도 판정표 + 부족한 점 목록**.
> 용어: "인공간뇌"는 저장소 어디에도 정의돼 있지 않다(검색 0건). 이 보고서는 사용자의 설명만을 기준으로 삼았고, 인공간뇌가 요구하는 규모 · 데이터 종류는 모른다(§4).
> 저장소의 용어와 맞추면: **결정론장** = `baseline` 모드의 "지금 검증된 코어"(운명 엔진 + 속도 엔진 + 사법부), **확률장** = `field` 모드의 T3 확률장 · T4 스파크 · T5 핵 기억(`docs/design/integral-field-engine.md`, "설계, 미구현"). 현재 코드에 있는 SSA · τ-도약 혼성 확률 층은 확률장이 아니라 **구획(공간 없음) 수준의 확률 층**이다.
> 판정 표기: **충족** · **부분** · **미충족** · **미확인**. 칸: 범위(기준) · 이유(판정과 근거) · 영향(인공간뇌에 왜 중요한가) · 확인(근거 위치).
> 직접 잰 것과 읽은 것을 구분했다. 이번 세션에서 직접 잰 것: JS = Rust 비트 일치, 수학 함수 정밀도, 결정론 시나리오의 결과 변화, 벤치, 데이터베이스 개수. 문서로만 확인한 것은 `(문서)`로 표시했다.

## 1. 한 줄 결론

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| **형태(아키텍처)** | 바닥에 필요한 성질 — 한 코어 · 하나의 불변 db, 재현성(JS = Rust 비트 26/26), 보존 원장 + 독립 검증, 반증 가능한 사전 등록 · 근거 추적 · 정직한 공백 · 철회 전파 — 은 **대부분 갖췄다**. 결정론장에 확률 층을 붙잡는 장치(같은 IR · 결정론 극한 수렴 시험 · 해석해 일치)도 구획 수준에서는 있다 | 쌓아 올릴 **토대의 골격은 충분하다** | §2 A·B·C |
| **그러나 바닥이 아직 "현실"이 아니다** | 결정론장이 닿아 있는 것은 현실이 아니라 **가정 값**이다: 실측 속도 상수가 있는 규칙 4 / 160(2.5 %), 시나리오 44 개 중 43 개가 가상, 현실과의 정량 일치 검증 0 | **Ground Truth 라는 이름의 가장 큰 구멍** — 엔진이 아무리 정밀해도 이 바닥 위에서는 "가정의 정확한 계산"일 뿐이다 | §2 A6 |
| **확률장(공간)은 없다** | T3 확률장 · T4 · T5 는 설계뿐이고 4부는 stage 1 에서 멈췄다(DEC-0028), 정수 장 코드는 보관 파일로 옮겨졌다(DEC-0032) | "확률장을 단단히 붙잡는다"는 **붙잡을 대상이 아직 없고**, 붙잡는 방식(관문 D · 결정론 영역 ≥ 100 전환)만 설계에 있다 | §2 B7–B10 |
| **밖에서 쓰는 문이 좁다** | 조회는 MCP 12 도구로 열려 있지만 **실행(시뮬레이션) 도구는 MCP 에 0 개**, 내보내기 형식(SBML · SED-ML · OMEX)도 없다 | 인공간뇌가 읽을 수는 있으나 **돌리거나 가져가기 어렵다** | §2 C2 · C9 |
| **내용(규모 · 도메인)** | 정의항 212 개, 세포 맥락 4 종(간세포 · 대식세포 · 수지상세포 · 섬유아세포), 인간만, 신경 관련 정의항 0 | 형태와 별개로 **인공간뇌의 기초 데이터라고 부르기엔 내용이 매우 이르다** | §2 C10 · C11 |

## 2. 충분도 판정표

### A. 결정론장 — 바닥(Ground Truth)의 자격

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| A1 재현성 | **충족**. 같은 입력이면 같은 출력, 그리고 **JS 와 Rust 가 비트까지 같다: 시나리오 26/26**(이번 세션 이전 1/26). 난수는 번호로 찾는 방식이라 걸음 거부 · 허용 오차 변경에 안 밀린다 | 바닥의 값이 실행 환경에 안 흔들린다 | 직접 측정: `node tests/fingerprint.js parity`, `tests/detmath.test.mjs` |
| A2 보존 · 무결성 | **충족**. 부분 구조 원장 ≤ 1e-14, 저장소 재생 검사, 사법부의 독립 질량 검증기(엔진 장부를 안 믿고 화학량을 db 에서 다시 셈) | 물질이 새거나 규칙 밖에서 바뀌면 잡힌다 | `judicial/verifier.js`(문서 + 시험 통과) |
| A3 수치 정확도 | **부분**. 운명 엔진은 L-안정 Rodas3 + 오차 제어이고 수학 함수는 ≤ 1.02 ulp(직접 잼), 결정론 극한 · 해석해 시험 통과. **속도 엔진은 1차 명시 오일러**(Δt 에 따라 끝 값 상대 6.5e-5 변함) | 운명 엔진은 바닥으로 쓸 만하지만 속도 엔진은 아니다 | 직접 측정, 해부 1호 E2 |
| A4 시간 | **부분**. 격자를 정수 번호로 세고 기록 시각 = 실제 적분 끝, 신호는 선언한 시각에 적용, 속도 엔진은 `t_end` 를 넘지 않음(오늘 수정). 남은 것: 속도 엔진 시각의 소수 9 자리 반올림, **사법부가 시각을 엔진과 독립적으로 다시 세지 않음**, 벽시계 시간이 변형 비교 판정의 비용 항에 들어감(K7) | "언제"를 검증하는 눈이 엔진 자신과 같다 | 직접 측정, 해부 2호 §2 |
| A5 하나의 진실 | **미충족**. 속도 엔진 (오일러 · 즉시 단계 · 순차 갱신)과 운명 엔진 (Rodas3)이 같은 db 규칙을 다르게 풀고 서로 기준이 될 수 없다(L000081). "한 순수 코어 + 하나의 불변 db" 원칙이 엔진 단위에서는 깨져 있다 | 바닥이 둘이면 어느 쪽이 데이터의 뜻인지 정할 수 없다 | PLAN-080 · 055 · 056(대기) |
| **A6 현실 닻(가장 중요)** | **미충족**. 규칙 160 중 실측 속도 상수가 있는 규칙 **4**(2.5 %, 모두 TCA 효소), 시나리오 44 중 가상(`hypothetical`) **43**, 수치 관찰 52 건 중 **상태량 측정은 6**(농도 2 · 부피 3 · 복제수 1, 나머지 46 은 서열 길이), `kinetic_constant` 관찰 0, 정량 검증 0(방향 문서가 스스로 적음) | 결정론장이 "가장 현실에 닿는 바닥"이 되려면 이 숫자가 바뀌어야 한다. 엔진 · 기록 개선과 무관한 **데이터 일**이다 | 직접 집계, `docs/design/direction.md` §3 |
| A7 반증 가능한 구조 | **충족**(구조). 사전 등록 사슬(실행 전 시나리오 해시), 모의 실험 규약(음성 대조 · 검정력 · 검증/추정 분리), 우연 기준선, 등급 관문, 승인 도장. 실제 사전 등록은 **5 건**, 도장 등록부 363 줄 | 장치는 있으나 실제로 돌려 본 횟수는 적다 | 직접 집계 `data/preregistrations.jsonl` |
| A8 표현력 | **부분**. 구획마다 잘 섞인 평균 농도(위치 · 확산 없음), 미카엘리스–멘텐이 첫 기질만(PLAN-083), 활성 힐 바닥 1, 전이 상태 이론형 상수는 운명 엔진에서 꺼짐, 온도 · pH 파생층은 열린 질문 | 표현하지 못하는 것은 조용히 빠지는 것이 아니라 한계로 등록 · 보고되는 편이지만, 공간 · 입체는 아예 없다 | 해부 1호 E3 · E4 |
| A9 단위 · 자리수 | **부분**. 정확한 유리수 환산 · 차원 검사(속도 법칙) · 원문 자리수 대조(ASY-08 일부). 추적성 칸 · 불확도 예산 칸 남음. 컴파일 단계 상수는 아직 `Math.exp` 등 사용 | 값의 단위 오류를 막는 틀은 서 있다 | ASY-08(진행) |
| A10 성능 | **부분**. Rust 가 JS 의 2–5 배(직접 벤치). 새 수학 함수의 비용은 **확률 궤적 한 번 JS 1126 → 1382 ms(+23 %), Rust 360 → 416 ms(+16 %)**(반복 없는 1 회 측정이라 잡음 크기를 모름). 규모 한계는 정의항 20 만(문서) 이전에 작업 흐름이 먼저 막힘 | 지금 규모(212)에서는 문제없다 | 직접 벤치, `scaling-limits.md` |

### B. 확률장을 결정론장에 붙잡는 형태

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| B1 한 코어 · 같은 규칙 | **충족**. 혼성 확률 층(SSA · τ-도약 · Rodas3)이 결정론과 **같은 IR · 같은 속도식**을 쓴다. 규칙마다 분자 수 · 속도로 방식을 고른다 | 확률 층이 결정론장과 다른 법칙을 몰래 쓸 수 없다 | `engine/fate_engine.js` |
| B2 결정론 극한 수렴 | **충족**(구획 수준). 계의 크기 Ω 1 · 4 · 16 에서 앙상블 평균과 결정론 궤적의 상대 차가 줄어듦, 출생–사멸 해석해 pmf 일치, SSA 대 τ-도약 같은 분포 | "확률장이 결정론장에 수렴한다"는 핵심 약속의 구획판이 시험으로 서 있다 | `tests/stochastic.test.mjs` ① ② ③ |
| B3 분포 판정 도구 | **충족**. χ² 적합도 · 이산 AD · KS · 검정력 · 앙상블 판정(사법부 통계) | 확률 결과를 한 번 돌린 값이 아니라 분포로 판정한다 | `judicial/stats.js` · `stoch_audit.js` |
| B4 시드 표류 · 짝 판정 | **부분**. 엔진 난수는 번호로 찾는 방식이 됨(오늘). **공통 난수 짝 판정(사법부)은 없음** | 변형 A 대 B 를 같은 난수로 비교하려면 사법부 쪽이 남음 | PLAN-020(진행) |
| B5 JS = Rust(확률 실행) | **충족**. 확률 실행 시나리오도 비트 일치 | 확률 결과도 환경에 안 흔들린다 | 직접 측정 |
| B6 성향의 근사 | **부분 · 미확인**. 미카엘리스–멘텐 · 힐 식을 SSA 성향으로 그대로 씀(분자 수가 적으면 근사). **같은 분자끼리의 반응(2A)이 N² 인지 N(N−1)/2 인지 확인 안 함** | 분자가 적은 영역에서 확률 층의 정확도 | 해부 1호 E5, 입문 보고서 §3 |
| **B7 공간(T3 확률장)** | **미충족**. 4차원 격자 · 정수 분자 수 · 면 유속은 **설계뿐**(문서가 "설계, 미구현"). 정수 장 stage 1 은 원장 오차 정확 0 까지 증명했지만 코드는 보관 파일로 옮겨졌다 | 사용자가 말한 "확률장"의 본체가 아직 없다 | `integral-field-engine.md`, DEC-0028 · 0032 |
| B8 T4 스파크 · T5 핵 기억 | **미충족**(설계뿐) | 같음 | 같음 |
| B9 붙잡는 규칙 | **미확인**. 설계에 "면당 이동 ≥ 100 이면 결정론, 1–100 포아송, < 1 입자" 문턱과 결합점 등록부가 있으나 공간에서 한 번도 검증되지 않음 | 결정론장이 확률장의 "단단한 바닥"이 되는 지점 | PLAN-027 결과 문서 |
| B10 관문 D | **미충족**. "새 엔진 대 기존 엔진을 검증 관찰로"(PLAN-030)가 대기. `field` 모드의 멈춤 규칙: "반박할 공간 관찰이 있나?"가 아니오면 결론 금지 | **공간 관찰이 없으면 확률장은 만들어도 결론을 못 낸다** | `docs/modes/field.md` |

### C. 인공간뇌의 기초 데이터 원천으로서

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| C1 읽기 인터페이스 | **충족**(구조). MCP 조회 도구 12 개: 요약 · 참조 매핑 · 맥락 · 기전 · 사고 패턴 · 한계 · 기원 · 가정 사용처 · 정성 그래프 · 철회 전파 · 수신함 · 후보 판정 | AI 가 질의로 정의 · 기전 · 한계를 읽을 수 있다 | `mcp/query.mjs`(직접 확인) |
| **C2 실행 인터페이스** | **미충족**. `simulate` · `fate` · 앙상블을 부르는 MCP 도구가 **0 개**(검색 결과 0). 실행은 `dbtool` 명령행과 JS 함수뿐 | AI 가 시나리오를 만들어 **엔진을 돌려 예측을 받는** 길이 표준화돼 있지 않다 | 직접 확인 `mcp/*.mjs` |
| C3 근거 · 등급 · 불확도 노출 | **충족/부분**. 관찰의 출처(DOI · PMID) · 신뢰 등급 · 값의 근거(`from`) · 가정 원장(A…) · 시나리오 시작 숫자의 기원(실측/추상/가정) · 불확도 출처 칸. 추적성 칸 · 불확도 예산은 남음 | 인공간뇌가 값의 무게를 알 수 있다 | `origin` 도구, SCHEMA |
| C4 정직한 공백 | **충족**. 한계 124 건(등록부), 커버리지(측정 사각) 지도, 지원 안 하는 법칙은 꺼지고 사실로 보고 | 모르는 것을 아는 척하지 않는다 | `limitations.md`, `dbtool status` |
| C5 갱신 · 철회 | **충족/부분**. 철회 → 파생값 → 결론 승인 재검토로 전파. 단일 작성자 잠금이 원자적이지 않아 동시 쓰기에서 잃어버린 갱신 위험 | 데이터가 바뀌어도 결론의 근거가 따라온다 | `retractionImpact`, 앞 구조 분석 D1 |
| C6 계산 과정 기록 | **미충족**. 실행 단위 기록(입력 · 코드 · 설정 · 환경 · 출력 해시) 없음. 입력 해시와 사전 등록 사슬만 | 바닥의 값이 어떻게 나왔는지 사후 재현을 묶을 수 없다 | PLAN-089(대기) |
| C7 주장 · 출력 추적 | **미충족** | 인공간뇌가 가져간 값을 원천 실행까지 되짚을 수 없다 | PLAN-091(대기) |
