## 0. 한 문단으로

실험 노트 하나를 우리 형식에 넣어 보니, 원문에 오차가 안 적혀 있을 때 쓰던 방법(마지막 자리를 오차로 삼기)이 실제 오차를 **100 배 이상 작게** 잡았다. 원인은 오차가 숫자 하나로만 적혀서, "반복하면 줄어드는 오차" 와 "반복해도 안 줄어드는 오차" 를 구분할 수 없었기 때문이다. 그래서 오차를 **성분별로** 적는 칸(불확도 예산)을 만들고, 성분마다 그 구분을 **반드시** 적게 했다. 같은 자리에 원문의 SEM · n 을 적는 칸도 더해서, 원문 숫자끼리 앞뒤가 안 맞으면(예: SEM 이 SD/√n 과 다름) 기계가 잡게 했다. 따로 한 일로, 매달 도는 예약 작업이 결과를 저장하지 못하고도 "성공" 으로 끝난 사고를 기록하고, 다시는 조용히 실패하지 않게 지시문을 고쳤다.

| 무엇을 봤나 | 무슨 문제였나 | 그게 뭘 뜻하나 | 그래서 |
|---|---|---|---|

| 방식 | sd (상대) | 반복 3 회 평균의 오차 | 반복 100 회 평균의 오차 |
|---|---|---|---|
| 옛 방식 — 해상도 (마지막 자리 0.001) | 0.094 % | 0.094 % (안 나눔) | 0.094 % |
| 옛 방식 — sd 통째로 ÷ √n (성분 구분 없이 11 % 라 했을 때) | 11.0 % | 6.3 % | **1.1 %** ← 과신 |
| **새 방식 — 예산** (반복 3 % random · 교정 1.5 % sys · 원액 3 % sys · 효소 농도 10 % sys) | √(0.03² + 0.015² + 0.03² + 0.10²) = **11.0 %** | √(0.03²/3 + 0.015² + 0.03² + 0.10²) = **10.7 %** | √(0.03²/100 + …) = **10.5 %** ← 바닥 |

| 이 표가 뜻하는 것 | 그래서 |
|---|---|
| 옛 해상도 방식은 실제보다 약 **117 배** 정밀하다고 봄 | 이번 사건의 크기 |
| 옛 ÷√n 방식은 반복을 늘리면 1 % 까지 줄어든다고 봄 | 원액·효소 농도 오차를 반복으로 지울 수 있다고 착각 |
| 새 방식은 반복을 아무리 늘려도 10.5 % 아래로 안 내려감 | **정밀도를 올리려면 반복이 아니라 효소 농도 측정을 고쳐야 한다**는 것이 숫자로 보임 — 실험 설계에 바로 쓰이는 정보 |

내부 일관성 예:

| 원문 | 기계가 하는 계산 | 결과 | 의미 |
|---|---|---|---|
| SD 60, n 3, SEM 34.6 | 60/√3 = 34.64 → 적힌 자리 안에서 같음 | 통과 | |
| SD 60, n 3, SEM 60 | 34.64 ≠ 60 | 경고 | SD 를 SEM 칸에 또 적었거나 n 이 다름 |
| SD 60, SEM 90 | n > 1 이면 SEM ≤ SD 여야 함 | 경고 — 뒤바뀜 | 논문에서 흔한 실수 |
| 정수 28 개의 평균 5.19 | 합 145 → 5.18, 146 → 5.21 — 5.19 가 나올 정수 합이 없음 | 경고 — GRIM | 평균이나 n 중 하나가 잘못 적힘 |

## 4. 그래서 이것이 의미하는 것

| 수준 | 의미 |
|---|---|
| 데이터 한 건 | "이 값은 ± 얼마" 가 아니라 "**왜** ± 얼마인지, 그중 무엇이 반복으로 줄어드는지" 를 담을 수 있게 됨 |
| 판정 | 시뮬레이션과 관찰이 "맞다/틀리다" 를 볼 때, 관찰 쪽 오차를 과장하지도 과소평가하지도 않음 — 특히 반복 많은 관찰을 과신하지 않음 |
| 등급 | 출처 없는 추정 성분이 섞이면 등급이 자동으로 내려감 — 사람·AI 가 "대충" 넣은 숫자가 근거 행세를 못 함 |
| 실험실 기준 (DEC-0061) | 기록표로 받은 원자료 → 성분을 **A 형(측정)** 으로 직접 계산 → 실험실 고유 기준값 ± 정직한 불확도. GMP 의 측정 불확도 · 시스템 적합성 개념과 같은 방향 |
| 원문 품질 | 논문 숫자를 옮길 때 원문 자체의 실수(SD/SEM 혼동 등)를 들이기 전에 잡음 — 쓰레기가 들어오는 문을 좁힘 |
| 하위 호환 | 옛 관찰 28 건 · 판정 · 등급 그대로 — 새 칸은 쓰는 관찰에만 효과 |

## 5. 예약 작업 (PLAN-077) — 무엇이 있었고 무엇을 바꿨나

| 무엇 | 내용 | 의미 | 그래서 |
|---|---|---|---|
| 11/3 실행 | 상태 SUCCEEDED · 실제로는 push 403 · 추세 커밋이 컨테이너와 함께 사라짐 | 겉으로 "성공", 실제로는 결과 0 — **조용한 실패** | 아무도 몰랐음 |
| 원인 | 예약 작업에 저장소가 붙어 있지 않음 (11/1 에 이미 남은 일로 적혀 있었음) | 기계 쪽 결함이 아니라 설정 누락 | 저장소 연결은 **사용자만** 할 수 있음 (claude.ai 예약 작업 설정) |
| 고친 것 ① 시작 전 확인 | `git push --dry-run` 으로 저장할 수 있는지 먼저 봄 → 안 되면 **아무것도 하지 않고** 첫 줄 "실패" | 일을 다 하고 나서 버려지는 낭비를 없앰 | 푸시 알림이 켜져 있어 사용자 폰에 "실패" 가 뜸 |
| 고친 것 ② 끝에 확인 | 원격 브랜치 해시 = 로컬 해시인지 확인 → 다르면 첫 줄 "실패" | "push 했다" 는 말이 아니라 **원격에 실제로 있는지**로 판정 | 이번 세션의 push 도 같은 방식으로 확인함 |
| 기록 | 플랜 PLAN-077 결과 · 결정 DEC-0062 | 다음 사람이 이유를 찾을 수 있음 | |
| 막지 못한 것 | 저장소 연결 자체 | 지시문은 실패를 **드러낼** 뿐, 연결을 만들지는 못함 | 연결 전까지 매달 "실패" 가 정직하게 뜸 |

## 6. 하지 않은 것 · 남은 것

| 무엇 | 왜 안 했나 | 언제 |
|---|---|---|
| 자유도(dof) · 확장 불확도 k | 쓰는 곳이 아직 없음 — 빈 장치를 미리 짓지 않음(RULE-0462) | 신뢰구간을 보고할 때 |
| 성분끼리 상관 | 지금은 "서로 무관" 가정으로 제곱합 | 상관을 아는 자료가 생길 때 |
| `shared` 로 이중 계산 막기 | 적기만 하고 아직 안 씀 | 여러 출처 합의(ASY-16) |
| 추적성 사슬 판정 (어디서 끊겼나 → 등급) | 기준물질 관찰이 아직 없음 | ASY-08 남은 일 |
| lognormal · poisson 예산 | 단위가 달라 바로 못 더함 | 필요해질 때 |
| 실제 관찰에 예산 채우기 | 정보 작성(author) 모드의 일 | 측정법 등록(ASY-01 · 03) 뒤 |
| 실험실 검증 칸 (반복성 · 중간 정밀도 · 검출 한계) | 기록표 자료가 와야 함 | ASY-09 |
