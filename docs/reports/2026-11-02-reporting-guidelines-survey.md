## 4. 주장 장부 — 설계 초안 (결정 2)

논문의 주장 하나가 어떤 증거 위에 서는지를 추가 전용 장부로 남긴다. 기록부 줄(`data/runs.jsonl` 안, 계산 기록부 설계 §2)에 이어 붙는다.

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| 줄의 칸(안) | `claim_id` · `text`(주장 문장) · `kind`(기전 예측 / 관찰 일치 / 한계 서술 / 방법 서술) · `evidence_runs`(기록부 번호와 사슬 root) · `evidence_obs`(관찰·DOI·PMID) · `attestation`(도장 번호) · `prereg`(사전 등록 번호, 있으면) · `assumption_load`(가상 상수 수 / 실측 상수 수) · `limits`(관련 등록 한계 번호) · `paper_ref`(원고 절·그림·표) · 상태(작성중 / 사람 승인 / 철회) · 행위자(§5) | 한 줄이 "문장 → 실행 → 입력·코드 → 관찰" 사슬의 끈이 된다 | 계산 기록부 §2, `protocol.js` |
| 올릴 수 있는 조건(안) | 근거 실행이 정식 실행(기록부)이고, 사법부 판정이 통과이며, `assumption_load` 가 계산돼 있어야 한다. 규약 없는 실행은 `kind` 가 "관찰 일치" 가 될 수 없다(탐색 실행은 검증 결론을 못 낸다는 기존 규칙과 같다) | 근거 없는 주장·확증처럼 보이는 탐색 결과를 장부가 거부한다 | `protocol.js` 머리 |
| 가상 의존 표시 | `assumption_load` 가 가상 상수를 쓰면 주장 문장 앞에 "가정 의존" 표지를 자동으로 붙인다. 이 등급에서는 "재현했다" 같은 결론 단어를 제한한다(단어 목록은 사전에서 조회, 코드에 문구를 두지 않는다) | 입문 보고서 §5 의 43/44 문제를 논문 단계에서 막는다 | `RULE-0215` |
| 철회 전파 | 근거 관찰이 철회되면 이를 쓴 주장이 자동으로 "검토 필요"가 된다 | 기존 `retractionImpact` 와 같은 방향 | `judicial/` |
| 논문 묶음 | 학술지 제출용으로 장부의 승인된 주장 + 근거 실행 + 보고서 + 코드·WASM 해시 + 데이터베이스 해시를 한 디렉터리로 내보내고 묶음 해시를 인용 | 형식은 학술지에 맞춘다. 교환 형식(SED-ML 등)은 이번에 못 열어서 후보로만 둔다 | §1 미열람 |
| 쓰기 | 장부 쓰기는 서기(입법)만 한다. 장부 줄은 사람의 승인이 있어야 "승인" 상태가 된다 | 입법·사법 코드를 건드리므로 사용자 요청이 있을 때만 구현한다(RULE-0197) | `CLAUDE.md` |

## 5. 사람과 AI 의 행위 분리 — 설계 초안 (결정 3)

학술 규범의 공통 요지(§2.3–2.4): AI 는 저자가 될 수 없고, 사람이 책임지며, 사용 방법을 방법 절에 공개한다. 이를 기록에서 구조로 보장한다.

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| 행위자 칸 | 모든 기록 줄(영수증, 계산 기록부, 주장 장부, 결정, 전환 기록)에 `actor` = `{ kind: human / ai / tool, id }` 를 둔다. `human` 은 사람 이름이나 계정 역할, `ai` 는 AI 도구가 제공하는 식별자와 세션 번호, `tool` 은 엔진·검사기 같은 프로그램 | "누가 했나"가 모든 줄에서 구조로 읽힌다. **이 저장소에 쓰는 문서에는 모델 이름을 적지 않는다**(세션 기록의 식별자를 가리키기만 한다) | 시스템 지침의 저장소 기록 제한 |
| 결정과 실행의 분리 | 결정(무엇을 하기로 했나)은 사람이 하고, 실행(그대로 해 옴)은 AI 나 도구가 한다. 결정 기록(DEC)에는 이미 `by: user` 와 `by_src: 세션 답 … (원문 그대로)` 가 있다 | 이 방식을 계속하고, 사람의 원문 요지를 근거로 남기는 규칙을 주장 장부에도 확장한다 | `rebuild/state/plans.jsonl` |
| 사람 승인 | AI 가 쓴 초안(보고서, 주장 문장, 해석)은 사람이 검토해 승인해야 장부 상태가 "승인"이 된다. 승인 줄의 `actor` 는 반드시 `human` | ICMJE 의 "사람이 검토·수정하고 책임진다"에 대응. AI 가 스스로 승인할 수 없다 | §2.3 |
| 구분 불가 행위의 표시 | 사람이 AI 의 제안을 그대로 수락한 것과 사람이 직접 쓴 것을 구분한다. 한 줄에 `origin` = `human_written` / `ai_drafted_human_approved` / `tool_generated` 를 둔다 | 방법 절의 "AI 가 무엇을 했나"를 생성할 근거 | §2.3 |
| 공개문 자동 생성 | 장부와 영수증에서 "AI 도구가 한 일(코드 작성, 분석 실행, 초안 작성) / 사람이 결정·승인한 일" 표를 생성해 방법 절·커버 레터의 재료로 쓴다. 최종 문구는 저자가 쓰고 학술지 정책에 맞춘다 | 학술지별 정책은 미확인이므로 틀만 만들고 문구는 제출처에 맞춘다 | §2.3 |
| 영수증의 역할 확장 | 영수증은 도구 호출만 기록하고 읽기·대화는 기록하지 않는다(앞 논의). 논문 공개에는 "AI 가 어떤 작업을 했나" 수준이면 충분한지, 그 이상(대화 기록 보관)이 필요한지는 제출처 정책에 달렸다 | 지금은 영수증 확장을 제안하지 않는다. 필요가 확인되면 별도 안건 | 입문 보고서의 영수증 논의 |
| 사람 쪽 기록 | 사람의 결정은 대화에서 나온다. 결정 기록에 원문 요지를 남기는 습관이 이 구분의 증거가 된다 | 계속 지킨다 | `plans.jsonl` |
| 한계 | `actor` 는 기록 시 입력이므로 거짓으로 적히면 막을 수 없다. 사슬이 사후 수정은 막지만 처음부터 틀린 입력은 못 막는다 | 영수증이 도구 호출 사실을 문지기가 직접 남긴다는 점(자기보고가 아님)을 `ai`/`tool` 구분의 근거로 쓰고, `human` 승인은 사람이 직접 하는 동작(예: 승인 명령)으로 남긴다 | `gate.mjs` |
