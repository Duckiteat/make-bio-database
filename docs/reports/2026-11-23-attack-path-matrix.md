# 도장 등록부 공격 경로 매트릭스 — 1 단계: 보호 목록 · 검사 코드의 실제 강제 경계 (PLAN-106 · DEC-0085)

> develop 세션의 **자기 점검** 이다(고친 쪽이 조사함). 독립성은 이 매트릭스를 받아 각 줄을 다시 실행하는 별도 세션의 재검토가 맡는다.
> 실행은 모두 저장소 밖 임시 git 저장소에서만 했다(문지기 훅 · CI 구역 점검을 그 저장소에 대고 실행). 이 저장소 · data · attestations 는 바꾸지 않았다.
> **실행** = 그 결과를 실제로 봄 · **분석** = 코드를 읽어 추정(실행하지 않음) · **조회** = GitHub 설정을 읽음.

## 0. 정의 (사용자 조건 2026-11-23)

| 항목 | 정의 | 판정에 쓰는 법 | 비고 |
|---|---|---|---|
| 보안 경계 | 사람이 병합하지 않은 위조 도장이 유효로 셈해지지 않는다 | 위조가 validate · finish 를 지나 **CI 도** 지나면 "뚫림" | 사람 병합에서만 막히면 "사람이 막음" 으로 따로 표시 |
| 범위 | 도장 등록부(attestations/registry.json)의 세 종류 — 승인(accept) · 신원(verified) · 추세(trend) — 와 그 검사 장치 | 감독 장부 · 전환 기록은 인접 경계(같은 문지기 함수를 씀) | |
| 두 속성 | **내용의 정합성**(digest · 축 · 관계 조건 · 증거 sha256 — 계산으로 확인 가능) / **발급 권한의 진위**(누가 냈나 — `by` 칸) | 따로 판정 | `by` 는 쓰는 쪽이 적는 이름표다 — 저장소 안 어디에도 발급자를 암호학으로 증명하는 장치가 없다. 진위는 "누가 main 에 바이트를 넣을 수 있나" 로만 닻을 내릴 수 있다 |
| 종료 조건 | 범위 안 위조 시나리오의 실제 우회 성공 0 · 검사 자체의 무력화도 독립적으로 차단됨 | 실행 결과로만 | |
