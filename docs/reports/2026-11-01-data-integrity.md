# 자료 무결성 — 제안 검토와 종합 (2026-11-01)

> 사용자가 가져온 「데이터 무결성 및 출처 검증 아키텍처 사양서」와, 그 밖의 방법을 함께 검토해 뺄 것은 빼고 묶은 보고서.
> 지금 저장소에 있는 것과 대조해 판단했다. 계획에 들어간 항목은 `docs/plan/ORDER.md` · `node rebuild/read.mjs ASY-11` 처럼 읽는다.
> 칸: 범위 · 이유 · 영향 · 확인.

## 1. 목적

- **값 하나를 믿을 근거를 기계가 보이게 한다.** 그 값이 원문 어디에서 왔고, 누가 옮겼고, 옮기다 바뀌지 않았고, 원문 안에서도 앞뒤가 맞고, 다른 독립 측정과도 맞는지를 확인할 수 있게.
- **엔진을 믿을 근거도 같은 방식으로.** 정답이 알려진 모형과 맞는지, 단위나 척도를 바꿔도 결과가 같은지 확인한다.
- 최종 목표(DEC-0043)는 GMP 자료를 담고 판정할 수 있는 그릇이다. 문헌값은 그 기준에 어디까지 닿는지 등급으로 정직하게 보인다. 규제 인증은 범위 밖이다.
- 선택 기준(DEC-0045)은 확률 적분층의 시드 표류를 막는 것, 그리고 화학 잡음과 측정 잡음을 섞지 않는 것이다.

## 2. 투명성 원칙 — 이 보고서의 판단이 지키는 것

| 원칙 | 무엇 |
|---|---|
| 원값은 바꾸지 않는다 | 잰 값과 원문 숫자는 그대로 둔다. 환산·보정은 파생층에서 하고, 가정과 불확도를 함께 적는다 |
| 못 하면 못 한다고 적는다 | 검사할 수 없는 경우(예: 화학식이 없는 묶음)는 통과로 치지 않고 "검사 불가"로 드러낸다 |
| 증명이 실제로 증명하는 것만 주장한다 | 서명·해시·도장이 "누가"나 "언제"를 증명하지 못하면, 증명한다고 쓰지 않는다 |
| 근거는 계산하고, 저장하지 않는다 | 등급·합의값은 기록에서 다시 계산한다. 점수를 데이터에 박지 않는다 |
| 결과는 결함이 아니다 | 고갈·정지·0 도달은 보고할 결과다(RULE-0039). 멈추는 것은 NaN·Inf 같은 수치 결함뿐이다 |

## 6. 이것으로 얻게 될 것

- **값마다 걸어온 길이 끊김 없이 보인다**: 원문 파일(sha256) → 인용문 → 원문 숫자 → 값(정확한 환산) → 분석 코드(commit) → 들인 사건(사슬). 어느 고리가 비면 그 빈 곳이 드러난다.
- **사람 실수의 큰 부분이 입력 순간에 걸린다**: 잘못 옮김(이중 입력), 잘못 고름(출처 고정), SD↔SEM 혼동(내부 일관성), 자리수 위조나 잘림(RULE-0525).
- **신뢰도가 계산된다**: 독립 근거가 몇 개이고 서로 얼마나 맞는지(합의), 검증 근거가 어디까지 있는지(ASY-09), GMP 칸이 얼마나 찼는지(ASY-10).
- **엔진을 믿을 근거가 생긴다**: 정답 모음과 척도 불변 시험. 확률 적분층으로 넘어갈 때 시드 표류와 엔진 오류를 가를 수 있다.
- **과거가 몰래 바뀌지 않는다**: 사슬 + 꼬리 대조 + 외부 증인.
- **하지 않는 것도 분명하다**: 규제 인증, 사람 서명 증명, 데이터 단계의 상태 정규화는 하지 않는다고 적어 둔다.
