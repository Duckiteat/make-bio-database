# 결함이 왜 이렇게 많은가 — 근본 원인 (2026-10-25)

> 이번 주 평가·분석에서 나온 결함(치명 1 · 중대 8 · 숨은 구멍 3)이 **어디서 왔는지**를 git 기록·`CHANGES.md` 로 추적했다. 칸: 범위 · 이유 · 영향 · 확인.

## 0. 한 줄

**구조가 데이터보다 훨씬 빨리 자랐고, 결함을 드러낼 두 장치(실측 데이터 · 바깥 기준의 시험)가 둘 다 약했다.** 그래서 결함이 생기는 속도는 빨랐고 드러나는 속도는 느렸다. 대부분은 지금 결론을 틀리게 하지 않는 **잠복 결함**이다 — 데이터·규모·동시 작업이 들어올 때 터진다.

## 2. 근본 원인 여섯

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| **① 명세 주도로 층을 쌓음 — 통합 경로 없이** | 10-08 에 공간 층(DEVS·FV·FNO 대리 모델·동적 관문)을 "명세" 대로 만들었는데, db 규칙에서 공간 영역을 만드는 길은 만들지 않았다 | 1,110 줄이 지금까지 생물 결론에 한 번도 쓰이지 않음(분석 D6). 쓰이지 않으니 결함도 드러날 일이 없음 | `CHANGES.md` 199–201 · `grep` |
| **② 대체하지 않고 공존 + 한계로 등록** | 10-08 `simulateRate`(v7) → 10-09 운명 엔진이 분할을 결합 Rodas3 로 바꿈. 그런데 `simulateRate` 는 옮기지 않고 "서로 기준 금지"(L000081, 10-09)를 한계로 남겼다 | 두 엔진이 같은 규칙을 다르게 풂(분석 R2). 한계 등록이 "고침" 대신 "기록" 의 출구가 됨 — 한계 119 개 | `CHANGES.md` 172–186 |
| **③ 규칙을 글로 먼저 쓰고, 집행은 한 입구에만** | "문턱은 올리기만" 은 10-10 에 글로 생겼고 집행은 10-25. "단일 작성자" 는 MCP 서버에만 있고 `dbtool` CLI 에는 없음 | 글을 읽으면 지켜지는 줄 앎. 실제로는 다른 입구로 우회 가능 | `CHANGES.md` 13·161 행 · `writerLock` |
| **④ "멈추지 말고 돌아라 + 표시" 기본값** | 모르는 시작량은 10·1000 분자, 속도 상수 없으면 "즉시", MM 은 첫 기질만, 막 부피는 시나리오가 고름 — 실행은 늘 끝까지 돈다 | 근사가 숨어서 쌓임. "농도 공백" 같은 표시가 있으니 다룬 것처럼 느껴짐 | 분석 D1·D2·D4 |
| **⑤ 시험이 자기 설계를 지킴(래칫)** | 시험은 같은 세션이 쓰고 지금 동작을 고정한다. 예: `r.window === vocab.consensus.window_days`(설정 = 설정), `meets({grade})` 순번 비교, 합성 관찰을 "계산값" 으로 표시하고 실측처럼 판정 | 결함을 찾지 못하고 굳힘. 바깥 기준(해석해·문헌 값)과 대조하는 시험은 소수 | 이번 세션에 고친 시험 셋 |
| **⑥ 데이터가 적어 결함이 숨음** | 실측 속도 상수 4 개, 두 기질 효소의 실측 값 없음, 동시 작성자 없음, 정의항 수백 개 | MM 첫 기질 · 잃어버린 갱신 · 규모 벽이 지금은 결과에 안 보임. 데이터가 시험 역할을 못 함 | 평가 보고서 |
| (덧) 세션이 끊기며 이유가 흩어짐 | 규칙이 CLAUDE.md 17 KB · agent-rules 44 KB · SCHEMA 102 KB 세 곳에 다른 길이로 | 다음 세션이 같은 규칙을 다르게 읽음 — 글과 코드 어긋남이 실제로 생김 | 평가 보고서 §4 |

## 4. 다시 생기지 않게 — 만드는 방식의 규칙 제안

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| P1 통합 경로 없는 층 금지 | 원인 ① | 새 층은 db → 컴파일러 → 엔진 → 사법부 → 보고서까지 한 번 이어진 실제 실행이 있어야 병합 | 종단 시험 하나 필수 |
| P2 대체에는 제거 기한 | 원인 ② | 새 것이 옛 것을 대신하면 같은 변경 또는 정한 기한 안에 옛 것을 지움. "서로 기준 금지" 한계는 기한을 단다 | 한계에 기한 칸 |
| P3 규칙 = 집행 지점 목록 + 거부 시험 | 원인 ③ | 규칙을 글에 쓸 때 그 규칙을 집행하는 모든 입구와 거부 시험을 같은 커밋에 — 없으면 규칙이 아니라 "의도" 로 적음 | 규칙마다 시험 이름 |
| P4 기본값 사용 수를 결과의 1 급 지표로 | 원인 ④ | 실행 결과 머리에 "기본값 · 즉시 · 미지원 법칙 · 선택한 부피" 의 개수 | 보고서 머리 |
| P5 바깥 기준 시험 비율 | 원인 ⑤ | 시험을 "자기 일관성" 과 "바깥 기준(해석해·문헌·독립 구현)" 으로 갈라 세고, 바깥 기준 쪽을 늘림 | 시험 분류 |
| P6 데이터 : 구조 비율 목표 | 원인 ⑥ | 구조 변경 하나마다 데이터 패치 하나 이상(또는 주 단위 비율) — 데이터가 결함을 드러내는 시험이 되게 | `CHANGES.md` 집계 |
