# 아키텍처 분석 — 분야별 구조 · 분야 사이 흐름 · 상충과 병목 · 개선안 (2026-10-25)

> 틀: 사용자가 준 분석 틀(1 분야별 구조 → 2 인터페이스·데이터 흐름 → 3 상충·병목·되먹임 → 4 개선안). 칭찬을 빼고 실효성과 모순만 적는다.
> 근거는 코드 위치와 오늘 잰 값(`docs/reports/2026-10-25-compute-efficiency.md`)이다. 칸: 범위 · 이유(문제) · 영향 · 확인(근거).

## 1. 분야별 구조 평가

### D1 지식 저장

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| 상태 정의 | 값은 `values`(V…)에만, `obs`·`kinetics` 는 정규화가 붙이는 보기. 관찰은 고치지 않고 철회만 | 명확. 다만 정규화된 표현이 원본의 7.7 배이고 실행마다 다시 만듦 | `scaling-limits.md` |
| **은닉 상태 — 시나리오가 늘 이긴다 (중대)** | 부피·시작량·속도 상수의 우선순위가 시나리오 > 데이터 > 기본값. 데이터를 바꿔도 시나리오가 덮으면 궤적이 안 바뀐다 | 데이터 개선이 결과에 닿았는지 실행 결과만 보고는 모름. 가정 원장이 이를 드러내지만 새 등록에만 강제 — 인라인 숫자가 남은 시나리오 5(28–71 자리) | `dbtool assume` |
| **은닉 상태 — 기본값 (중대)** | 없는 시작량은 10 또는 1000 분자(`bulk`), 산물로만 나타나는 저장소는 시나리오가 없으면 바로 기본값(L000103) | "농도 공백" 으로 표시는 되지만 궤적에는 숫자로 들어감. 결론은 도달 여부만 말해야 함 | `core.js` 4.7·4.9 |
| **동시 쓰기 — 잃어버린 갱신 (중대)** | 봉인은 "쓸 db = 판결한 db" 만 보증하고 "디스크의 db = 병합이 읽은 db" 는 확인하지 않는다(비교 후 교체 없음). 단일 작성자 잠금은 MCP `clerk` 만 잡고 `dbtool` CLI 는 잡지 않는다. 잠금도 확인 → 쓰기가 원자적이지 않다 | 두 작성자가 같은 바탕에서 병합하면 뒤의 것이 앞의 것을 지운다. 델타 기록 재생에서 나중에야 어긋남이 드러남(막지 못하고 들킴) | `legislative/clerk.mjs` `commitMerge`·`writerLock` |
| 단일 파일 | V8 최대 문자열 537 MB → 정의항 약 20 만에서 읽기가 던짐 | 규모 상한이 구조로 정해짐 | `scaling-limits.md` §2 |

### D4 속도 기반 `simulateRate`

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| **명시 오일러 + 가용량 자르기 (중대)** | ξ = v·N_A·V·Δt 를 입력 가용량으로 자름 — 1 차 정확도, 오차 추정·단계 제어 없음. 안정성 비율은 기록만 하고 강제하지 않음 | Δt 에 따라 결과가 바뀜: LPS→NF-κB 끝 값 5219.20(Δt 0.01) ↔ 5219.54(Δt 0.001), 상대 6.5e-5. 수렴 확인은 사람 규칙("Δt 줄여 수렴할 때만 보고") | 오늘 측정 · CLAUDE.md |
| **단계 안 순차 갱신 (중대)** | 한 Δt 안에서 반응 단계를 IR 순서대로 바로 갱신하고(뒤 단계는 앞 단계가 바꾼 N 을 읽음), 그 뒤 공급 → 분해 순서 | 분할 오차 + 순서 의존. 저장소가 모자랄 때 앞 단계가 먼저 가져감 | `core.js:640–700` |
| **"즉시" 단계 (중대)** | 속도 상수 없는 단계는 한 Δt 에 가용량 전부를 바꿈 | 그 단계의 시간 척도가 Δt 가 됨 — 속도 단계와 섞이면 Δt 를 바꾸는 것이 생물 가정을 바꾸는 것 | 교과서 4.9 |
| 두 엔진의 같은 화학 | 같은 db 규칙을 D4(오일러·즉시)와 D5(Rodas3·즉시 단계는 꺼짐)가 다르게 푼다. 서로 기준 금지(L000081) | 같은 질문에 두 답이 가능하고, 어느 쪽이 맞는지 판정할 길이 설계상 없음 | L000081 |

## 2. 분야 사이 인터페이스 · 데이터 흐름

```
D9 수집 ─(수신함 파일·받기 기록)→ D7 대조 → D1 패치(관문·봉인·서기)
D1 db ─┬→ D2 컴파일러 ─(IR·irHash)→ D5 운명 엔진 ─(원자료)→ D8 조정자 → D7 판정·보고서
       ├→ D3 simulate (IR 없이 core 직접) ┐
       └→ D4 simulateRate (rate_ir) ─────┴→ D7 감사(auditRun)
시나리오·가정 원장 ─→ D2 (시나리오 > 데이터 > 기본값)
D6 공간 층 ── (입력 없음 — 본선과 끊김)
```

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| 단위 | 환산표는 `vocab.unitFactors` 하나, 값은 `physicalBounds` 안, 농도 = N/(N_A·V) | 단위 불일치는 구조적으로 막힘 | 교과서 4.9G |
| **분자 수의 형(型) 불일치 (경미)** | D4·D5 결정론은 분자 수를 실수로, 확률 층·P3 는 정수로. "1 분자 아래 = 고갈" 문턱은 실수 경로에서 0.4 분자 같은 상태를 허용 | 같은 사건(고갈)의 뜻이 경로마다 다름 | 교과서 4.9 ⑤ |
| **2D → 3D 환산 (중대)** | 막 단계의 반응 부피 = 참여자의 첫 3D 위치 또는 시나리오가 준 막 유효 부피 | 막 반응의 속도가 선택한 부피에 비례 — 생물 근거가 아니라 선택. 시나리오마다 다르면 같은 규칙이 다른 속도 | 교과서 4.9E |
| 시간 — D5 | 적분은 적응 단계, 기록·신호는 격자, 사건·결정은 다시 적분 + 근 찾기 | 사건 시각은 격자와 무관 — 시간 동기화 문제 없음 | 교과서 4.9E |
| **시간 — D4 (중대)** | 한 Δt 안 반응 → 공급 → 분해 순서, 반응끼리도 순서대로 | 순서 역전 소지가 구조에 있음(동시 갱신 아님) | `core.js:640–700` |
