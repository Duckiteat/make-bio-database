# 독자적 조정 체계 — 역할을 권한으로 바꾸기 (설계 제안, 2026-11-27)

> inspect 모드 · **설계 제안만, 사용자 결정 전.** 코드 · 장부 · 설정 · 데이터는 바꾸지 않았다. 구현은 develop 세션(PLAN-104 배정 자동화 · PLAN-116 거버넌스)이 사용자 결정 뒤 한다. 조정 코드는 지키는 자리(L6)라 사람 서명 커밋으로만 들어간다.

## 0. 한 줄

**심판이 선수가 아니게 한다.** 조정하는 쪽은 LLM 이 없는 결정론적 프로그램이고, 일꾼(Claude · 다른 모델 · 사람)에게는 저장소 쓰기 권한을 주지 않는다. 일꾼은 읽고 **제안만 제출**하며, 반영 · 기록 · 판정 순서는 조정 프로그램이 한다. 이것으로 "모드 자기 선언 · 훅 의존 · 일꾼이 만든 영수증" 은 풀린다. "판단의 독립" 은 이것만으로 풀리지 않으므로, 판정을 **다른 근거 경로**(기계 재계산 · 1차 원문 대조)와 **다른 판단자**(다른 모델 · 사람)의 사다리로 둔다.

## 2. 원칙 [제안]

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| ① 조정층에 LLM 없음 | 배정 · 권한 부여 · 반영 · 기록을 판단하는 쪽이 선수면 다시 역할놀이 | 조정은 표와 규칙으로만 — 같은 입력이면 같은 결정 | 결정론 시험 |
| ② 부탁 대신 권한 | 규칙을 읽고 지키길 바라지 않고, **할 수 없게** 한다 | 일꾼 손에 저장소 쓰기 · 셸 · git 이 없음 | 일꾼 도구 목록 |
| ③ 제안은 모두 후보 | 일꾼 출력 = 후보 (기존 RULE-0305 의 일반화) | 반영은 조정 프로그램이 판정을 통과시킨 뒤에만 | clerk 의 기존 원칙 |
| ④ 독립은 근거 경로로 | 세션이 다르다는 것은 독립의 근거가 아님 | 판정 사다리(§5)의 낮은 단은 모델이 아니라 기계 · 원문 | 주장 층 sha256 대조 |
| ⑤ 심판 코드는 사람이 지킴 | 조정 프로그램이 새 단일 실패점이 됨 | 조정 코드 = L6, 사람 서명 커밋만 (기존 trust-check) | RULE-0553 |
| ⑥ 과학 작업에 태워 만듦 | 11-20 이후 커밋 121 중 데이터 패치 0 — 체계만 자람 (DEC-0066 메타 편중) | 첫 바퀴는 실제 데이터 작업 하나 | §7 |

## 3. 구조 [제안]

```
           ┌──────────── 조정층 (결정론 프로그램 · L6) ─────────────┐
 작업 ──▶  배정기 ─▶ 권한 묶음 ─▶ [일꾼 실행] ─▶ 접수 ─▶ 판정 사다리 ─▶ 반영 ─▶ 기록
           (작업→모드)  (도구·역할)      │        (종류 판정) (기계→원문→다른 판단자→사람) (clerk) (해시 사슬)
                                         ▼
                           ┌──── 실행층 (갈아 끼움) ────┐
                           │ Claude · 다른 모델 · 사람   │
                           │ 읽기 MCP + 제안 제출만      │
                           └────────────────────────────┘
```

| 조각 | 할 일 | 이미 있는 씨앗 [사실] | 새로 필요한 것 |
|---|---|---|---|
| 배정기 | 작업 종류 → 모드 → 권한 묶음. 일꾼은 모드를 고르지 않음 | 감독 장부 `rebuild/supervise.mjs` · 작업 계약 칸(11-21 §5 `purpose · inputs · mode · done_when · verify · executor · state`) | 작업 종류 → 모드 표 |
| 권한 묶음 | 일꾼에게 줄 도구와 역할을 **띄우는 쪽이** 정함 | clerk 는 이미 띄울 때 정한 역할(`BIODB_ROLE`)로 쓰기를 가림 · 수집가는 `put_handoff` 만 | 모드별 묶음 표 (§4) |
| 일꾼 실행 | 일꾼은 따로 떨어진 작업 공간에서 읽기 MCP(query · run · fetch)와 제출 하나만 | MCP 서버 넷 · 도구 32 — 외부 패키지 없는 표준 입출력 JSON-RPC | 일꾼을 띄우는 어댑터 (Claude · 사람 먼저) |
| 접수 | 제출물의 **종류**를 판정(패치 · 판정 · 보고서 · 코드 차이)하고 작업의 모드와 맞는지 봄 | `workspace/handoff/` · `validate_patch` | 종류 판정 규칙 — "이름표 바꾸기" 를 내용으로 잡음 |
| 판정 사다리 | §5 | 사법부 · ci-zone · trust-check · 주장 층 · 관문 재계산 | 단 배정 표 |
| 반영 | 판정을 통과한 제출물만 clerk 로 씀 | clerk = 저장소를 바꾸는 유일한 문 · 단일 작성자 잠금 | 조정 프로그램만 integrator 역할로 clerk 를 띄움 |
| 기록 | 영수증을 조정 프로그램이 씀 — 일꾼이 아님 | 덧붙이기만 하는 장부 · 해시 사슬 (events · 사전 · 가정) | 조정 기록 사슬 하나 |

## 4. 모드별 권한 묶음 [제안]

| 모드 | 일꾼이 가진 것 | 제출할 수 있는 것 | 반영 길 |
|---|---|---|---|
| author | query · fetch (원문 받기) | 데이터 패치 · 넘김 파일 | 판정 사다리 → clerk `merge` |
| baseline | query · run (엔진 실행) | 실행 보고 · 사전 등록 | 실행은 조정 프로그램이 같은 입력으로 다시 돌려 대조 → 보고서 자리 |
| inspect | query · 받아 둔 원문 읽기 | 판정(통과 · 거부 · 재검토)과 이유 | 판정 기록 자리. 승인 도장은 §5 의 단에 따라 |
| develop | 저장소 읽기 · 시험 돌리기 (격리된 사본) | 코드 차이 | 시험 + CI + 사람 서명 PR (지키는 자리는 사람만) |
| field | 시제품 자리 읽기 · 시험 | 시제품 코드 차이 | develop 과 같음, 자리만 다름 |
| 모두 | 셸 · git · 직접 쓰기 **없음** | — | — |

## 5. 판정 사다리 — 독립을 근거로 [제안]

| 단 | 판단자 | 무엇을 | 어떤 제출물에 |
|---|---|---|---|
| 0 기계 | 관문 · 형식 · 번호 · 구역 | 모양이 맞나 | 모두 |
| 1 재계산 | 조정 프로그램이 같은 입력으로 다시 계산 | 숫자 · 실행 결과가 같나 (예: 다중 출처 값 `pooled`) | 계산된 값 · 실행 보고 |
| 2 원문 대조 | 받아 둔 1차 원문의 sha256 · 인용 글자 대조 | 인용이 원문에 그대로 있나 | 근거가 붙은 패치 · 주장 |
| 3 다른 판단자 | 작성과 **다른** 모델 또는 사람 | 해석이 맞나 (원문이 그 주장을 뒷받침하나) | 해석이 들어간 패치 · 결론급 판정 |
| 4 사람 | 사용자 | 방향 · 지키는 자리 · 결론 공개 | L6 코드 · 결론 도장 |

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| 낮은 단에서 끝나는 것을 늘림 | 0–2 단은 모델이 같아도 독립 (같은 실수를 할 수 없음) | 사람 손이 3–4 단에만 | 단별 통과 수 |
| 연극 계기판 | 단 3 의 거부 · 수정 권고 비율을 셈 | 0% 로 가면 연극의 신호 | 조정 기록에서 계산 |
| 같은 모델의 한계 | 다른 모델도 비슷한 자료로 배워 비슷하게 틀릴 수 있음 | 단 3 은 "다른 모델" 보다 "다른 근거" 를 먼저 | 단 1 · 2 우선 |
