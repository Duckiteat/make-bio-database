# 엔진 해부 2호 — 사법부의 시간 처리와 시험의 빈틈 (2026-11-01)

> 1호(`2026-11-01-engine-teardown.md`)가 "읽지 않음" 으로 남긴 분야 중 두 곳을 읽었다: 사법부가 엔진의 시각을 어떻게 다루는지, 그리고 그 한계를 시험이 지키는지.
> 칸: 범위 · 이유(문제) · 영향 · 확인(근거). 등급: **치명** 결론이 틀릴 수 있음 · **중대** 조건에 따라 틀리거나 막힘 · **경미** 비용·가독성.
> 번호 K1–K7 은 1호 §2 의 시계 항목이다. 이번에도 코드는 고치지 않았다. 아직 안 읽은 분야(`model.js` · Rust 본문 · 컴파일러 본문 · 입법·시나리오 입구)는 3호 이후.

## 2. 사법부의 시간 처리

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| **벽시계가 변형 비교 판정을 직접 가른다** (**중대**, K7 확정) | `compare` 는 `dMs = (b.ms − a.ms)/a.ms` 를 구하고 `cost = dUnits > 0 \|\| dMs > 0.05` 로 쓴다. `cost` 가 거짓이면 Optimization-Positive/Neutral, 참이면 Optimization-Negative/Trade-off 로 간다. `ms` 는 `process.hrtime` 으로 잰 실행 시간 | 같은 두 변형이라도 기계 부하에 따라 판정이 뒤집힌다. 5 % 는 측정 잡음보다 작을 수 있다(이번에 잡음 크기는 안 쟀다). 판정 입력이 재현되지 않으면 "판정 = 입력의 함수" 가 깨진다 | `judicial/compare.js:39–42` · `orchestrator.js:54` |
| **비교의 "같은 시각" 허용치 = 격자 dt** (**중대**, 신규) | `sameTime = \|x − y\| ≤ dt`(A 의 dt). 도달·결정 시각이 dt 이내로 다르면 결과가 같다고 본다 | 정밀 근 찾기(`event_tol` 0.01 s)로 구한 시각을 dt=60 s 눈금으로 뭉갠다. 즉 60 s 이내의 사건 시각 변화는 Behavior-Changing 이 아니다. 거꾸로 dt 가 다른 두 변형은 허용치가 비대칭(A 기준) | `compare.js:33–35` |
| **궤적 비교는 선형 보간 + 1e-9** (경미) | 격자가 다르면 B 를 A 의 시각에서 선형 보간해 L2 를 잰다 | 비선형 구간에서 보간 오차가 "궤적 차" 에 섞인다. 격자가 성긴 쪽의 오차가 비교 수치로 들어감 | `compare.js:30–32` |
| **기록점 사이 값은 선형 보간으로 관찰과 비교** (**중대**, 신규) | 관찰 연산자 `at()` 가 `condition.time_s` 의 값을 기록점 사이 선형 보간으로 구하고, `t ≥ 마지막 기록 시각` 이면 **끝 상태를 그냥 돌려준다** | ① 관찰 시각이 시뮬레이션 길이를 넘어도 오류 없이 끝 값이 비교됨(외삽이 아니라 정지된 값). ② 지수 변화 구간에서 격자 60 s 선형 보간은 곡률 오차를 낳음. ③ K3(마지막 기록 시각이 틀림)이면 보간 가중치도 틀림 | `obs_operator.js:38–44` |
| **`fraction` 은 격자 위 첫 도달 시각 비교** (경미) | `r <= t` 로 판정, `r` 은 근 찾기로 구한 시각 | 정밀 시각과 정수 관찰 시각을 비교하므로 경계에서 0/1 이 갈림 | `obs_operator.js:56–57` |
| **과정 보고서의 신호 확인이 같은 `t + dt` 관례를 쓴다** (**중대**, 신규) | `sigBad` 검사가 `decl(s, T[j] − dt)` 로 신호를 재계산한다. 즉 기록 시각을 `구간 시작 + dt` 로 본다는 엔진의 규약을 사법부가 그대로 가정 | K3(마지막 구간이 짧을 때 기록 시각이 `t+dt`) 가 사법부에서도 같은 값으로 재현되어 독립 검증이 되지 않는다. K4(신호 지연)도 `decl` 이 엔진과 같은 `e.t ≤ t + 1e-9` 라 같은 지연을 "선언대로" 로 통과시킨다 | `process_report.js:110–111` |
| **독립 질량 검증기에는 시각 항목이 없다** (**중대**, 1호 §4 확인) | 검증기 ①–⑤ 는 화학량·재생·부분 구조·규칙 밖·음수. 시각은 검증 대상이 아니다 | 시계 결함(K1–K4)을 어떤 감사도 잡지 못한다 | `verifier.js:1–12` |
| **과정 보고서의 창·병합이 dt 에 묶임** (경미) | 속도 창 `W = round(900/dt)`, 단계 병합 `2·dt` | dt 를 바꾸면 보고서 문구(어느 단계로 묶이는지)가 바뀐다. 결론은 안 바뀌나 재현 비교 시 노이즈 | `process_report.js:34·66` |
| **분화 정지 창이 6 h 고정** (경미) | `arrest_window = 6·3600` 기본 | 시나리오가 안 정하면 시간 척도가 다른 모델(텔로미어 등)에서 같은 창이 맞지 않음 | `fate_audit.js:79` |

## 3. 시험은 시계 결함을 건드리는가

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| **전 시나리오가 K3 를 우연히 피한다** (**중대**) | 24 개 시나리오 모두 `t_end` 가 `dt_slow` 의 정수배(60·21600 의 배수). 짧은 마지막 구간이 있는 시나리오가 없다 | K3 는 시험으로도, 실제 시나리오로도 한 번도 밟히지 않았다. 새 시나리오가 배수가 아니면 처음으로 드러난다 | **측정**: `examples/scenarios/*.json` 전수 |
| **전 시나리오가 K4 를 우연히 피한다** (**중대**) | 신호 시각이 모두 0·1800·3600·5400·7200 (60 의 배수). 격자 사이에 놓인 신호가 없다 | 신호 적용 지연은 실제로는 한 번도 안 나타났다. 1호의 "100 s → 120 s" 는 코드로만 확인된 가상 사례 | **측정**, 1호 §2 K4 |
| **MHC ⑤ 시험은 격자 의존이 없음을 "증명" 한 것처럼 읽히지만 범위가 좁다** (**중대**) | `dt_slow` 를 300·120·60·30 s 로 바꿔 도달·결정 시각 퍼짐이 0.01 s 미만임을 본다. 쓰는 시나리오(`maturation-lps`)의 신호는 0·1800 s 로 네 격자 모두의 배수 | 신호가 격자에 안 맞는 경우를 통과시킨 시험이 아니다. "격자에 묶이지 않음" 이라는 제목이 일반 주장처럼 읽히는 점이 위험 | `tests/mhc.test.mjs:121–126`, **측정** |
| **텔로미어 시험의 Δt 무관성은 신호 없는 산술 계에서** (경미) | 되먹임을 끈 선형 감쇠에서 12 h/6 h/3 h 를 비교, 오차 1e-9 | 가장 강한 시험이지만 계가 선형이라 적응형 걸음의 경로 의존은 안 건드림 | `tests/telomere.test.mjs:54–60` |
| **속도 엔진 Δt 시험은 "너무 큼" 경고 유무만** (**중대**) | 소진 시험 3 은 Δt 0.1 에 안정성 감사가 뜨는지, 0.005 에는 안 뜨는지를 본다. 수렴(Δt 를 줄여 끝 값이 변하지 않음)은 검증하지 않는다 | LPS 끝 값의 Δt 의존(상대 6.5e-5)을 막는 시험이 없다. "Δt 를 줄여 수렴할 때만 보고" 는 사람 규칙으로만 있다 | `tests/rules.test.mjs:714–717`, 1호 E2 |
| **JS 대 Rust 는 `rtol` 안에서만 비교** (경미) | MHC ⑥ 은 궤적 상대차 ≤ `rtol` | 의도된 보장이나, 확률 실행의 JS 대 Rust 경로 분기는 ⑧ 이 "출생–사멸은 비트 동일" 만 본다. 운명 프로그램은 분포 비교뿐 | `tests/mhc.test.mjs:128–132`, `tests/rust_engine.test.mjs:134` |
| **시계 전용 시험이 없다** (**중대**) | `t_end` 비배수·신호 격자 사이·`dt` 비정확 값·`toFixed` 경계를 다루는 시험이 `tests/` 에 없다 | 시계를 고치려면 먼저 현재 동작을 고정하는 시험(PLAN-088 의 안전망)이 필요 | `tests/` 전수 grep |
| **수치 래칫이 시험 개수 위주** (경미) | `FLOOR.json`: 거부 말뭉치 25 · 판정 검사 자리 426 · 시험 369 | 시험이 "많다" 는 신호이지 "시간을 지킨다" 는 신호가 아님 | `tests/fixtures/FLOOR.json` |
| **벤치(`bench_engine`)는 벽시계 측정이고 판정과 분리** (경미) | RULE-0030 에 따라 엔진 이득 보고용 | `compare` 의 `ms` 와 달리 판정에 안 쓰임. 다만 둘이 같은 `hrtime` 방식이라 혼동 소지 | `tests/bench_engine.js:1–25` |

## 4. 1호 등급표에 반영할 변경

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| K7 (벽시계) | "판정 사용처 미확인" → **확인**: 변형 비교 판정의 비용 항을 직접 가른다 | 중대 유지, 근거 확정 | §2 |

| 사법부의 독립성 | 질량은 독립 재계산(강함), 시각은 엔진과 같은 관례를 공유(약함) | "엔진 ↔ 사법부" 분리가 질량에는 성립하고 시간에는 성립하지 않음 | §2 |
