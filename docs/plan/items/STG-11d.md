# STG-11d — 파일 탐침

> 생성물 — 원본 `rebuild/state/plans.jsonl` · `rebuild/state/plan-log.jsonl` 에서 (`node rebuild/status.mjs --write`). 손으로 고치지 않는다 — 바꾸려면 `node rebuild/plan.mjs apply`. 계획: [재건 계획 (rebuilding project) — 글이 아니라 구조가 말하게](../rebuild.md) · [순서](../ORDER.md)

- **계획 · 부**: rebuild 11d · 7. 단계
- **단계**: 파일 탐침
- **무엇**: node rebuild/probe.mjs <파일 · 함수 · RULE-… · ASY-… · 작업 이름> — 닿는 자리를 한 번에: 규칙 장부 where · 집행 장부 · 시험 추적 지도 · 계획 자리 · git 함께 바뀜 · 단위 장부 분류 · 반복 작업 처방을 엮음(손으로 적은 지도를 새로 만들지 않음). 읽기·찾기가 호출의 37 % (2026-11-01 영수증) — 절반으로 줄이는 것이 목표 (docs/reports/2026-11-01-work-automation.md §4) · 바뀐 자리 따라가기(docs/reports/2026-11-01-work-automation.md §8): 깨진 참조를 감지해 사전 검사에 알림 · 현재 상태를 가리키는 기계적 참조(저장 지도 · 문서 링크 · 계획 자리 · where 의 파일 경로)는 자동 수정(장부 사건으로) · 과거 기록(CHANGES · 이력 · 영수증 · 도장 · 봉인 · 데이터)에 쓰는 수정은 거부
- **끝나는 조건**: 이번 세션 작업 셋(RULE-0525 · 0526 · 무결성 보고서)에 탐침이 내놓는 자리 ⊇ 실제로 고친 파일 · 읽기만 · 파일을 옮기면 첫 등급 참조가 고쳐지고 깨진 참조 0 · 과거 기록을 고치려 하면 거부
- **상태**: ☐ 대기
