# DEC-0018 — 세션 규칙 — 한 세션 = 한 모드 (사용자 결정 2026-10-25)

> 생성물 — 원본 `rebuild/state/plans.jsonl` · `rebuild/state/plan-log.jsonl` 에서 (`node rebuild/status.mjs --write`). 손으로 고치지 않는다 — 바꾸려면 `node rebuild/plan.mjs apply`. 계획: [rebuild](../rebuild.md)

`2026-10-25` · 사용자 · 방법 · 처음 적힌 커밋 `82fc060` · 옛 문서의 §3

- 세션은 **한 모드로 시작해서 한 모드로 끝난다.** 세션 안에서 모드를 바꾸지 않는다. 그래서 기초시험 중에 엔진을 고치는 길이 구조적으로 없다(승인 절차가 따로 필요 없음).
- 다른 모드가 필요하면 그 세션은 **전환 기록**을 남기고 끝난다. 다음 세션이 그 기록을 받아 새 모드로 시작한다. 전환 기록이 지금의 `workspace/handoff/NEXT-*.md` 산문을 대신한다.

전환 기록 (형식 초안 — 4단계에서 확정):

```json
{ "from": "baseline", "to": "develop", "at": "YYYY-MM-DD", "why": "한 줄",
  "target": ["D000148", "O000027"], "files": ["경로"], "open": ["다음 세션이 답할 질문"], "units": ["U…"] }
```

- **결정 ② (2026-10-25) — 수집가의 commit·push**: (다) 자기 브랜치(`collector/*`)에만 허용 + 문지기 훅이 push 직전에 브랜치와 바뀐 파일(`workspace/handoff/` 만)을 확인. 이유: 한 세션 = 한 모드라서 수집가 세션의 핸드오프는 push 되지 않으면 다음 세션에 닿지 못하고 사라진다(컨테이너는 세션이 끝나면 회수). 지금 문서의 모순(`workspace/README` 허용 ↔ `START-HERE`·`collector.settings.json` 금지)은 7 단계에서 이 결정으로 하나로 맞춘다. 확인한 사실: main 은 브랜치 보호가 꺼져 있다(2026-10-25) — README 의 "브랜치 보호가 막는다" 는 지금 사실이 아니다. 보호는 사용자가 GitHub 에서 켠다.
