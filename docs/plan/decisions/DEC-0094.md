# DEC-0094 — CI 구역 점검 — 선언(영수증) 없는 커밋은 AI 로 봄, 예외는 GitHub 이 검증한 사람 계정 서명뿐

> 생성물 — 원본 `rebuild/state/plans.jsonl` · `rebuild/state/plan-log.jsonl` 에서 (`node rebuild/status.mjs --write`). 손으로 고치지 않는다 — 바꾸려면 `node rebuild/plan.mjs apply`. 계획: [build](../build.md)

`2026-11-24` · 사용자 (세션 답 2026-11-24 — 'AI 로 봄 + 사람 서명만 예외 (Recommended)') · 설계

배경: ci-zone 은 선언 없는 커밋을 사람의 커밋으로 보고 알리기만 했다(공격 재검토 N8 — 따옴표 · eval 속 커밋이 검사 없이 통과). 커밋 작성자 이메일은 저장소 기록에 보여 흉내 낼 수 있어 신원 증거가 아니다(조회: a71393d 의 작성자는 noreply 이메일로만 Duckiteat). 결정: 선언 없는 커밋은 '모드 없음' 으로 판정 — 바꾼 파일이 있으면 위반. 예외는 GitHub 이 검증한 서명(verification.verified)이고 커미터 계정이 사람 계정(Duckiteat, DEC-0090)인 커밋 — 그 커밋은 지금처럼 알리기만(도장 등록부 정책은 그대로 봄). 웹 흐름(web-flow) 서명은 API 로 작성자를 정할 수 있어 예외가 아니다. 서명 사실은 워크플로가 GitHub API 로 모아 ci-zone 에 넘긴다 — 사실이 없으면 아무도 사람이 아님(fail-closed). 사람 쪽 준비: GitHub Settings → Codespaces → GPG verification 켜기(이 저장소). 구현은 승인 묶음(ci-zone · 그 시험 · check.yml), 사람 승인 · 병합.
