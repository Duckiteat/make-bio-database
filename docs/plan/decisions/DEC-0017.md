# DEC-0017 — 두 독자 — 원본은 기계용, 사람은 읽기 모드로만 (사용자 결정 2026-10-25)

> 생성물 — 원본 `rebuild/state/plans.jsonl` · `rebuild/state/plan-log.jsonl` 에서 (`node rebuild/status.mjs --write`). 손으로 고치지 않는다 — 바꾸려면 `node rebuild/plan.mjs apply`. 계획: [rebuild](../rebuild.md)

`2026-10-25` · 사용자 · 설계 · 처음 적힌 커밋 `a1be74c` · 옛 문서의 §2′

- **원본은 컴퓨터·AI 친화적으로 만든다.** 사람은 원본을 읽지 않는다. 형식: 한 줄 한 기록(JSONL) · 영어 열쇠와 열거값 · 참조는 번호로만 · 기록마다 형식 스키마와 시험 · 정렬 결정론. 사람말은 원문 인용(`text`)과 이유(R2)에만 남는다.
- **사람은 읽기 모드(`inspect`)로만 읽는다.** 읽기 모드가 원본을 사람 글로 펼친다. 깊이 셋:

| 깊이 | 보여 주는 것 | 예 |
|---|---|---|
| L0 한 줄 | 무엇인가 | "속도 상수는 등급 parameter 이상이어야 시뮬레이션에 쓴다" |
| L1 연결 | 어떻게 이어지나 — 이 기록이 무엇에서 오고(출처·관찰·가정), 어디서 집행되고(코드 자리), 어떤 시험이 지키고, 무엇에 닿나(규칙·단계·경로·결론) | 관찰 O… → 값 V… → 규칙 kinetics → 단계 S… → 시뮬레이션 관문 → 과정 보고서 줄 |
| L2 상세 | 어떤 수식으로 이 모양을 만들었나 — 식, 변수마다 출처·단위·값, 유도 단계, 그 식을 계산하는 코드 자리, 그 식을 검증하는 시험, 실제 값을 넣은 계산 한 번 | v = kcat·[E]·[S]/(Km+[S]) — kcat 26.7 s⁻¹(O000002) · [E] … → 흐름 … |

- **읽기 모드는 조회하지 추론하지 않는다** (`dictionary-and-translation.md` §3 을 사람 읽기 전체로). L1 연결은 번호 그래프에서, L2 수식은 기록의 수식 칸(식 · 변수 → 번호 · 단위 · 코드 자리 · 검증 시험)에서 만든다. 수식 기록이 없으면 "수식 기록 없음" 이라고 보여 준다 — AI 가 그 자리에서 식을 지어내 설명하지 않는다. 그래서 수식도 원본 기록이 된다(6 단계). 씨앗: 컴파일러 테이프 명세(속도 법칙), `judicial/derivative.js`(법칙 재구성), `vocab.kineticLaws`, 과정 보고서 인과 추적.
- `rebuild/status/` 도 이 원칙을 따른다 — 지금의 .md 는 임시이고, 6 단계에서 기계용 원본(JSON) + 읽기 모드 렌더로 바꾼다.
