# DEC-0081 — 전환 기록에 선택 칸 sup(상위 작업 번호) — DEC-0065 ② '전환 형식 불변' 을 이 한 칸만큼 고침 · 감독 장부 넘김이 다른 상위 작업의 전환 기록을 가리키면 거부

> 생성물 — 원본 `rebuild/state/plans.jsonl` · `rebuild/state/plan-log.jsonl` 에서 (`node rebuild/status.mjs --write`). 손으로 고치지 않는다 — 바꾸려면 `node rebuild/plan.mjs apply`. 계획: [build](../build.md)

`2026-11-23` · 사용자 (세션 답 2026-11-23 'ㄱㄱㄱ 가' (선택지는 통합가 제안)) · 설계

사용자: "ㄱㄱㄱ 가" — (가) 선택 칸 추가. 문제(G5 E3, DEC-0079): 감독 장부의 넘김 사건이 가리키는 전환 기록(transition_seq)이 다른 상위 작업의 것이어도 잡지 못했다 — 전환 기록에 상위 작업 칸이 없음. 정함: ① 전환 기록 칸 일곱에 **선택** 칸 sup(SUP-네 자리) 하나 — 있어도 되고 없어도 됨, 새 기록부터, 옛 기록은 그대로(일괄 이관 없음) ② 감독 장부 검사: 넘김(또는 inputs.transitions)이 가리킨 전환 기록에 sup 가 있고 그것이 그 사건의 상위 작업과 다르면 거부(RULE-0545) — sup 가 없는 옛 기록은 판정하지 않고 승인 보고서의 절차 감사에 '연결 확인 못 함' 으로 드러냄 ③ DEC-0065 ② 의 나머지(전환 기록이 감독 장부를 가리키지 않음 · 연결 방향은 감독 → 전환)는 그대로 — sup 는 '이 전환이 어느 상위 작업의 일인지' 의 꼬리표일 뿐 감독 장부의 사건 번호를 가리키지 않는다. 모드표(L6)의 '전환 기록 { from, to, at, why, target, files, open }' 문장은 사람 몫이라 고치지 않음 — 선택 칸이라 그 문장과 어긋나지 않는다.
