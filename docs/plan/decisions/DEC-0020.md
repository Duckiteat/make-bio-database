# DEC-0020 — 번호 사전 — 모든 인덱스를 한 곳에서 (사용자 제안 2026-10-25)

> 생성물 — 원본 `rebuild/state/plans.jsonl` · `rebuild/state/plan-log.jsonl` 에서 (`node rebuild/status.mjs --write`). 손으로 고치지 않는다 — 바꾸려면 `node rebuild/plan.mjs apply`. 계획: [rebuild](../rebuild.md)

`2026-10-25` · 사용자 · 설계 · 처음 적힌 커밋 `de1df46` · 옛 문서의 §4′

번호 체계가 저장소 곳곳에 따로 산다 — 데이터(T·D·S·O·V·L), 가정(A), 장부(U), 하위 번호(`D…/site/키`·`D…/rule/키`), 묶음 키, 감사 코드(`AUDIT_*`), 과제(`TASK-…`), 예약 작업(`trig_…`), 외부 번호(UniProt `P…`·`Q…`, ChEBI …). 형식·발급자·불변 규칙은 각 코드와 글에 흩어져 있고, **번호가 아예 없는 것**도 많다: 규칙 · 결정("결정 ①") · 변경 기록 행 · 계획 항목(표의 순번뿐) · 시험(파일마다 ①부터 다시 — `①` 이 27 개) · 전환 기록.

두 층으로 나눈다:

| 층 | 무엇 | 저장 |
|---|---|---|
| **이름공간 표** (번호 사전 본체) | 번호 종류 하나 = 기록 하나: `{ ns, means, pattern(정규식), issuer(누가 번호를 매기나), store(정의되는 자리), immutable(재사용 금지·moved·revises), refers_to, render }` | 원본 — 기계용 JSONL, 손으로 더하되 형식 검사 |
| **참조 색인** | 번호 하나하나가 어디서 정의되고 어디서 가리켜지나 | **저장하지 않고 계산** (계산할 수 있는 것은 저장하지 않는다 — 교과서 P6). 읽기 모드 L1 연결의 바탕, 개수는 관리 파일에 |

규칙:
- **등록되지 않은 번호 모양은 실패.** 저장소에서 번호 모양 토큰을 뽑아 어느 이름공간에도 맞지 않으면 시험이 실패한다 — 새 번호 종류를 만들려면 표에 먼저 올린다.
- **새로 번호를 받는 것**: 규칙(5 단계) · 결정 · 변경 기록 행 · 계획 항목 · 시험 · 전환 기록. 시험은 파일 안 순번 대신 전역 번호.
- **겹침 판정**: 이름공간끼리 정규식이 겹치면 실패(예: 가정 `A` + 6자리와 UniProt `A0A…` 는 형식으로 갈린다는 것을 시험이 보인다).
- **말 사전과 다르다**: `data/dictionary.jsonl` 은 통제 토큰의 **뜻**(ko·en 라벨)이고, 번호 사전은 **신원**(무엇이 무엇을 가리키나)이다. 섞지 않되, 번호 사전의 `means`·`render` 는 말 사전의 열쇠를 가리켜 사본을 만들지 않는다.
