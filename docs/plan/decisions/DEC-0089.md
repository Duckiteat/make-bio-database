# DEC-0089 — git push 확인 창을 지금 없앰(가) · 사람 클릭에 기대지 않는 안전 구조(보안 핵심)를 먼저 빠르게

> 생성물 — 원본 `rebuild/state/plans.jsonl` · `rebuild/state/plan-log.jsonl` 에서 (`node rebuild/status.mjs --write`). 손으로 고치지 않는다 — 바꾸려면 `node rebuild/plan.mjs apply`. 계획: [build](../build.md)

`2026-11-23` · 사용자 (세션 답 2026-11-23 "그건 사람이 버튼을 누르지않아도 안전한 구조가 만들어지는게 아니니까. 그거도 중요하거든. 그래서 지금 가로 하되, 이거부터 빠르게 만들어버려야해" (선택지 가 · 나 · 다는 develop 세션 제안, 권고 가)) · 순서

배경: develop 세션(전환 기록 #19)에서 사용자와 이해 확인 — 승인 · 병합 · 설정만 사람 계정에 남기고 읽기 · 쓰기 · 커밋 · 작업 브랜치 push · PR 열기는 AI 가 계속 한다(자율성 유지). 사용자가 push 때마다 뜨는 확인 창(설정 ask, PERM-0012)을 없앨 수 있는지 물음. 결정 ① 가: 지금 git push 를 ask → allow — 작업 브랜치 push 는 묻지 않고, main 은 GitHub 보호(PR 필수 · 필수 검사)가, force push · main 직접 push · AI 의 PR 병합 · 자동 병합 켜기(N12)는 설정 deny 가 막는다. 승인 도구가 권한 넓히기를 묶음으로 받지 않으므로(RULE-0528) deny 더하기는 승인 묶음(workspace/DEC-0089-deny-bundle.patch), allow 옮기기는 사용자가 손으로 — 적용 순서 workspace/DEC-0089-README.md. 결정 ② 순서: 확인 창을 누르는 것은 안전 구조가 아니다 — 사람이 매번 누르지 않아도 안전한 구조(DEC-0088 Q2 보안 핵심: 신원 분리 · main 코드로만 판정 · 병합 커밋 판정 · 문지기 fail-closed · 자동 병합 끄기)를 거부권 · 스파링 · 중재와 제안서 13 장의 나머지 검토보다 먼저, 빠르게 만든다.
