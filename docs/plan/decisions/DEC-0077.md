사용자: "이후 PLAN-116 G2–G4로 진행한다." 범위(1 단계 보고서 docs/reports/2026-11-23-plan-116-phase1-governance-mapping.md §5): G2 Deny/Hold — 감독 장부 block 의 원인 태그 일곱(CAUSES)을 deny(필수 검증 실패 · 코드 결함 · 실행 실패: ENGINE_DEFECT · COMPILER_DEFECT · EXEC_FAILURE) · hold(근거 부족 · 해석 불확실 · 검증 불일치 · 원인 모름: FINDING · DATA_GAP · DOMAIN_CONFLICT · NUMERICAL) 두 묶음으로 나누는 표 하나(rebuild/supervise.mjs CAUSES 곁) — 사건 형식 · 칸은 그대로. G3 검수 독립성 — 제안서 §7.2 다섯 요소(역할 · 권한 · 실행 · 정보 접근 · 판단 근거)를 감독 장부 · 모드 표 · 영수증 · git 에서 계산(judicial/supervise_approval.js 순수 함수). 정보 접근 · 판단 근거는 영수증의 명령 글에서 추정한 것이라 '추정' 으로 표시하고, 다섯이 모두 서지 않으면 '제한적'. G4 승인 보고서 — 제안서 §8 의 12 칸을 결정적 읽기 명령(node rebuild/supervise.mjs report <SUP-…>)이 장부 · 영수증 · git · 전환 기록에서 만든다. Supervisor(AI)는 쓰지 않음(DEC-0065 ① 유지 — 1 단계 U3). 최종 권고 칸도 규칙으로 계산(승인 판정 · 막힘 종류 · 독립성) — AI 의 문장이 아님. 하지 않는 것: G1 위험 단계 이름(R0–R3) · G5 우회 대본 시험 · G6–G8 · 사건 형식 변경 · 새 승인 사건 · 문지기 코드. 기존 데이터 · 장부 줄은 바꾸지 않는다.
