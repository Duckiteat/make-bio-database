# DEC-0101 — PLAN-135 조건 ②(머리 커밋에 묶인 사람 승인)는 GitHub 규칙 세트에 맡긴다 — 독립 판정은 사람 서명 커밋 · 병합 커밋 속 변경 · 새 파일 구멍을 본다

> 생성물 — 원본 `rebuild/state/plans.jsonl` · `rebuild/state/plan-log.jsonl` 에서 (`node rebuild/status.mjs --write`). 손으로 고치지 않는다 — 바꾸려면 `node rebuild/plan.mjs apply`. 계획: [build](../build.md)

`2026-11-25` · 사용자 (세션 답 2026-11-25 — "조건 ② 를 어디서 지킬까요" 에 "GitHub 규칙 세트에 맡김 (Recommended)") · 설계

배경: 독립 판정은 pull_request_target(main 의 코드)으로만 도는데, 이 이벤트는 PR 이 열리거나 커밋이 올라올 때만 돌고 승인 리뷰 제출에는 돌지 않는다. 리뷰 이벤트(pull_request_review)는 PR 쪽 워크플로 파일로 돌아 PR 이 판정을 바꿀 수 있어 안전하지 않다(조건 ③ 위반). 결정: ② 는 규칙 세트(Require review from Code Owners · Dismiss stale approvals — 우회 목록을 비우면 아무도 못 피함)가 병합 전에, workflow approval(PLAN-117)이 병합 뒤 사실로 본다. 독립 판정은 ① 지키는 자리를 바꾼 커밋이 모두 사람 서명 ② 병합 커밋이 부모에 없던 내용을 넣지 않음 ③ L6 폴더 아래 새 파일(저장 지도 글롭 .github/** · .claude/hooks/**)도 지키는 자리 · 사실 없으면 사람 아님. 대안(승인 뒤 사람이 재실행 클릭)은 L6 PR 마다 클릭이 늘어 고르지 않음.
