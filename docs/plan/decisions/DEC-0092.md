# DEC-0092 — 전환 기록 번호를 일 묶음 단위로 — 같은 일은 같은 번호 + 글자(20a · 20b …), 사람이 완결을 찍으면 다음 번호

> 생성물 — 원본 `rebuild/state/plans.jsonl` · `rebuild/state/plan-log.jsonl` 에서 (`node rebuild/status.mjs --write`). 손으로 고치지 않는다 — 바꾸려면 `node rebuild/plan.mjs apply`. 계획: [build](../build.md)

`2026-11-24` · 사용자와 합의 (세션 답 2026-11-24 — 사용자 제안 '20a 20b ~ 20z 까지 두고, 완결나면 다른 숫자' · 통합가 추천 표(완결 = 사람 · z 뒤 aa · 새 번호는 사람 결정 · 지난 기록 그대로)에 "ㅇㅇ") · 설계

배경: 전환 기록 번호(seq)는 workspace/transitions.jsonl 의 줄 수 + 1(legislative/clerk.mjs appendTransition)이라 일의 맥락을 담지 못하고, 브랜치가 갈리면 같은 번호가 둘 생긴다 — main 의 #20(inspect → develop, PR #24)과 claude/attack-matrix-independent-review 의 #20(develop → inspect). 동시에 여러 일을 진행하면 섞인다. 결정: ① 한 묶음의 일은 같은 번호에 글자 — 20a(inspect → develop) → 20b(develop → inspect) → … · 일마다 번호가 따로라 여러 일이 함께 진행(20c · 21b). ② 완결은 사람이 정한다 — 마지막 기록에 close: true, 그 PR 을 사람이 승인. 완결된 번호에는 더 붙일 수 없다. ③ z 다음은 aa. ④ 새 번호는 사람 결정으로만 연다. 글자는 그 번호 안 다음 글자 — 두 브랜치가 같은 글자를 쓰면 병합 때 검사가 잡는다. ⑤ 지난 #1–#20(두 개 모두)은 그대로 — 새 방식은 다음 기록부터, 필요하면 대응표. 구현은 develop: 서기(legislative/clerk.mjs) 번호 매기기 · 검사(judicial/transition_audit.js — 보호 자리, 승인 묶음 + 사람 병합) · 시험(tests/transitions.test.mjs) · 문지기 시작 안내(최근 전환 기록 표시). 이 결정 전 기록(main #20)의 open 에는 없음 — develop 세션은 이 결정을 함께 읽을 것.
