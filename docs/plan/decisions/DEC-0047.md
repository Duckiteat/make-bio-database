# DEC-0047 — 반복 기록 일의 자동화와 파일 탐침 — 기록 규약은 그대로, 손일과 다시 돌리기만 줄인다

> 생성물 — 원본 `rebuild/state/plans.jsonl` · `rebuild/state/plan-log.jsonl` 에서 (`node rebuild/status.mjs --write`). 손으로 고치지 않는다 — 바꾸려면 `node rebuild/plan.mjs apply`. 계획: [rebuild](../rebuild.md)

`2026-11-01` · 사용자 (세션 답 2026-11-01 (원문 그대로)) · 방법

그러면 그 일들 자동화는 못하나? · 이거 보고서로 올려놓고 가자 효율성차이가 어느정도로 나게될지도 정리하고. 거기에 필요한 파일로 가는 탐침도 있으면 좋을거같다 생각하면 그것도 포함해서 만들어놔 (추정: 도구 호출 490 → 약 330, 실패한 전체 시험 8 → 약 2 — docs/reports/2026-11-01-work-automation.md)

## 뒤에 일어난 일

- `2026-11-01` 그러면 파일탐침을 통해서 변경된 루트나 지점들을 바꿔주는 시스템을 도입하는건 어떻게 생각해? · 오케이 정리하고 보고서 쓰자 — 세 등급(자동 · 제안 뒤 확인 · 절대 안 고침), STG-11d · 11a 를 넓힘 (docs/reports/2026-11-01-work-automation.md §8)
- `2026-11-01` 세션끊기는 순서에 넣어두고, 기록을 항목단위로 묶기는 기록만 해두자 (docs/reports/2026-11-01-work-automation.md §9)
- `2026-11-01` 이것도 적어두되, 이건 아직 시기적으로 올바르다는 생각이 안들어서. 이건 적어두고 단계로는 일단 두지말자 (docs/reports/2026-11-01-work-automation.md §10)
