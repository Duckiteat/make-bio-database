# DEC-0021 — 분류 방법 — 언어보다 구조가 말하게

> 생성물 — 원본 `rebuild/state/plans.jsonl` · `rebuild/state/plan-log.jsonl` 에서 (`node rebuild/status.mjs --write`). 손으로 고치지 않는다 — 바꾸려면 `node rebuild/plan.mjs apply`. 계획: [rebuild](../rebuild.md)

`2026-10-25` · 원문에 누가인지 없음 · 방법 · 처음 적힌 커밋 `82fc060` · 옛 문서의 §5

장부는 기계용이다(§2′) — 열쇠·열거값은 영어, 참조는 번호, 사람말은 `text`(원문)와 `note` 에만. **단위는 문장 하나**다(파일이 아님 — 한 문단에 두 모드가 섞인 경우가 많다). 단위마다 장부 `rebuild/ledger/*.jsonl` 에 한 줄:

```json
{ "id": "U0001", "src": "CLAUDE.md:12 (자라는 기록은 파일:* — 파일 전체 하나)", "text": "원문 그대로(긴 문장은 요지 + 원문 위치)",
  "mode": "author|baseline|develop|field|inspect|common", "kind": "rule|procedure|reason|value|history",
  "enforce": "machine|text|none|unchecked", "by": "heur (휴리스틱으로 매김 — 검토 전, 없으면 판단)", "same_as": ["U… — 이 단위가 다른 단위의 사본이면"], "where": "집행 자리(파일·함수·시험) — machine 일 때", "note": "" }
```

종류가 처리를 정한다:

| 종류 | 뜻 | 갈 곳 |
|---|---|---|
| `rule` 규칙 | 지켜야 하는 것 | 규칙 장부 — 집행 지점과 짝. `enforce: text` 면 기계로 올리기 · 보고서가 하게 · 지우기 셋 중 하나(build-plan 69) |
| `procedure` 절차 | 명령 순서·방법 | 모드 문서의 명령 순서(또는 명령 장부) |
| `reason` 이유 | 왜 그렇게 하나 | 규칙 번호에 붙은 이유 글 |
| `value` 현재 숫자 | 개수·크기·버전·분포 | 지운다 — 필요하면 생성 |
| `history` 역사 | 언제 무엇이 있었나·결과 일지 | 보관(읽기 경로 밖) |

`mode` 가 둘 이상에 걸치면 단위를 쪼갠다. 그래도 여러 모드가 쓰는 기준(등급·인정·종·한계)은 `common` 이거나, 한 모드에 두고 다른 모드는 번호로만 가리킨다 — 사본을 만들지 않는다.
