# 재건 계획 (rebuilding project) — 글이 아니라 구조가 말하게

> 생성물 — `node rebuild/status.mjs --write` 가 원본 `rebuild/state/plans.jsonl` · `rebuild/state/plan-log.jsonl` 에서 만든다. 손으로 고치지 않는다.
> 바꾸려면 `node rebuild/plan.mjs apply <ops.json>` (바꿀 때마다 왜를 적는다). 하나만 읽기: `node rebuild/read.mjs <PLAN-…|STG-…|DEC-…|DIR-…|ASY-…> [--depth 0|1|2]`.
> 이 문서의 차례: 목적 → 왜 → 결정(표) → 작업(표) → 종합 결과와 의의 → 나아갈 방향 → 열린 질문 → 근거 점검. 무엇을 언제 하나는 [순서](ORDER.md), 작업 하나는 items/, 결정 하나는 decisions/.

> 브랜치 `rebuilding-project` (2026-10-25 시작, main `4a84b40` 에서). 이 문서는 재건의 **목적·결정·방법·단계**를 적는다.
> 지금 숫자(파일 수·크기·분류 진행)는 이 문서에 쓰지 않는다 — `rebuild/status/` 가 자동으로 만든다(§6).

## 1. 목적 — 처음 목적과 그 뒤에 바뀐 목적

### DEC-0014 — 재건의 미션 — 모든 파일을 갈아엎되 검증은 끊기지 않게

`2026-10-25` · 원문에 누가인지 없음 · 목적 · 처음 적힌 커밋 `82fc060` · 옛 문서의 §0

**모든 파일을 갈아엎는다는 생각으로 한다.** 문서·코드·시험·데이터 배치 모두 "지금 있으니까 둔다" 는 이유로 남기지 않는다. 파일마다 어느 모드에 속하는지, 무엇을 위해 있는지 다시 정하고, 그 자리를 구조가 말하게 한다.

지키는 것 하나: **검증은 끊기지 않는다.** 옮기는 동안 관문·시험·도장이 하던 판정은 그대로 돌아야 한다. 새 자리가 확인되면 옛 자리는 같은 단계에서 지운다(대체에는 제거 기한 — 결함 원인 ②).
