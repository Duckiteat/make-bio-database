# 기질 축 — 값의 열쇠에 "무엇의 Km 인가"를 넣는다 (설계, 2026-11-03)

> 상태: 구현 대상 (사용자 요청 2026-11-03: 수집 시스템의 입력 형식을 먼저 완성). 형식 번호는 **v12 그대로** — 하위 호환 선택 칸이라 이관 스크립트가 없다.
> 근거: `docs/reports/2026-11-03-collection-dataset-structure-fit.md` §2.1 · §6 · `format-v12.md` §2 · `judicial/judicial.js validateValues` · `model.js kineticsOf` · `core.js:662` · `judicial/derivative.js:111`.
> 칸: 범위 · 이유 · 영향 · 확인.

## 0. 결정

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| 값(V)과 관찰(O)의 **선택 칸 `substrate`** (정의항 번호 `D…`) | 기질이 다른 `Km` 은 다른 양이다. 맥락(측정 환경)이 아니라 **무엇을 재는가**의 일부 | 값의 열쇠가 `대상 · 속성 · 기질 · 맥락` 이 된다 | §1 |
| 허용 속성은 **`Km` 만** (`vocab.substratedProperties`) | 지금 이 칸을 읽는 쪽이 `Km` 뿐이다. 소비자가 생기면 목록에 더한다 (RULE-0462) | 다른 속성에 쓰면 거부 | §2 |
| 기질은 그 규칙 단계의 **`minor` 가 아닌 입력**이어야 한다 | 단계 입력은 이미 `D번호\|위치` 로 기질을 구조화해 둔다 | 새 어휘 없이 "대상 존재" 검사 방식으로 | §2 |
| **기질 없는 값은 "첫 기질" 의 값으로 읽는다** | 엔진(`core.js:662`)과 사법부(`derivative.js:111`)가 둘 다 첫 `minor` 아닌 입력을 쓴다 | 기존 데이터 · 엔진 그대로 | §3 |
| 한 `(대상, 속성)` 에 기질 있는 값과 없는 값이 **섞이면 거부** | 섞이면 "첫 기질" 이 두 번 말해진다 | 이관은 한 규칙씩 완결 | §2 |
| 곡선(온도 · 농도)은 이번에 안 한다 | 사용자 결정: 입력 시스템과 데이터 개념이 선 뒤 | 맞춤 유도 방식(`fit`)도 그때 | 이 문서 §6 |

## 1. 문제 — 실데이터로 본 것

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| 열쇠에 기질이 없다 | 값의 열쇠는 `대상 · 속성 · 맥락(여섯 칸)`. 같은 규칙에 기질이 다른 `Km` 이 둘 들어오면 현재 값이 둘이라 RULE-0233 이 거부 | 2번째 기질의 Km 은 **들어올 길이 없다** | `judicial.js` 256행 |
| 실제로 한 건이 못 들어왔다 | `O000007`(CS Km 3.6 µM, UniProt O75390)의 `note`: "같은 출처의 아세틸-CoA Km 은 7.7 µM 이고, 기질이 둘인 속도식을 담을 칸이 없어 따로 적지 못했다". 이 관찰은 현재 어떤 값(V)도 가리키지 않는다 | 증거는 있는데 값 층에 없다 — 이 설계로 되살릴 수 있다 | `O000007` · 현재 값 목록 |
| 보기 투영이 소리 없이 덮어쓴다 | `kineticsOf` 가 `속성` 으로만 Map 을 만든다. 열쇠 검사를 풀면 뒤의 값이 앞의 값을 덮는다 | 투영 규칙을 정해야 한다 | `model.js kineticsOf` |
| 엔진은 첫 기질만 쓴다 | `core.js:662` `lawInsB[0]`, `derivative.js:111` `lawIns[0]` — 단계 입력 중 `minor` 가 아닌 첫 번째 | 규칙당 `Km` 하나 | 두 파일 |

## 2. 칸과 검사

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| `values.V….substrate` | 선택. `^D\d{6}$` | 없으면 null 로 열쇠에 들어감 (기존 값 열쇠 불변) | `model.js normValue` |
| `observations.O….observable.substrate` | 선택. 같은 모양. `observable.kind === kinetic_constant` 이고 `param` 이 허용 속성일 때만 | 기존 관찰은 불변(관찰은 바꾸지 않는다) | 스키마 |
| 열쇠 | `대상 \| 속성 \| 기질 \| 맥락열쇠` (+ 범주형이면 수준) | 같은 기질의 현재 값이 둘이면 RULE-0233 그대로 | `validateValues` |
| 검사 1 | `substrate` 가 있으면 속성이 `substratedProperties` 안 | 다른 속성은 거부 | 새 규칙 |
| 검사 2 | `substrate` 가 그 규칙을 `rule` 로 가진 단계의 `minor` 아닌 입력에 있다 | 엉뚱한 기질 번호 거부 | 새 규칙 |
| 검사 3 | 같은 `(대상, 속성)` 의 현재 값은 모두 기질이 있거나 모두 없다 | 섞임 거부 | 새 규칙 |
| 검사 4 | 값의 `from` 관찰 중 `observable.substrate` 가 있는 것은 값의 `substrate` 와 같다. 관찰에 기질이 없으면 비교하지 않음(옛 관찰은 바꿀 수 없다) | 기질이 다른 관찰을 근거로 달면 거부 | 새 규칙 |

## 2.5 패치로 넣는 길 — `kinetics.by_substrate`

패치는 `values` 를 직접 실을 수 없다 (`legislative.js foldValues` — 값은 규칙의 `kinetics` 보기와 정의항의 `obs` 보기에서만 만들어진다). 그래서 보기에 선택 칸 하나를 더한다.

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| `kinetics.by_substrate: { "D…": { Km: 숫자, from: ["O…"] } }` | 기질별 값을 실을 자리. 안쪽 속성은 `substratedProperties` 만 | 패치가 기질별 `Km` 을 값 층으로 보낼 수 있다 | `valuesOfKinetics` |
| 평면 `kinetics.Km` 은 **투영** | `by_substrate` 에 `Km` 이 있으면 평면 `Km` 은 첫 기질의 값을 보이는 것일 뿐이다. 값을 만들 때 무시한다 | 보기 → 값 → 보기 왕복이 멱등(중복 값이 안 생김). 보기를 읽고 고쳐 되돌려 보내는 패치가 안전 | 정규화 멱등 시험 |
| 보기 `by_substrate` 는 모든 기질을 보여 준다 | 읽는 쪽이 둘째 기질 이후를 볼 수 있다 | 엔진은 `by_substrate` 를 읽지 않는다(평면 `Km` 만) | §3 |
| 접기(`foldValues`) · 맞추기(`reconcileValues`) 의 짝짓기 열쇠 | 지금은 `속성` 만 — 기질이 다른 `Km` 을 같은 값으로 오인한다 | 열쇠를 `속성 \| 기질` 로. 패치가 규칙의 `kinetics` 를 통째로 주는 기존 규약(빠진 칸은 철회)은 그대로 | `foldValues` |

## 3. 보기 투영 (엔진은 그대로)

`kineticsOf(law, vals)` 가 만드는 `kinetics.Km` 은 **첫 기질의 Km** 이다.

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| 기질 없는 값만 있는 규칙 | 지금 모든 규칙 | 지금과 같다 | 기존 시험 |
| 기질 있는 값이 있는 규칙 | 단계에서 첫 `minor` 아닌 입력을 구해 그 기질의 `Km` 을 `kinetics.Km` 으로 | 엔진이 보는 숫자는 그대로 | `core.js:662` |
| 첫 기질의 값이 없는데 둘째 기질의 값만 있을 때 | 다른 기질의 Km 을 첫 기질 자리에 쓰면 틀린 숫자가 엔진에 간다 | `kinetics.Km` 을 **비운다**(없음). 엔진은 Km 없음으로 취급 — 기존 동작 | 새 시험 |
| 같은 규칙을 쓰는 단계가 여럿 | 첫 번째 단계(번호순)의 첫 기질 | 지금은 규칙당 단계 하나 | 데이터 확인 |
| 둘째 기질 이후의 Km | 값 층에는 저장, 보기에는 아직 안 나감 | 엔진의 다기질 법칙(다른 세션)이 서면 그때 보기를 더한다 — 이번에 만들지 않는다 | RULE-0462 |

## 4. 기존 데이터 이관 (데이터 패치 — 정보 작성 모드)

값은 바꿀 수 없으므로 새 기록이 `supersedes` 로 대체한다. 관찰은 바꿀 수 없으므로 기존 관찰은 그대로 둔다.

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| `V000060` (IDH3 `oxdecarb`) → 기질 `D000138` 아이소시트르산 | 첫 입력. 값은 S0.5 를 Km 으로 쓴 것 | 새 V 가 대체 | `S000033` |
| `V000063` (FH `hydrate`) → `D000142` 푸마르산 | 유일한 입력 | 새 V 가 대체 | `S000037` |
| `V000066` (CS `condense`) → `D000134` 아세틸-CoA | 첫 입력, 값 7.7 µM 은 아세틸-CoA Km | 새 V 가 대체 | `S000031` · `O000024` |
| `V000068` (ACO2 `isomerize`) → `D000137` 시트르산 | 유일한 입력 | 새 V 가 대체 | `S000032` |
| **새 V**: CS `condense` 의 `D000136` 옥살로아세트산 Km (`O000007`) | 되살리는 값. 단 `O000007` 의 기질이 옥살로아세트산인지 UniProt O75390 원본에서 먼저 확인한다(note 가 "아세틸-CoA 가 아닌 쪽" 이라고만 함) | 확인되면 값 층에 둘째 기질 Km 이 생김 | 이관 때 확인 |
| 규칙 안에서 한 번에 | 검사 3(섞임 금지) | 한 규칙의 기질 없는 값을 모두 같은 묶음에서 대체 | §2 |

## 6. 이번에 하지 않는 것

| 범위 | 이유 | 영향 | 확인 |
|---|---|---|---|
| 온도 · pH 곡선 맞춤 | 사용자 결정: 입력 시스템과 데이터 개념 이후 | `derivation` 에 `fit` 이 없다는 사실(`DERIVATIONS` 는 `direct · unit_conversion · lumped · computed`)만 적어 둔다 | 보고서 |
| 효소 형태 · 완충액 · 받개 칸 | 소비자가 없다. 효소 신원은 `subject` 의 `xrefs` 와 수집 때 검사로 해결 | 자유 글(`scope`)에 둔다 | 보고서 §6 |
| 엔진 다기질 법칙 | 다른 세션 | 보기에서 둘째 기질 이후를 내보내는 것도 그때 | §3 |
| `kcat` 의 기질 | 엔진은 규칙당 `kcat` 하나 | 필요해지면 `substratedProperties` 에 더한다 | §0 |
