# 에이전트 규칙 — 해설판

> 자동으로 실리는 `CLAUDE.md` 는 이 문서의 한 줄 점검표다. 규칙은 두 곳에 같이 있고, 이유·경위·예시는 여기에만 있다. 규칙을 바꾸면 두 곳을 같은 커밋에서 맞춘다.


데이터는 사람이 아니라 AI가 넣는다. 저장소는 `data/db.json`, 병합 기록은 `data/patches/`.
모든 항목은 고정 번호(개념 T…, 뜻 D…, 단계 S…)로 식별되고 연결도 번호로만 건다. 정의항의 하위 항목은 `D…/site/키`·`D…/rule/키`, 묶음은 `D…|부위:특징|위치`.
규칙 전체는 `SCHEMA.md`, 구조·저장·알고리즘·상호작용의 설명은 교과서 `docs/textbook/00-목차.md`. 명령은 저장소 최상위에서 실행한다.
**무엇을 어떻게 돌리는지는 `docs/RUNBOOK.md` 하나로 충분하다** — 돌릴 수 있는 경로·상태, 확인된 상태×시나리오 짝, 결과를 읽는 법, 관문 거부 메시지 → 고칠 곳, 넘길 신호. 큰 파일(`data/db.json` 604 KB·`CHANGES.md`·`limitations.md`)을 통째로 읽지 말고 조회 명령과 `grep` 으로 필요한 줄만 본다.

## 삼권 분립 (반드시 — 어기면 무결성 규약 위반, `docs/design/tripartite-governance.md`)

- **행정부(`core.js`·`engine/*`)는 읽기·시뮬레이션만.** 규칙과 초기 상태의 순수 함수로 원자료만 낸다 — 파일·db.json 쓰기, 검사·승인, `'verified'` 선언, 감사 코드(`AUDIT_*`)·사후 분석·질량 판정을 엔진에 넣지 않는다. 엔진이 사법·입법·조정자 모듈을 부르지 않는다.
- **입법부(`legislative/`)는 데이터 정의·수정만.** `merge`·패치 초안(보강·리팩터링)은 순수 함수, **파일 쓰기는 입법 서기 `legislative/clerk.mjs` 만** — db.json·patches 는 사법부 관문 봉인(통과 + 같은 db sha256)이 있을 때만, 증명 등록부는 도장 재검증 뒤에만. 다른 파일에 `writeFileSync` 같은 쓰기를 더하지 않는다(`dbtool.mjs` 포함).
- **쓸 자격과 쓸 자리는 따로 본다 (구역, `clerk.ZONES`).** 서기의 모든 쓰기는 `put(구역, 파일)` 하나를 지나고, 저장소 안에서 그 구역의 자리가 아니면 봉인이 유효해도 거부된다 — `registry`(db.json·patches·log — S1 델타 기록 · preregistrations.jsonl — 모의 실험 규약 사전 등록 · dictionary.jsonl · assumptions.jsonl — 가정 원장) · `attestation`(등록부) · `evidence`(수신함·받기) · `derived`(limitations.md·교과서 부록·CHANGES.md) · `report`(사용자 지정, 보호 목록) · `draft`(저장소 밖만 — MCP 입출력기 잠금도) · `handoff`(`workspace/handoff/` — 수집 후보를 붙이기만, 수집가 역할이 쓸 수 있는 유일한 자리). 저장소 밖 사본은 구역 밖이다. 새 쓰기를 더할 때는 구역을 고르거나 구역을 새로 선언한다 — `put` 을 우회하지 않는다(`tests/governance.test.mjs ④′`).
- **사법부(`judicial/`)는 검증·증명만.** validate·관문·Patch Report·정제 점검·한계 상태·감사(`auditRate`)·독립 질량 검증(`verifier.js`)·운명 판정(`fate_audit.js`)·보고서·비교 판정·신원 확인·증명 도장·통계 검정(`stats.js` — 자기 난수로 재표본)·관찰 판정(`obs_compare.js` — CONSISTENT·CONFLICT·INDISTINGUISHABLE). 행정부는 관찰을 읽지 않는다 — 예측 표본은 조정자가 관찰 연산자(`compiler/obs_operator.js`)로 만들어 넘긴다. 엔진을 실행하지 않고(원자료를 입력으로 받음) 데이터·엔진을 고치지 않는다 — 오류는 판결·보고서로만 내고, 고치는 것은 에이전트가 새 패치로 한다(읽기 전용 되먹임).
- **`'verified'` 는 사법부 도장으로만.** `attestations/registry.json` 의 유효한 도장(digest·증거 sha256·같은 확인 재실행) 없이 status `verified` 를 패치에 쓰면 관문이 거부한다. 도장은 `augment apply` 가 판결과 함께 발급하고 서기가 기록한다. `node dbtool.mjs attest` 로 재검증.
- 엔진 실행이 필요한 감사(audit-run·해상도 계획·비교 검토·운명 보고서)는 조정자 `orchestrator.js` 가 행정부로 원자료를 만들고 사법부에 넘긴다. 엔진의 수치 선택(정칙화·관문 문턱·탐침 격자·뉴턴 허용 오차)은 `engine/coupling.js` 등록부에서만 읽는다 — 엔진에 기본값을 박지 않는다.
- **엔진 출력은 원자료 계약을 지킨다.** 운명 엔진(JS·Rust/WASM)의 출력 모양을 바꾸면 `schemas/ffi/fate-raw.schema.json` 을 같은 커밋에서 고친다 — 사법부(`judicial/contract.js`)는 계약을 어긴 원자료를 판정하지 않는다. 엔진 이식은 `docs/design/engine-port-roadmap.md` 의 단계·완료 조건을 따르고, 이득은 `node tests/bench_engine.js` 기준선과 함께 보고한다.
- **컴파일러(`compiler/`)는 공유 순수 층.** db + 시나리오 → 불변 IR(정수 번호·화학량·속도식·기호 도함수 테이프·희소 패턴·해시). 3단계: 희소 LU 기호 분석(`sparse_lu.js` — 최소 차수 순서·채움·값 위치, 사법부 `checkLU` 가 검증)과 경로 시뮬레이션 IR(`rate_ir.js` — `simulateRate` 루프는 그 정수 표 위에서, 결과는 이전과 비트 단위로 같아야 한다). 쓰기·판정·엔진·권력 모듈 호출 없음. 엔진은 IR 만 먹고 원자료에 `irHash` 를 적으며, 조정자는 같은 IR 을 사법부에 넘겨 `judicial/derivative.js` 가 법칙 충실도·자동미분 대비 도함수(≤ 1e-14)를 검증한다. 속도 법칙을 바꾸면 컴파일러·테이프 명세·사법부 법칙 재구성을 같은 커밋에서 맞춘다.
- **결함은 태그대로 고친다 (`judicial/fault.js`).** 모든 감사 항목에 `fault` 가 있다: `FINDING`(결과 — 고치지 않음) · `DATA_GAP`(한계 등록, 확인된 값만) · `DOMAIN_CONFLICT`(근거와 함께 데이터 패치) · `NUMERICAL`(결합점·솔버 — **db.json 의 생물 상수를 바꾸지 않는다**) · `ENGINE_DEFECT`(엔진 코드) · `COMPILER_DEFECT`(`compiler/`). 수치 문제를 데이터로 맞추거나 결과(고갈·정지)를 결함으로 고치지 않는다.
- **표·로직 분리 (2026-10-23).** "토큰 → 사람말" 표(라벨·의미)는 데이터라 `vocab.js` 한 곳에 두고(영어는 `data/dictionary.jsonl`, 신원 = register/key — 같은 키가 여러 표에 있을 수 있어 맨 키는 하나뿐일 때만), 모듈은 그 표의 보기(`M.labelsOf`)만 계산한다 — 같은 문구를 코드에 복사하지 않는다. "토큰 → 동작·숫자·정책" 표(교란 부호, ID 정규식, 적분기 계수, 서기 쓰기 허용 경로, 감지 함수)와 등급 규칙의 설명(`reliability.js` RULE)은 로직과 함께 바뀌어야 하므로 로직 곁에 둔다. 사전은 vocab 만 읽어서 어느 권력 층이 써도 다른 층으로 가는 우회로가 아니다(governance ⑮). 이유: 결함 채널 표가 사법부에 있으면 행정부가 사전을 쓰는 순간 행정→사법 경로가 생긴다.
- **군더더기 금지.** 결함은 `storage-map.json` 의 아키텍처 노드(`node`·`governance`·`refactor_strategy`) 안에서 고친다 — 래퍼·임시 대체 플래그·사후 잘라내기로 덮지 않는다. 비교용으로 남긴 경로는 판정이 나면 지운다.
- **Rust 엔진 (`engine/rust/`, 1·1.5·2단계).** 운명 엔진의 기본 백엔드는 Rust/WASM(`engine: 'rust'`), JS(`engine/fate_engine.js` 의 `run`)는 기준 구현(오라클)이다. 두 백엔드 모두 IR 테이프만 해석한다(법칙 코드 없음). 적분은 두 층·조절 배율을 묶은 진행량 좌표 결합 Rodas3(오차 추정·단계 거부로 양수성) — 정확도는 `integrator.rtol·atol`(결합점 등록부)로 정하고, 관찰 격자 `dt_slow` 는 신호·기록 간격일 뿐이다. 수치 L2 의 수렴 기준은 같은 적분기를 허용 오차 1/1000 로(`orchestrator.refScenario`). 결정 탐침은 워커마다 독립 WASM 인스턴스로 병렬(`engine/probe_pool.js`) — 탐침은 (시작 상태, t0) 의 순수 함수로 두고, 결정 시각·탐침 끝 상태는 lanes 와 무관하게 직렬과 같아야 한다(⑦). 사건·도달·결정 시각은 격자에서 감지한 뒤 직전 스냅숏에서 같은 적분기로 다시 적분(`advance`)해 근 찾기·연속 이분 탐색으로 정한다(4단계 ③, `event_tol`·`commitment_tol`) — 보고 시각을 격자 Δ 로 되돌리지 않는다. Rust 소스를 바꾸면 `sh engine/rust/build.sh` 로 `pkg/fate_core.wasm`·`.json` 을 다시 만들어 같은 커밋에 넣고, `tests/rust_engine.test.mjs`(JS 와 동등 — 궤적 ≤ rtol·운명·시각 같음·byteLength 불변·네이티브 = WASM 비트·루프 할당 0)가 통과해야 한다. 알고리즘을 바꾸면 두 백엔드를 같은 커밋에서 맞춘다. 확률 층(4단계 ⑤)도 두 백엔드에 같은 순서로 있다 — 연속 부분이 자명한 계(출생–사멸)는 같은 (seed, 궤적)에서 JS = Rust 비트, 운명 프로그램은 결정론 부분의 libm ulp 차이가 도약·추첨으로 증폭되므로 같은 분포(두 표본 검정)로 판정한다. 네이티브 = WASM 은 확률 실행도 비트 단위.
- 이 분리를 바꾸는 변경은 `node --test tests/*.test.mjs`(특히 `tests/governance.test.mjs`) 통과가 조건이다.

## 데이터를 넣을 때

`data/db.json` 을 직접 편집하지 않는다. 항상 패치 → `merge` 경로를 쓴다.

1. `node dbtool.mjs status`, `node dbtool.mjs prompt` 로 규모·규칙·색인을 읽는다.
2. 쓰려는 개념이 이미 있는지 `node dbtool.mjs map <이름|영문명|외부ID>` 로 먼저 찾는다. 있으면 그 번호(D…)를 쓴다.
   뜻이 여러 개면 `node dbtool.mjs context <피정의항>` 으로 맥락을 보고 맞는 정의항을 고른다.
   기전을 넣을 때는 `node dbtool.mjs mechanism <경로|S…>` 으로 기존 사슬·묶음 키를, `context` 로 원천의 부위·규칙을 확인한다.
3. 패치 JSON 을 저장소 밖(스크래치 폴더)에 쓰고 `node dbtool.mjs merge <patch.json> --dry` 로 관문을 통과하는지 본다.
   거부되면 메시지대로 고친다. `--allow-warnings` 는 사용자가 허락한 경우에만 쓴다.
4. 통과하면 `--dry` 없이 병합하고 `data/db.json` 과 `data/patches/` 를 함께 커밋한다.

반드시 지킬 것
- 외부 ID(ChEBI, UniProt, EC, GO …)는 확실한 것만 적는다. 모르면 `unmapped` 에 사유를 적는다. 지어내지 않는다.
- **외부 ID 는 역할을 선언한다 (ChEBI 규약).** ChEBI 는 같은 물질에 중성 모체·pH 7.3 우세 이온 종·이온화 상태를 묶은 분류를 따로 두므로, `xrefs[].role` 로 규약을 적는다 — `physiological`(엔진·상호 운용이 읽는 단 하나) · `parent`(모체, 다를 때만) · `class`(중합체·불균일 물질만). 분류 항목을 저분자·이온의 번호로 쓰면 화학식 대조가 건너뛰어지므로 거부된다. `physiological` 주장은 켤레 관계(짝과 수소·전하만 차이)와 반응 참여(Rhea ≥ 3, `data/fetched/rhea/`)를 모두 통과해야 verified 가 된다.
- 원본 대조는 자동 보강 고리로만: `node dbtool.mjs augment plan` → `fetch`(막히면 `data/fetched/RETRIEVAL_TASKS.md` 를 사용자에게 넘김 — "UniProt 에 닿지 못함, 이 파일들을 받아 주세요") → `build`(확인) → `apply`(관문 + CHANGES 행). 확인을 통과한 것만 `verified`, 모호하면 unmapped + Identity_Gap 유지, 다른 값의 asserted 는 사용자가 동기화를 요청할 때만(`--sync`) 바꾼다. 수신함 원본은 해석만 하고 실행하지 않는다.
- 두 해상도를 지킨다.
  - 정의항(D)을 만들거나 넓힐 때: 완전성·구조적 깊이 우선. 구성 요소(소단위·보조인자), 막 위상, 부위, 규칙을 빠뜨리지 않는다.
    잔기 번호를 모르면 `residue_unknown: true`, 외부 ID 를 모르면 `unmapped` — 모르는 값은 명시하고 지어내지 않는다.
  - 묶음·단계(B/S)를 만들 때: 효율·참조 무결성 우선. 단계는 원천의 전이 규칙 참조 + 묶음만. 라벨·설명문은 규칙에 둔다.
- 인산화형·활성형 같은 변화는 새 개념이 아니라 묶음의 `부위:특징` 으로, 활성은 원천의 상태 의미 규칙으로 표현한다.
- 위치는 묶음마다 적는다(세포 밖·세포막·세포질 …). 공간 접촉이 안 되는 단계는 거부된다 — 위치를 고치거나 수송 단계를 넣는다.
- 종마다 다른 값은 `obs` 에 `context.species` 와 함께. 정의항의 기준 종은 하나(단백질·핵산은 기본 9606).
- 연결의 `span` 은 정의 문장 속 구절을 원문 그대로. 근거가 문장에 없으면 연결을 빼거나 문장을 고친다.
- 기존 정의항을 고치는 패치는 적은 최상위 필드만 교체한다. `desc`·`site`·`rule` 같은 배열·객체는 통째로 바뀌므로 유지할 항목도 함께 적는다.
- 새 항목에는 임시 번호(T+1, D+1, S+1)를 쓴다. 번호를 직접 지어내지 않는다. `data/db.json` 의 `meta.next` 를 손대지 않는다.
- 구조 지문(InChIKey·서열 해시)은 머릿속으로 계산해 넣지 않는다. 도구로 계산한 값만 `computed` 로 넣는다.

## 한계와 개념 진화 (반드시)

- **한계는 데이터다.** 시뮬레이션 실패·우회·추정·단순화를 오류로 넘기지 않는다. 발견하는 즉시 패치의 `limitations` 로 `[Target | Type | Requirement]` 를 등록하고(해결 경로 `needs` 포함) `node dbtool.mjs limitations --write` 로 `limitations.md` 를 갱신한다. `node dbtool.mjs limitations --detect` 의 후보가 0 이 되게 한다.
- **새 개념을 설계하기 전에 `limitations.md` 를 먼저 읽는다.** 새 정의항이 어떤 한계를 어떻게 해결하는지 `addresses: [{ limitation, how }]` 에 적는다. 해결하지 않으면 `gap_review` 에 이유를 적는다(상위 개념은 둘 중 하나가 없으면 거부된다).
- **개별 단계에 갇히지 않는다.** 경로를 넣은 뒤 `node dbtool.mjs pattern <경로>` 로 상위 패턴을 확인하고, 상위 개념이 없는 패턴이 두 경로 이상에서 반복되면 kind process + `motif` 정의항으로 추상화한다.
- 시뮬레이션 결과를 보고할 때는 "농도 공백" 표시(기본값·무한 풀)를 함께 밝힌다 — 그 결과는 도달 여부만 말한다.
- **3차원을 무작정 늘리지 않는다.** `node dbtool.mjs resolution <경로>` 로 단계마다 필요한 해상도(R0 위상·R1 부위·R2 구조)를 보고, R2 는 경쟁(T3)을 속도 상수로 가를 수 없는 반응 중심에만 둔다. 경쟁은 먼저 속도 상수(Kd·kcat·Km)로 푼다.
- **속도 상수는 규칙의 `kinetics` 에 SI 정준 단위로, 근거와 함께.** 확인하지 못한 값은 넣지 않는다 — 엔진 시험용 값은 **가정 원장**(`data/assumptions.jsonl`, build-plan 49 · `structure-realignment.md` §3)에 번호 A… 로 두고 `hypothetical: true` 시나리오가 숫자 자리에 `{ "assume": "A…" }` 로 가리킨다. 이유: 같은 가상 숫자를 파일마다 복사하면(변환 전 속도 상수 기입 794 개 중 서로 다른 값 124 개) 어느 결론이 어느 가정에 기대는지 셀 수 없고, 나중에 고칠 때 연결이 조용히 약해진다. 그래서 (ㄱ) 원장은 추가만 하는 사슬이고 쓰기는 사법부 `assumption_audit.checkProposals` 봉인 뒤 서기만(`node dbtool.mjs assume add`), (ㄴ) 고치기는 `revises` 단 새 번호 — **가리키는 쪽은 최신을 따라가지 않는다**(옛 번호는 옛 숫자), (ㄷ) 번호는 자기 자리(종류·열쇠·칸·부피는 세포)에만 붙고 다른 칸에 옮겨 붙이면 풀기가 거부, (ㄹ) 사전 등록은 번호를 푼 내용에 해시를 걸고 인라인 가상 숫자가 있으면 거부(이미 등록된 5 건은 다시 쓰지 않고 `assume uses` 가 내용 일치로 잇는다), (ㅁ) 새 기록은 기원 기록 없음(unrecorded)일 수 없다 — 열린 한계를 달고 assumed 로. 탐색 실행(미등록)은 인라인 숫자를 허용하되 첫 장면 기원 감사가 unrecorded 로 센다. 문헌 값은 **관찰 기록(O…)으로 먼저 넣고 `kinetics.from` 으로 참조**해야 관문을 통과한다(교과서 7.5′). 종이 다른 값(돼지·소 심장 효소)을 사람 값으로 적지 않고 찾지 못한 것은 한계로 등록한다. 불확도를 보고하지 않은 문헌 값은 sd 를 보고된 유효 숫자의 해상도로 적고 그 사실을 `note` 에 남긴다. 상수를 넣으면 '즉시' 로 처리되던 단계가 속도를 갖게 되어 궤적이 크게 바뀌므로, 넣은 뒤 전후를 비교해 보고한다.
- **값의 등급은 계산된다 (신뢰 지표, `judicial/reliability.js`).** 어떤 값을 시뮬레이션에 쓸 수 있는지는 두 축으로 가른다 — S(출처: 유효한 도장 4 · 문헌 식별자 3 · 그 밖 2 · 확인 불가 0)와 D(성질: 실측·도구 계산 4 · 요약 상수 3 · 추론 2). 점수를 데이터에 적지 않는다(계산되는 것). 곱 S×D 로 판정하지 않는다 — (2,4) 와 (4,2) 가 겹친다. 등급은 `anchor`(기준값) · `parameter`(매개변수) · `bounded`(오차 막대와 함께) · `legacy`(지난값, 지우지 않음) · `reference`(계산 금지) · `blocked`(한계로만)이고, `node dbtool.mjs grade [--min parameter]` 로 본다. 결과를 보고할 때는 쓴 값의 등급을 함께 말한다.
- **추세는 다시 받아 확인한다 (시간 축 ③, `judicial/trend.js`).** 등급 `anchor`(기준값)는 "지금도 합의와 같다" 를 요구한다. 웹 검색 결과를 데이터로 저장하지 않는다 — `node dbtool.mjs trend --fetch` 로 **더 새 원본**을 합의 수신함(`data/fetched/consensus/`, 신원 수신함을 덮지 않는다)에 받고, `trend` 가 같은 신원 확인을 다시 돌려 `match`·`mismatch`·`unchecked` 를 판정한 뒤 `--write` 로 날짜가 박힌 도장(claim `trend`)을 남긴다. 원천별 합의 창(`vocab.consensus.sources` — 원천이 공표한 판 주기: UniProt 56 일 · ChEBI 31 일, 2026-10-24 결정)을 넘긴 도장은 다시 `unchecked` 이므로 기준값은 영구하지 않다. 표에 없는 원천은 창이 없으니 만료다 — 창을 지어내지 않는다. `mismatch` 면 값을 지우지 않고 등급이 `legacy` 로 내려가며 `Consensus_Gap` 을 등록한다 — 왜 달라졌는지가 데이터다.
- **인정은 (기록, 용도) 순서쌍이다 (build-plan 72, `judicial/acceptance.js`).** 같은 값이라도 서술에 쓸 때와 검증 근거로 쓸 때 요구가 다르다. 서술·비교·추정은 축 조건과 관계 조건(기준 종, 추정에 쓰지 않음)으로 계산만 하고, 검증 근거·기준은 `node dbtool.mjs accept <O…> --use evidence --reason "…"` 의 승인 도장이 있어야 한다. 승인은 사람과 통합 에이전트(`BIODB_ROLE=integrator`, 2026-10-25 결정 — 자동결정률을 위해)가 하고, 수집가는 못 한다. 승인은 축 조건을 넘지 못하며(서기가 거부), 나중에 축이 내려가면 도장이 있어도 '재검토' 로 보인다. 결론은 가장 약한 근거를 따른다 — 검증 세트의 관찰 하나라도 인정되지 않으면 보고서 판정이 '인정 재검토 필요' 다. 관찰의 `use` 는 신청이지 인정이 아니다. 기준(standard)은 독립 단위 ≥ 2 를 요구하므로 I 축(52) 전에는 아무것도 닿지 못한다.
- **등급은 쓰는 자리에서 강제된다 (관문 ②).** 시뮬레이션·운명 실행마다 사법부가 쓰인 상수의 등급을 계산한다 — 데이터에서 온 상수가 문턱(기본 `parameter`) 미달이면 `AUDIT_KINETIC` 이고, 시나리오가 준 값은 등급 밖(`hypothetical`)이므로 그 시나리오가 `hypothetical: true` 를 선언했을 때만 쓸 수 있다. 문턱은 시나리오 `min_grade` 로만 올린다(내리는 길은 없다 — 2026-10-25 까지는 글로만 있었고 `reference` 같은 낮은 문턱이 통과했다. 이제 `gateMinError` 가 기본보다 엄격하지 않은 문턱을 거부한다). 문턱 비교는 축 조건(`THRESHOLD`: S ≥ s ∧ D ≥ d ∧ 허용 추세)이라 비교할 수 없는 bounded(S4,D2)와 parameter(S3,D3)는 서로의 문턱을 넘지 못한다. 과정 보고서의 무결성 증명서가 이 판정을 한 줄로 싣고, 미달이면 FAIL 이므로 그 결과를 결론에 쓰지 않는다.
- **값 층 (형식 v12, SCHEMA §8N).** 수치는 정의 구조 안이 아니라 `values`(V…)에 기록 하나씩 저장한다 — 앞으로 가장 많이 늘고 가장 자주 형식이 바뀌는 것이 값이기 때문이다. 정의항 `obs`·규칙 `kinetics` 는 정규화가 현재 값으로 붙이는 보기라서 읽는 코드와 패치 작성법은 그대로다. 값 기록은 바꾸거나 지우지 않는다: 바뀌면 병합이 새 기록(`supersedes`)을, 빠지면 철회를 남기고, 관문(`valueImmutability`)이 이전 기록이 그대로인지 본다. 값이 바뀌는 병합에는 기록 시각(`recorded_at`, dbtool 이 병합 전에 찍음)이 필요하다 — 사건 사슬을 재생하면 같은 db 가 나와야 하고, `model.asOf(그날)` 로 과거 시점의 값을 다시 세울 수 있어야 하기 때문이다. 패치가 `values` 를 직접 쓰면 거부한다.
- **실측값은 관찰 기록으로 (v10, `docs/design/observation-port.md`).** 측정한 수치는 모델 표현이 아니라 "무엇을 쟀는가"로 `observations`(O+1)에 넣는다. 값(SI)·불확도(크기·유형·잡음 모형)·반복 수·조건(종)·출처·용도(`estimation | validation`)가 필수다. 원문에 반복 수가 없으면 `replicates: null`(미보고)로 적고 1 로 채우지 않는다 — 1 이 '한 번 잼' 과 '모름' 을 섞으면 신뢰 지표가 둘을 가를 수 없다(2026-10-25). 미보고는 D3, 비교는 1 회로 본다(표준 오차가 가장 넓은 쪽). eQuilibrator 같은 도구 추정값은 관찰 칸에 있어도 실측이 아니다(`D2.estimate`). 문헌 속도 상수는 그 관찰을 `kinetics.from` 으로 참조하는 파생값이고, 묶은 상수(`lumped`)도 원 관찰을 참조한다. 관찰 기록은 바꾸거나 지우지 않는다 — 잘못이면 `retracted` 만 더한다. 추정에 쓴 관찰을 검증에 쓰지 않는다. 합성 관찰은 `examples/observations/` 에만 둔다. 측정값은 손으로 옮기지 말고 포트(계약 `schemas/obs/`)로 넣는다 — 지식(개념·기전)은 직접 패치, 측정은 포트. **정의항 `obs` 도 측정의 파생값이다 (v11, SCHEMA §8M)** — 측정량이 있는 속성의 문헌(`curated`) 값은 `from: 'O…'` 로 그 관찰을 가리켜야 하고, 사법부가 단위 환산 뒤 값·종·세포·위치를 대조한다. 단위는 `vocab.unitFactors` 의 환산표에 있는 것만, 값은 `vocab.physicalBounds` 의 물리적 상한 안이어야 한다(818 µM 을 818 M 로 적는 실수를 잡는 천장이고, 그럴듯함은 판정하지 않는다). `from` 이 달린 obs 는 **지울 수 없다** — 가리키는 관찰에 `retracted` 를 표시한 뒤에만 지운다. 환산표는 엔진과 사법부가 **같은 것 하나**를 읽는다(표가 둘이면 대조가 자기 환산으로 틀린다).
- **교란 실험은 복사본이 아니라 파생 시나리오로 (build-plan 9).** 무엇을 끊거나 막은 실험은 기준 시나리오를 복사해 값을 고치지 말고 `{ base: '기준.json', perturbation: { … } }` 로 적는다 — 기준이 대조군이고, 교란 외의 차이가 생길 자리가 없다(다른 필드는 거부). 복사본은 기준이 바뀌어도 따라가지 않고, 무엇과 비교하는지가 파일 밖에서 정해진다(예전 MHC II null 두 건은 '같은 신호' 라고 했지만 성숙 시나리오와 신호가 달랐다).
- **정성 관찰과 맥락 열쇠 (형식 v12 2차, SCHEMA §8N · `docs/design/format-v12.md` §4–6).** "X 를 없애면 Y 가 줄었다" 같은 방향·유무·순서의 실험 결과는 `kind: 'qualitative'` 관찰로 넣는다 — 교란(`perturbation`, `compiler/perturb.js` 와 같은 형식)·읽을 거리(`readout`)·기대(`expect`). 출처는 1차 문헌(DOI·PMID, `provenance.source`)과 그 논문의 문장을 그대로 옮긴 `quote` 가 필수다: 교과서·추론은 정성 관찰이 될 수 없고(그런 후보는 한계·메모로), 정성 관찰은 검증용(`validation`)만이며 수치(속도 상수·정의항 obs)의 근거가 될 수 없다. 같은 논문의 같은 실험계에서 나온 관찰은 `experiment` 로 묶는다 — 독립 판정의 단위다. 값·관찰의 맥락은 `vocab.contextKeys` 여섯 칸이 열쇠이고(`model.contextKey`), `condition` 은 정의항 번호 목록이다 — 자유 문장은 `scope` 에 둔다(열쇠에 문장이 들어가면 같은 맥락이 다른 열쇠가 된다). 같은 열쇠의 현재 값은 하나뿐이다. 정의항·개념·단계를 합치거나 나눌 때는 지우고 새로 만들지 말고 패치 `moved` 로 옮긴다 — 번호는 재사용하지 않고, 옛 번호를 가리키는 패치·정의는 관문이 대상을 알려 주며 거부한다. 정성 관찰을 넣은 뒤에는 `node dbtool.mjs qualgraph` 로 0 층 판정을 본다 — 기전 그래프에 교란 대상 → 읽을 거리 경로가 없으면 Structural_Gap 후보(빠진 단계·조절을 찾거나 한계로 등록), 모든 경로 부호가 주장과 반대면 모순 후보(근거와 데이터를 다시 대조). "구조 지지" 는 경로와 부호가 맞는다는 뜻일 뿐 관찰과 일치한다는 판정이 아니다 — 일치는 사전 등록된 규약 아래의 모의 판정으로만. 모의 판정은 `node dbtool.mjs observe <O…> --state <상태> --scenario <대조군>` 으로 — 관찰이 선언한 교란을 대조군 시나리오에 걸어(교란 차이 검사 통과가 전제) 두 군을 돌리고 방향·유무·단조·순서를 본다. 결정론은 차이가 분해능(수치 오차 + 분자 1 개)을 넘어야 방향이 있고, 앙상블은 검정으로 — 보이지 못한 것은 불일치가 아니다(그렇게 보고). 효과 없음은 앙상블에서 동등성 허용 차이 δ 가 있어야 보인다. 여러 주장을 보고할 때는 맞힌 수가 우연으로 나올 확률(우연 기준선)을 함께 적는다.
- **모든 시뮬레이션·갱신 뒤 `node dbtool.mjs audit-run <경로>` 를 돌린다.** Audit Error 는 오류로 넘기지 말고, 교정 제안의 한계를 채우거나 새 한계로 등록한다.
- **물질은 무한하지 않다 (v7).** 대사물은 유한 저장소이고, 재생은 공급 규칙(`type: supply`)으로, 소멸은 분해 규칙(`type: degradation`, lost | recycled)으로만 표현한다. 고갈(AUDIT_RESOURCE·stalled)은 결과로 보고하고, 재생 경로가 없으면 공급 규칙을 정의하거나 Kinetic_Gap 으로 등록한다.
- **유한 계는 결국 멈춘다.** 회로·경로를 넣으면 `simulate --rate --until-death` 로 정지까지 돌리고, 사후 분석의 제한 요인(고갈 → Resource_Gap, 평형·속도 → Kinetic_Gap)을 등록한다. 적분 안정성 감사(Δt 너무 큼)가 나오면 Δt 를 줄여 결과가 수렴할 때만 보고한다.
- **3 층 (v8).** 새 분자 정의항에는 `tier`(T1 연속 장 | T2 규칙 행위자)를 — 분자 부류는 반드시 명시. 확산 계수·pH·유전율은 위치(`context.location`)와 SI 단위로만. 가역 반응은 `dG0` 로 역 상수를 정하고(k_r 를 따로 지어내지 않음), 닫힌 고리 ΣΔG° = 0 (AUDIT_THERMO). 실행 상태(영역·원장 거래)는 데이터베이스에 넣지 않고 시나리오 `domains`·`engine/` 에.
- **실행 층(P3) 을 바꾸면** `node tests/p3_end_to_end.js` 가 |N_initial − N_final| < 1 로 통과해야 한다. 원장은 거래(`applyLedgerTx`·`applyLocalTx`)로만 바꾸고, 장(FV)은 언제나 원장에 맞춰 재척도한다 — 반대 방향 금지.
- **대리 모델(P4) 은 분포 안에서만.** 대리 출력은 같은 단계에서 OOD 탐지를 통과해야 쓰고, 아니면 버리고 FV. 속도 향상을 보고할 때는 `tests/p4_benchmark.js` 의 FV 부분 단계 수(강성)와 함께 — 비강성 영역에서는 대리 모델이 더 느리다. 정확도 기준(L2 < 2%)과 `tests/p4_end_to_end.js` 통과가 바꾼 뒤의 조건.
- **동적 관문(P5) 은 강성으로 고른다.** 경로는 `engine/p5_dynamic_gate.js` 의 N_sub(FV 부분 단계 수와 같아야 함)·히스테리시스(K_up/K_down/M)·사전 필터 γ 로만 정하고, 충격·OOD 는 같은 단계 강등 + W 냉각. 전이마다 `exactAnchor` 로 |Σu − N_ledger| ≤ 1e-15. `mode: 'fv'`(P3) 결과는 비트 단위로 바꾸지 않는다. 관문·대리 모델을 바꾸면 `tests/p5_dynamic_promotion.js` 통과가 조건이고, 속도는 구간별 N_sub 와 함께 보고한다(N_sub < 15 구간은 ≈ 1×). 운명 엔진은 1.5단계부터 이 관문을 쓰지 않는다 — 강성은 L-안정 결합 적분이 흡수한다.
- **운명은 상태 전이다 (v9).** 계통 결정은 `cell_state`(표지 서명·대사 프로그램·전이)와 `modulation` 규칙의 사슬(신호 → 대사 공급 규칙 → 대사물 → 전사 인자 합성)로 넣는다 — 표지를 데이터에 직접 올리지 않는다. 매개 단계를 조절 규칙 하나로 묶으면 `Regulatory_Gap` 을 등록하고(힐 상수 포함), 힐 상수·합성 속도·문턱은 확인한 값만 데이터에, 나머지는 `hypothetical` 시나리오에. 운명 결과를 보고할 때는 결정 시점(신호 철회 시험)·분화 정지 원인(사후 분석의 고갈 저장소·시각)과 함께 "상수는 가상" 을 밝히고, 운명 층을 바꾸면 `node tests/fate_suite.js` 통과가 조건이다. 생리적이지 않은 계통 경로(예: B 세포 → NKT 세포)는 근거 사슬 없이 만들지 않는다.
- **분열·소모는 공급 규칙의 진행량으로 센다 (복제 노화 실험, SCHEMA §8L).** "분열마다 줄어든다" 를 담으려고 새 규칙 종류나 횟수를 세는 가짜 분자를 만들지 않는다 — 0차 공급 규칙 하나(`zero_order`, k = 간격의 역수 ÷ N_A·V)의 **누적 진행량이 분열 횟수**이고 소비 화학량이 분열당 소실량이다. 임계값에서의 전이는 억제 힐로 두고 **K 를 임계값보다 10 % 아래**에 놓는다 — 힐은 K 에서 이미 절반 켜져 있어서 K 를 임계값에 맞추면 정지 되먹임이 임계 통과 자체를 늦춘다. 활성 힐(`activates`)의 기준선은 1 로 고정이므로 "신호 없으면 속도 0" 은 쓸 수 없고 1/fmax 근사로 적어 한계로 등록한다. 도달·임계 시각은 격자가 아니라 근 찾기로 나오므로 Δ 를 바꿔 같은지 확인해 보고한다.
- **엔진은 이름을 모른다.** `core.js`·`engine/*` 에 분자·위치·부분 구조 이름을 쓰지 않는다 — 화학·생물 사실(부분 구조의 원자 수 `elements`, 기본 위치 `defaultVolumeLocation` …)은 데이터나 어휘에 두고 엔진은 번호·부분 구조·속도 상수로만 계산한다. 부분 구조 수지 ΣIn = ΣOut 은 규칙 검사와 운명 엔진 원장 모두 상대 1e-14.
- **비교 검토 없이 더하지 않는다 (Comparative Optimization).** 새 규칙·경로·수식·수치 선택은 `node dbtool.mjs compare --state … --scenario A [--scenario-b B | --patch p]` 로 지금 구현과 나란히 돌려 판정을 본다: 결과가 같고 비용(규칙·조절 수, 시간 +5% 초과)만 늘며 수치 이득 < 1e-5 이면 **Optimization-Negative — 넣지 않는다**. 결과가 바뀌면(Behavior-Changing) 수치로는 고를 수 없으니 관찰 데이터로 고르고, 없으면 그 선택을 Kinetic_Gap/Regulatory_Gap 의 note 로 남긴다. 이미 있는 supply·modulation 으로 표현할 수 있으면 새 규칙 종류를 만들지 않는다.
- **정제 점검은 자동이다.** `augment build/apply`, `simulate --rate`, `fate`, `validate <patch>` 가 `refineCheck`(사법부, 판결만) 를 돌린다 — 중복 규칙(같은 화학량·위치의 공급, 같은 조절자·대상·효과·위치의 조절)과 경로 순 반응 ↔ 단계 화학량 합의 모순. 패치가 새로 만든 중복이나 등록 안 된 모순은 병합을 막고, 입법부(`legislative.draftRefactor`)가 리팩터링 패치 초안(참조 없는 중복 제거)을 저장소 밖에 쓴다 — 적용은 에이전트가 새 패치로. 의도한 단순화면 그 규칙을 대상으로 Structural_Gap 을 등록한다(→ known).
- **기전은 세포 상태에 걸어 돌린다 (MHC 실험).** 기전 경로를 운명 엔진에서 돌리려면 그 경로를 세포 상태의 `mechanisms` 에 걸고, 상태의 표지는 그 기전이 만드는 묶음으로 둔다 — 경로만 따로 돌리는 길을 만들지 않는다. 단계의 속도 법칙은 질량 작용·가역 결합·미카엘리스–멘텐만 결합 적분으로 내려가고(가역 결합은 정·역 두 채널), 나머지는 단계를 끄고 `Kinetic_Gap` 으로 보고된다. 막에서만 일어나는 단계는 시나리오 `volumes[막]` 을 유효 부피로 쓴다 — `simulateRate` 는 같은 단계를 '즉시'로 다루므로 두 경로의 궤적을 서로의 수렴 기준으로 쓰지 않는다(L000081). 기전 층을 바꾸면 `node --test tests/mhc.test.mjs` 통과가 조건이다.
- **시나리오는 무엇을 보이려는지 선언한다.** 운명·기전 시나리오에 `context { role, state, note }` 를 둔다 — `cause`(그 상태에 이르는 원인) · `requirement`(무엇을 끊으면 이르지 못하는지) · `baseline`(신호 없는 일반 상황). 사법부가 선언과 실행의 일관성을 판정하고, 어긋나면 무결성 증명서가 FAIL 이다. 결과를 보고할 때는 맥락과 함께 말한다("이 실행은 X 의 원인을 보인다", "Y 없이는 이르지 못한다").
- **확률 결과는 앙상블로만 판정한다 (4단계 ④).** 시나리오 `stochastic { seed }` 로 켜고(seed 는 실행 전에 — 입력 해시), 궤적 하나를 결론으로 쓰지 않는다. 운명 비율(구간)·도달 시각 분포·표지 퍼짐(Fano)은 `judicial/stoch_audit.js` 로, 방식(SSA·τ-도약)이나 분할 문턱을 바꾸면 해석해·두 표본·결정론 극한 시험(`tests/stochastic.test.mjs`)이 통과해야 한다. 확률 실행이 없으면 결정론 결과는 비트 단위로 그대로여야 한다.
- **교란은 컴파일러 연산자로만 (build-plan 4).** 넉아웃·차단·억제·고정·용량 단계는 `compiler/perturb.js` 가 기준 시나리오에 선언 필드(`amounts`·`exclude_rules`·`rule_scale`·`buffered`·`signals`)로만 얹는다 — 시나리오 파일을 복사해 시작량만 0 으로 두면 합성 규칙이 살아 있어 넉아웃이 아니고, 대조군과 교란 외의 차이를 보장할 수 없다. 엔진은 바뀌지 않고(IR 테이프만), 억제 배율은 사법부 `derivative` 가 같은 값으로 법칙을 재구성한다. 억제는 경쟁·비경쟁을 가리지 않는 단순 배율이다. 사법부 `judicial/perturb_audit.js` 는 컴파일러 코드를 쓰지 않고 기준 시나리오·기준 IR 에서 교란 결과를 다시 세워, 교란 시나리오·IR 이 선언한 교란만큼만 다른지(생성 규칙을 빠뜨린 넉아웃, 선언 밖 차이, 다른 대조군, 꾸민 배율)를 판정한다.
- **검증은 사전 등록된 모의 실험 규약 아래에서만 (build-plan 3, L3).** 검증은 "실제 실험과 같은 실험을 모델에서 했을 때 같은 결과가 나오나" 이므로, 검증에 쓰는 실행은 시나리오 `protocol` 로 실험 계획(흉내 내는 실제 실험의 출처·종·세포·조건·측정 시점, 음성 대조, 측정량, 검정력으로 정한 반복 수, 검증 관찰 목록, 허용 차이 δ, 중단 규칙)을 선언하고 `node dbtool.mjs register` 로 **실행 전에** 사전 등록부에 남긴다. 결과를 보고 예측·관찰·반복 수를 고치면 해시가 달라져 미등록이 되므로, "실행 전 선언" 을 기계가 증명한다. 규약이 없는 실행은 탐색 실행으로 판정은 하되 일치를 결론으로 쓰지 않는다.
- **운명 결과는 과정 보고서로만 보고한다.** `node dbtool.mjs fate <상태> --scenario s.json [--report 파일.md]` 가 만드는 보고서(1 요약 · 2 변곡점·시계열·구간 [기간 | 주된 원인 | 우세 표지 | 대사 비용] · 3 무결성 증명서 · 4 인과 추적 · 5 기술 부록)를 근거로 쓰고, 끝 상태만 말하지 않는다. 무결성 증명서가 FAIL(원장·재생이 어느 한 단계라도 1e-14 초과, 신호가 선언된 일정과 다름, 다시 돌린 궤적 해시가 다름, 쓰인 상수가 입력과 다름)이면 그 결과는 실패로 보고하고 결론에 쓰지 않는다. 예측은 실행 전에 시나리오 `expect` 에 적는다(입력 해시에 들어감) — 실행 뒤 바꾸지 않는다.
- 데이터 패치 절차: 초안(스크래치) → `node dbtool.mjs validate <patch.json>`(관문 미리 보기 + 정제 점검) → `node dbtool.mjs augment apply <patch.json>`(병합 + 기록 + CHANGES.md 행 + limitations.md·교과서 부록 갱신).
- **부분 구조 수지를 지킨다.** 부분이 옮겨 다니는 분자에는 `moieties` 를 달고, 변환·분해·공급 규칙의 빠진 산물(피로인산·Pi …)은 규칙과 단계(minor)에 함께 넣는다. 원료가 모델 밖이면 `source: true` — 수지 검사를 피하려고 쓰지 않는다. 반감기·공급 속도·서열 길이는 확인한 값만.

## 추적 가능한 진화 (Traceable Evolution Protocol)

추적 가능성 > 장황함. 기록은 구조화·고밀도·차등(diff)으로.
| 변경 | 기록 | 도구 |
|---|---|---|
| 데이터 패치 | 패치 최상위 `why` 필수 → `merge` 가 **Patch Report**(Scope·Why·Impact·Verification)를 계산해 출력하고 `data/patches/` 기록의 `report` 에 저장. `why` 없거나 미등록 한계 후보·새 정제 점검 문제가 있으면 **관문이** 거부(`patchPolicy` — 봉인 경계 안) | `merge`, `report <기록>` |
| 코드·형식·어휘·문서 구조 | `CHANGES.md` 맨 위에 한 행(표): Scope(파일·함수·정의항) · Why · Impact(하류 규칙·명령·데이터) · Verification(테스트 수·validate·check) | 손으로, 같은 커밋 |
| 사용자 보고 | 같은 네 칸의 표. 산문 요약 금지 | — |

- 살아 있는 문서: 구조(D·묶음·S 형식) 변경 → `SCHEMA.md`, 작업 규칙·원리 → `CLAUDE.md`, 모든 실패·unmapped·미해결 공백 → `limitations.md`(패치 `limitations` → `--write`). 문서는 전체 재작성 금지, 해당 절만 고친다.
- `unmapped` 외부 ID 도 한계다(`Identity_Gap`). `limitations --detect` 후보 0 은 병합 조건.
- 세션 시작: `docs/design/direction.md`(방향·우선순위·왜 그 순서) → 철학 문서(`authority-and-comprehension`·`tripartite-governance`·`dictionary-and-translation`·`conservation-classes`·`work-verification`) → `CHANGES.md` 위 몇 행 → `limitations.md` → `SCHEMA.md` 변경 기록 순으로 최신 방향·설계와 동기화한다. 새 세션은 이 읽기로 지금의 방향 감각에 들어온다 — 기억이 아니라 저장소가 연속성을 준다.
- 변경이 논리를 깨면 감지·수정·기록까지가 한 작업이다 (테스트·`audit-run` 로 감지, CHANGES.md 에 기록).

## 규칙·코드를 바꿀 때

- 통제 어휘(`vocab.js`)나 규칙(`model.js`·`core.js`·`judicial/`·`legislative/`)은 사용자 요청이 있을 때만 바꾼다. 데이터를 통과시키려고 규칙을 느슨하게 하지 않는다.
- 바꾼 뒤 `node dbtool.mjs validate` 가 통과해야 하고, `node --test tests/*.test.mjs` 로 회귀를 막는다. 다만 **전체를 매번 돌리지 않는다** — 테스트·시뮬레이션은 결정론적이라 변경이 닿지 않는 부분은 다시 돌려도 같은 결과이고, 재실행은 토큰·시간 낭비다(실측 실험이나 데이터값 검증을 다시 하는 것이 아니라, 내 코드 변경이 다른 동작을 깨뜨렸는지 보는 회귀 점검일 뿐이다). 그래서 **반복 중에는 바뀐 코드가 영향을 줄 수 있는 테스트 파일만** 돌리고, 전체 스위트는 **커밋 직전 1회**로 모은다. 데이터·보고서만 고쳤으면 영향 테스트 + 최종 전체 1회로 충분하다. 전체 재실행의 본래 쓸모는 **엔진·공유 기계(vocab·model·core·engine·compiler·judicial·legislative·형식)를 업데이트했을 때, 그 변경이 기존 결과를 여전히 옳게 두는지 재는 것**이다 — 이때는 반드시 전체를 돌린다. 저장소 설계(기원 봉인·델타 기록·증분 관문, build-plan 15–17)도 "전체가 아니라 바뀐 조각만 검증" 이라는 같은 원칙이다. 새 규칙에는 거부 테스트를 추가한다.
- **방어 규칙을 느슨하게 하는 변경은 래칫이 막는다 (v11, `tests/rejections.test.mjs`).** 거부되어야 하는 패치는 `tests/fixtures/rejections/` 에 기대 거부 사유(`EXPECT.json`)와 함께 둔다 — 규칙이 느슨해지면 그 패치가 통과해 버려서 빨개진다. 말뭉치 수·사법부 검사 자리 수·시험 수의 바닥값은 `tests/fixtures/FLOOR.json` 에 있고, 내려가면 실패한다. 시험을 `skip`·`todo` 로 두지 않는다(건너뛴 시험은 없는 시험이다) — 새 규칙을 더하면 말뭉치와 바닥값을 같이 올린다. 규칙을 **의도적으로** 느슨하게 하려면 바닥값을 내리는 커밋을 따로 남겨 눈에 보이게 한다.
- 형식이 바뀌면 `migrations/` 에 변환 스크립트를 추가하고 `SCHEMA.md` 변경 기록을 갱신한다.
- `index.html` 은 `viewer.html` 의 복사본이다. 화면을 고치면 둘 다 맞춘다.
- 교과서: 알고리즘·형식·상호작용을 바꾸면 `docs/textbook/` 해당 장을 같은 커밋에서 고친다. 지금 값은 손으로 쓰지 않고 `node dbtool.mjs textbook --write` 로 부록을 만든다. 파일을 더하거나 옮기면 `docs/textbook/storage-map.json` 에 분류를 적는다 — `textbook --check` 가 분류되지 않은 파일을 잡는다.

- **MCP 서버는 자원 기준으로 나누고, 권한은 입출력기 하나가 진다 (2026-10-23, `outsourcing-and-mcp.md` §4).** `mcp/query.mjs`(db·색인·원장을 메모리에 두고 읽기만 — 부팅·정규화 약 220 ms 를 호출마다 내지 않으려고) · `mcp/fetch.mjs`(공개 전문·초록만 받고 받을 때마다 `FETCH_LOG.jsonl` 사슬에 기록 — 에이전트의 말이 아니라 도구의 기록이 증거라서, 유료·PMC 무료 열람본은 저작권 때문에 받지 않음) · `mcp/clerk.mjs`(유일한 작성자: 잠금으로 하나만 뜨고, 권위 쓰기는 dbtool 명령을 불러 사법부가 다시 판정한 뒤 서기가 쓴다 — 다른 서버의 판정을 믿지 않고 로직을 두 번 쓰지 않으려고). 역할(`BIODB_ROLE`)은 기본이 가장 좁은 `collector`(핸드오프 붙이기만)이고, 목록에 없는 도구는 부르는 자리에서도 거부한다. `--allow-warnings` 는 사람 역할만. 외주화하는 것은 판단하는 에이전트이고, 받기·기록은 우리 도구가 한다. `lab` 은 엔진 경계(build-plan 56) 뒤.
