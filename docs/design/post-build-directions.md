# 포스트-빌드 방향 (Post-Build Directions)

> 이 문서는 **본 프로젝트(build-plan 1–41)가 끝난 뒤**의 방향만 담는다. **활성 작업 항목이 아니다** — `build-plan.md` 와 섞지 않는다. 지금 할 일은 여기 없다.
> 적는 이유: 그 미래를 싸게 만드는 규율(비트 결정성 · 불변 IR · 삼권 솔기)을 지금 흔들지 않기 위한 기준점.

## 1. 엔진을 효율별로 분해해 MCP 로 돌린다 (사용자 비전, 2026-10-16)

**아이디어:** 프로젝트가 끝나면 각 엔진을 효율에 맞게 분해하고 MCP(Model Context Protocol) 서버로 노출한다.

**왜 잘 맞나:** 아키텍처가 이미 준비돼 있다. 삼권 분립(행정·입법·사법·컴파일러·조정자) + 불변 IR + 원자료 JSON 스키마(FFI) = **깨끗한 타입드 솔기**. "찢는다"기보다 이미 난 솔기를 노출하는 것에 가깝다. 부수 효과로, 사법 검증기를 별도 프로세스로 떼면 "불신·검증" 모델이 **더 강해진다**(독립 프로세스가 원자료를 재검증).

**지키면 핵심(비트 결정성·신뢰)을 안 잃는 네 제약:**

1. **MCP 는 굵은 솔기에만** — `compile`(시나리오→IR) · `run`(IR→원자료) · `verify`(원자료→판결) · `report`. 뜨거운 시뮬 루프나 엔진 하나하나를 서비스로 쪼개면, "연산마다 보정은 느려서 못 쓴다"가 **네트워크 계층에서 그대로 재발**한다(JSON-RPC 왕복). 루프는 한 프로세스 안에 둔다.
2. **데이터 중력(data gravity) 배치** — 큰 원자료(궤적·격자, MB 급)를 주고받는 **수치 엔진 + 컴파일러 + 사법 검증기 + 원자료 저장소는 코로케이션**(같은 기계/프로세스 그룹, 물리적으로 가깝게). 얇은 원격 링크엔 **시나리오·판결·해시·보고서(작음)만** 흐른다.
3. **내부는 MCP-stdio(로컬, 지연 ~0), 경계만 HTTP** — MCP ≠ 네트워크. stdio/로컬 소켓이면 모듈러 인터페이스와 지역성을 **동시에** 가진다. 맨 위 솔기만 HTTP 로 원격 LLM 에 노출.
4. **경계엔 바이트가 아니라 해시/IR** — MCP 의 JSON 직렬화가 float 를 조금이라도 깎으면 비트 결정성(JS=Rust=WASM, IR 비트 동일, exactAnchor 1e-15)이 **조용히 깨진다**. 해시 참조가 바이트를 대신하고, 원격 검증은 큰 원자료 대신 **작은 IR + seed 를 받아 로컬 재실행**한다(대역폭→계산; 독립 검증이 원래 하려는 일과 동일). 데이터 왕래 비용을 이렇게 우회한다.

**분해 단위 = 신뢰 역할 + 성능 계층 (~4–5개), "엔진별" 아님:** 무거운 수치 엔진(Rust/WASM) · 조정자/컴파일러(JS) · 사법 검증기 · 입법/저장. rate·fate·field 는 IR·컴파일러·탐침 풀을 공유하므로 각각 서비스로 잘게 쪼개면 버전·지연·운영 복잡도만 는다.

## 시기·전제

- **2026-10-23 갱신**: 위 분해는 **계산 쪽**(엔진·컴파일러·검증기) 이야기다. **수집 쪽 MCP**(`query`·`fetch`, 쓰기는 모두 입출력기 `clerk` 하나)는 엔진 솔기와 무관하고 지금 병목이라 먼저 한다 — `outsourcing-and-mcp.md` §4.

- **시기:** build-plan 27–37(적분장) **이후**. 그 전엔 분해할 대상 서비스가 없다.
- **전제:** 지금 유지하는 규율(비트 결정성 · IR 해시 · 삼권 솔기 · 오차 세 채널 분리)이 그대로일 것. **이 규율이 이 분해를 공짜로 만든다** — 그래서 지금 솔기를 깨끗이 지키는 것이 이 미래의 선투자다.

## 2. 바깥으로 — 상업·지원·커리어 (생각 기록, 활성 작업 아님)

> 2026-10-16 토의 기록. 코드 작업이 아니라 "성공했을 때 이게 무엇이 되나"의 방향 메모. 바깥용 한 장 개요는 `docs/project-overview.md`.

- **상업성:** "범용 시뮬레이터"로는 안 팔린다(무료·학계 포화). **팔리는 포지션 = QSP(정량 시스템 약리) + 규제 모델 신뢰성** — 기존 도구가 가장 약한 "신뢰·감사 문서화"를 정면으로 겨냥. 해자는 코드가 아니라 **① 등급 데이터 코퍼스 ② 검증 track record ③ 방법론 평판**. 진짜 차별점은 **비트 정확 재현성 + 수치/물리/모델 오차의 구조적 분리**(희소). 수익 모양: QSP 서비스 · 규제 신뢰성 SaaS · 방법론/엔진 라이선스 · acqui-hire · 바이오-LLM 근거 기층(MCP).
- **지원(학교/연구비):** 개인 구독 요청은 낮음, **지도교수 연구비로 "이 연구 과제의 도구"** 프레이밍은 중상. 경로: PI 연구비 · 학과 재량 · 연구센터 · 도서관(SW 라이선스) · 연구전산. 현재 Claude Max 가격·학술 프로그램은 수시 변동이라 공식 페이지·학교 IT 로 확인.
- **커리어:** 씨앗이 되는 길 — 전산·시스템 생물학 연구자 · QSP/약리모델링 · 연구 소프트웨어 엔지니어 · 신뢰 가능 AI/AI-for-science · 창업. **코드가 아니라 "밖으로 나가기"(가시성·신뢰 앵커·검증된 사례 하나)가 커리어로 바꾼다.** 희소 자산은 결과물보다 **인식론적 규율**(반증 가능성·오차 분리·자기 과제를 의심하는 능력).
- **공통 병목(셋 다 같음):** 데이터 + 검증 + 가시성 + 신뢰 앵커 — 전부 **밖으로 나가야** 생긴다. "현실과 맞나 · 팔리나 · 커리어 되나"는 규모만 다른 같은 질문이고, 그 첫 단위가 TIER A 현실 검증 한 건이다.
