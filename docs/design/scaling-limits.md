# 규모 한계 — 어디가 먼저 터지나, 구조인가 하드웨어인가

> 측정일 2026-10-10 · 측정 방법: 합성 db(정의항 4k·16k·64k)를 **각각 새 프로세스**에서. 한 프로세스에서 이어 재면
> GC 압력이 `index` 를 10배로 보이게 만든다(확인 후 버림) — 규모 측정은 프로세스를 갈라야 한다.
> 재현: `node --max-old-space-size=6000 <합성 생성 + 경로별 계측>` · 메모리 비율은 `--expose-gc` 로 원본 문자열·입력 객체를 버린 뒤.

## 1. 측정한 규모 곡선

| 경로 | 4k | 16k | 64k | 지수 (16k→64k) |
|---|---|---|---|---|
| `JSON.parse` | 10 | 44 | 233 ms | 1.2 |
| `model.normalize` | 54 | 174 | 633 ms | 0.93 (선형) |
| `model.index` | 35 | 119 | 486 ms | 1.02 (선형) |
| `JSON.stringify` | 19 | 77 | 310 ms | 1.00 (선형) |
| `judicial.validate` | 50 | 356 | 1,115 ms | 0.82 |
| **`legislative.merge`** | 150 | 568 | **3,462 ms** | **1.30** |
| **`judicial.gate`** | 198 | 702 | **4,462 ms** | **1.33** |
| **`judicial.patchReport`** | 164 | 745 | **4,614 ms** | **1.31** |
| 힙 (전체) | 99 | 379 | 1,568 MB | 선형 |

메모리 표현 비율 (원본 문자열·입력 객체를 버린 뒤, 16k·64k 에서 **같음**):

| 항목 | 비율 |
|---|---|
| 정규화된 db | JSON 바이트의 **5.6배** |
| + 색인(`index`) | 합 **7.7배** |

개별 경로는 모두 선형이다. **초선형인 것은 패치 경로 하나뿐**(n^1.3) — 각 부분이 선형인데 전체 db 를 여러 번 다시 유도하고 그만큼 할당하기 때문이다.

## 2. 터지는 순서

| 순위 | 터지는 곳 | 임계 | 근거 |
|---|---|---|---|
| **1 (가장 먼저 아픔)** | 패치 한 건 = `merge` + `gate` + `patchReport` | 1만–5만에서 체감(1–3 s) · 20만에서 ~55 s · 100만에서 **~8분** (외삽) | 64k 에서 **12.5 s**, 지수 n^1.3. 데이터를 넣는 **모든** 작업이 지난다 |
| **2 (모든 명령)** | 도장 검증 `attestation.validStamps` | 20만 도장 ≈ **4분** · 200만 ≈ **40분** | 도장당 **1.2 ms** 선형. `status`·`validate`·`grade`·`attest` 가 전부 지난다 |
| **3 (절대 벽 — 멈춤)** | `readFileSync('data/db.json','utf8')` | **정의항 약 20만 개** | V8 최대 문자열 **537 MB**(`buffer.constants.MAX_STRING_LENGTH`) ÷ 정의항당 2,683 바이트. 느려지는 게 아니라 **던진다** |
| **4 (거의 같은 지점)** | 힙 | 20만 ≈ **4.9 GB** > Node 기본 한도(~4 GB) | 64k 에서 1.57 GB, 선형 |
| 5 | `attestations/registry.json` 단일 파일 | **도장 약 63만 개** | 도장당 849 바이트 → 같은 문자열 벽 |
| 6 | 수신함 파일 수 | 100만 정의항 → 200만+ 파일 | 과제당 파일 하나 · `present()` 가 과제마다 최대 4회 `existsSync`(1회 **0.7 µs**) → `augment plan` 한 번에 800만 syscall ≈ 6 s+, 한 폴더에 수백만 항목 |
| 7 | git 이력 | 패치마다 db.json 전체가 새 블롭 | 지금 .git 16 MB(545 KB × 22판 + 증거 11 MB). 100만이면 패치마다 2.7 GB |
| 8 | `viewer.html` | **2만 정의항 ≈ 54 MB** | db.json 전체를 브라우저로 보낸다 — node 보다 **10배 먼저** 쓸 수 없게 된다 |

**가장 먼저 멈추는 것은 3·4번, 정의항 15만–20만 개.** 그 전에 1번이 작업 흐름을 못 쓰게 만든다.

## 3. 구조인가 하드웨어인가

| 벽 | 판정 | 근거 |
|---|---|---|
| 20만에서 읽기가 던짐 | **순수 구조** | V8 최대 문자열은 **소프트웨어 상수**다. 1 TB RAM 기계에서도 똑같이 던진다. "db 전체가 하나의 JSON 텍스트" 라는 선택의 결과 |
| 힙 | **구조가 비율을 정하고 하드웨어가 한계를 민다** | 비율 7.7배는 구조(필드마다 객체·Map·문자열). 1M 이면 JSON 2.7 GB → 힙 **약 21 GB** — 큰 기계면 담기지만, 벽 3 을 먼저 치운 뒤의 이야기 |
| 패치 n^1.3 | **순수 구조** | 하드웨어는 상수배(CPU 2–5배)만 산다. **지수는 못 바꾼다** — 100만에서 8분이 2분이 될 뿐 |
| 도장 검증 | **하드웨어가 진짜로 사는 유일한 자리** | 도장끼리 독립이라 코어 수만큼 선형으로 나뉜다. 32코어면 200만 도장 40분 → ~75 s. (운명 엔진의 결정 탐침은 이미 이 길을 쓴다 — lanes 4 에서 1.9–2.4×) |
| 수신함 파일 수 | 구조 (+ 파일시스템) | 과제당 파일 하나라는 선택. 묶음 파일·아카이브로 바꾸면 사라진다 |
| git 블롭 | 순수 구조 | 패치마다 전체를 다시 쓰는 선택 |
| viewer | 순수 구조 | 전체를 브라우저로 보내는 선택 |

**일곱 중 여섯이 구조다.** 하드웨어가 사는 것은 상수배이고, 규모를 진짜로 사는 자리는 도장 검증 하나다.

### 그런데 그 구조는 검증 모델에서 나왔다

한계를 만든 선택들은 게으름이 아니라 **무결성을 얻는 대가**다.

| 선택 | 그 대가로 얻은 것 |
|---|---|
| db 전체가 한 파일 | 관문 봉인이 **db 전체의 sha256** 에 묶인다 — 판결을 다른 데이터에 재사용할 수 없다 |
| 캐시 대신 매번 다시 유도 | 포인터가 늘어질 자리가 없다. IR 해시·궤적 해시 재실행이 무결성 증명서가 된다 |
| 증거가 파일 하나씩 | 도장이 그 파일의 sha256 을 가리키고, 같은 확인을 다시 돌릴 수 있다 |

그래서 한계를 넘는 일은 "쪼개기" 가 아니라 **검증을 부분 단위로 다시 정의하는 일**이다. 봉인이 전체 해시 하나라면 부분만 읽을 수 없고, 부분만 읽을 수 있다면 봉인이 부분마다 있어야 한다.

| 넘으려면 바꿔야 하는 것 | 지금 | 넘은 뒤 |
|---|---|---|
| 봉인의 단위 | db 전체 sha256 하나 | 부분(구역·조각)마다 해시 + 그것들을 묶는 매니페스트 해시 (Merkle 식) — 전체 해시는 매니페스트에서 **계산**된다 |
| 읽기 | `readFileSync(utf8)` 로 전체 | 필요한 조각만 (스트리밍 파싱 또는 조각 파일) — 한 문자열을 만들지 않는다 |
| 패치 경로 | 전체를 다시 유도 | **건드린 부분만** — 도장 재검증에서 쓴 것과 같은 수법(측정 38배) |
| 도장 검증 | 한 과정에서 직렬 | 도장끼리 독립이므로 코어로 나눈다 |

## 4. 방아쇠 (언제 하는가)

쪼개기(③)를 지금 하지 않는 근거와, 해야 할 때를 가르는 수치를 함께 적는다.

| 방아쇠 | 값 | 지금 |
|---|---|---|
| 정의항 수가 **10만** 을 넘으면 | 벽 3·4 의 절반 — 남은 여유가 2배뿐 | **203** |
| 패치 한 건이 **10초** 를 넘으면 | 작업 흐름(초안 → validate → merge)이 분 단위가 된다 | 64k 에서 12.5 s, 지금 규모에서는 0.1 s 아래 |
| 도장이 **30만** 을 넘으면 | 등록부 문자열 벽(63만)의 절반 | **341** |
| 뷰어가 받는 db.json 이 **20 MB** 를 넘으면 | 화면이 먼저 못 쓰게 된다 | 0.5 MB |

넷 중 하나라도 걸리면 ③ 을 연다. 그 전에는 열지 않는다 — 지금 쪼개면 사용자 대기 시간의 1–6% 를 깎으면서 로더·`merge`·색인·모든 명령·뷰어·마이그레이션·형식 버전을 한꺼번에 건드린다.
