# 구현 계획 — 검증 · 저장 · 적분 엔진 (작업 단위 목록)

근거 설계: `integral-field-engine.md` §1–17. 이 파일은 **위에서 아래로 차례로** 실행하는 작업 목록이다. 항목마다 끝나는 조건을 통과해야 다음으로 간다.
교과서는 **같은 커밋 규칙으로 되돌림 (2026-10-15)** — 처음에는 부록을 마지막(41)에 한 번 쓰기로 했으나, 장 본문까지 밀려 빚이 커져 사용자가 결정을 맡겼고, 밀린 장(02·03·04·06·07)과 부록을 한 번에 따라잡은 뒤 이후로는 작업마다 같은 커밋에서 장과 부록(`textbook --write`)을 갱신한다.

**순서 조정 (2026-10-15, 사용자 합의)**: 12(보고서) 다음에 **12A 정성 관찰 수집**을 넣고, 15–19(조각 저장·색인·증분 관문·대량 입력·20 만 합성 db)는 뒤로 미룬다 — 정의항 211 개에서 20 만 규모 대비는 아직 쓰이지 않고, 판정 기계는 판정할 실제 관찰이 없으면 일을 하지 않는다.

**북극성 (2026-10-15, 사용자)**: 최종 목표는 **살아 있는 생명체에서 일어나는 기전을 연구하는 것** — 실제로는 전부 관측할 수 없는 것이다. 그래서 (ㄱ) 등급 붙은 **실측** 기전 데이터와 반증 가능한 판정을 **자원**으로 먼저 세우고, (ㄴ) 그 자원 위에 적분 장 엔진(공간·입자, 27–37)을 올려 소비한다. 적분 장이 다른 시뮬레이터보다 경제적·정확할 수 있는 근거는 **임의 매개변수가 아니라 이 등급 자원에 매여 있다는 것** 하나뿐이다 — 그러므로 순서(자원 먼저, 장 나중)는 취향이 아니라 그 주장이 참이 되기 위한 **조건**이다. 지금 운명·속도 상수가 전부 가상(hypothetical)인 한, 적분 장을 돌려도 "데이터에 매여 더 정확"이 성립하지 않는다. 그래서 당장의 투자는: **신뢰 기반(22·23·24·25·13) + 실측 등급 값·관찰 수집**. 적분 장(27–37)은 그 자원이 생긴 뒤.
- 분류: **신뢰 기반(지금)** 13·22·23·24·25 · **표현·사전(지금, 세션 휘발·토큰·학술 가치)** 16A · **연구 신뢰도(중기)** 38·39·40 · **규모(양이 가까워지면)** 15–19 · **공간 엔진(자원 뒤)** 20·21·27–37 · **데이터(나란히, 기반을 돌려 보며 공백을 연다)** 12·12A.

**측정·기록 인프라 점검 + 계측기 시기 결정 (2026-10-16, 사용자와 토의)**: "현실과 맞는지"가 가장 큰 걱정 → 측정 방식 freeze 가정에서 측정/기록/검증 층을 전수 점검(서브에이전트). 결론:
- **기록·검증 파이프라인은 {효소 상수·대사물 농도·정성 교란}에 대해 완성·end-to-end**(값 층 v12·등급·사전 등록 규약·TOST·정성 판정·우연 기준선 — 항목 1·3·6·8 ☑). **아무것도 안 지어도 검증 한 건을 지금 돌릴 수 있다.**
- **측정 종류 공백(스키마 변경 필요, "freeze" 가 강제하는 차단 결정)**: ① pH observable(+ pH dim·상한) ② 반응 흐름(flux) observable ③ 시계열(시간을 맥락 열쇠 밖 → 안으로) ④ 측정 방법/assay 칸(지금 자유 문자열, 독립성·맥락에 안 쓰임 — L000109). pH·농도·흐름·시계열 **연료를 본격 수집하기 전에** 결정.
- **계측기 시기(TIER)** — 사용자 제안 4종(장 수렴·도칸 오차 / 물리요동 vs 수치오차 / 체적·경계 / Sobol)을 자리매김:
  - **TIER A (지금, 안 지은 엔진 불필요)**: 현실 검증 한 건 + **가벼운 입력-귀속**(실측 상수 vs 가상 입력을 각각 흔들어 결론 J 분산의 출처 가름 — 39 Sobol 의 경량 선행, "결과가 실측 때문인가 가상 때문인가"를 정량화). 정성 Fano 는 `stoch_audit.js` 에 이미 있음.
  - **TIER B (pH·흐름·시계열 연료 직전)**: 위 측정 공백 ①–④.
  - **TIER C (불균일 적분장 27–37 과 함께, 그 전엔 아님 — 대상 엔진이 없으면 검증 장비도 공회전)**: 장 수렴·질량보존 잔여·스파크-장 경계 거래(27·29·30·31) · 배제 축 e 경계(28) · FMA 금지·카운터 난수 교차 플랫폼 비트(20·21). (농도 환산 N→M 정확 분수 접기 검증은 11 에서 완료 — 재사용.)
- **TIER A 선행조건(스키마 아님, 출처=데이터 문제)**: 검증은 사전 등록 규약을 세울 만큼 출처가 풍부한 관찰이 있어야 한다(대응 실험의 종·세포·측정 시각·음성 대조). TAP 사례는 초록에 측정 세포가 없어 규약 불가였다(L000107). → 첫 행동 = "어느 관찰이 규약을 세울 수 있는 출처인가" 점검.

**오차 관리 — 세 채널을 구조로 분리 (2026-10-16, 사용자와 합의)**: 보정이 핵심이되 **"연산마다 보정"은 느려 못 쓴다.** 세 가지 오차/변동을 **한 숫자로 섞지 않고 각각 별도 채널(별도 이름 필드)** 로 관리한다:
- **A. 수치오차 (계산값 − 수학적 정답, ①→②)**: 부동소수점·솔버 오차. **보존량**(질량·분자 수)은 정수/고정소수 원장으로 **구조상 0 — 추적이 아니라 제거**; **비보존 float**(속도·ΔG·float 농도·야코비안)는 정답이 없어 **예산으로 추적**(정체성 잔차 상대값 ΣΔG°=0·수지·미시가역성, 솔버는 허용오차 1/1000 수렴). 채널 = 사법부 수치 예산 · 결함 태그 `NUMERICAL` · 수치 선택은 `engine/coupling.js` 등록부.
- **B. 물리 요동 (실제 분자 수 변동)**: 포아송·생물 분산 — **오차가 아니라 실재 변동**. 앙상블로만 판정(`stoch_audit.js` Fano·도달 분포), 수치오차(가짜 진동)와 구별.
- **C. 실효오차율 (예측 − 보류 실측, ②→③)**: **z = (예측 − 실측)/실측 불확도**. 현실과의 거리. 채널 = 검증 판정(`obs_compare`), 쌓이면 coverage/CRPS(항목 23). 깃발: |z|≈0 계통적 → 수상하게 완벽(순환·입력 조작 의심) · |z|≫2 계통적 → DOMAIN_CONFLICT · 특정 영역만 큼 → 항목 24.
- **무누수 철칙 + 구조 분리**: A·B·C 를 합하거나 서로 대체하지 않는다. **A·B 는 생물 등급(reliability)·현실 잔차 C 에 절대 들어가지 않는다**(`NUMERICAL` 은 db 생물 상수 불변). 보정은 연산마다가 아니라 **회계 경계·배치에서 한 번**: 보존 희소 텐서 리덕션은 정수/보상 합산(Kahan)으로 집계만 정확(배치당 1회), 비보존 희소 LU(`compiler/sparse_lu.js`)는 float+예산 — **두 코드 경로를 섞지 않는다**.
- **지금 vs TIER C**: 설계는 지금 확정. **지금 가능한 구조 분리** = 검증·보고 출력이 A·B·C 를 **별도 이름 필드**로(한 "오차"로 합치지 않음) + 그 분리를 지키는 시험. **빈 강제 장치를 미리 짓지 않음**(아직 C 값이 없음 — 북극성). **TIER C(엔진과 함께)** = 정수 장·배치 보상 리덕션 코드 경로(27·희소 텐서), 장 수렴 계측(29·30·31).
- **보존 분류를 기저 데이터로 (2026-10-16, 사용자 — "희소 텐서 고정소수점" 제안에서 귀결)**: 양을 **conserved**(보존 법칙 존재·목표 오차 0)/**non_conserved**(법칙 없음·예산으로만)로 가르고 **원인**을 통제 어휘(`vocab.conservationClasses`·`conservationReasons`)로 못박아, 사전 register(16A)로 노출. **범용 BigInt 고정소수점은 반려** — float 는 봉인을 안 깸(봉인=정준 데이터·판결 해시, 비트동일은 20·21), 비보존을 '정확히' 표현하려는 건 거짓 정밀도·속도·패러다임(두 경로 혼합 금지) 범주 오류. class 는 표현 독립(정수 원장 정확-0 이든 Rodas3 상대 1e-14 든 같은 class). **지금 = 데이터·원리만**(강제 미리 안 지음), **강제는 TIER C**(보존 양이 float 경로로 새면 거부·NUMERICAL 라우팅이 class 참조·27 정수 장이 분기). 설계 `conservation-classes.md`.
**작업 검증·꼼수 방지 (2026-10-17, 사용자 — 설계만, 미구현)**: AI 자기보고를 실행 증거로 인정하지 않기. 조사 결론 — 쓰기 측은 관문·도장·사전등록·해시사슬 로그로 **이미 강제**, **조사·수집 측이 구멍**(자기보고 인정, TASK-001 표본). 핵심: 작업자 과정을 검증하려 말고 **통합가가 결과를 터미널에서 독립 재-도출**(엔진 사법 원리). 두 레지스터 — 결정론 행동=전수 재실행 대조(싸다)·외부 웹 행동=표본 재-fetch+REVIEW_REQUIRED(비싸다·사람). 엔진 해시사슬 형식을 실행 테이프로 재사용(#10 탐지)하되 **도구 런타임이 써야** 하고 재생 검증은 결정론만(미확인: harness transcript 소비 가능 여부). 상태 어휘는 `identity.js` verdict 재사용 → PASS/INCOMPLETE/BLOCKED/REJECTED/REVIEW_REQUIRED. 못 막는 것(정직): #1 커버리지·#5·#6 내용 진실·외부 과정 → 사람/통합가. 최소 구현 `judicial/collection_audit.js`(결정론 전수 + 외부 표본 + 나머지 REVIEW, 거부 픽스처). 설계 `work-verification.md`.<br>2026-10-17 ②: **1차 구현** — `judicial/collection_audit.js` + `dbtool verify-collection <핸드오프.jsonl>`: 구조·구별·출처 형식·근거 없는 값·상태 내용 불일치·재사용 db 존재/철회 검사 → PASS/INCOMPLETE/BLOCKED/REJECTED/REVIEW_REQUIRED(값 후보 자동 PASS 금지). 거부 시험 `tests/collection_audit.test.mjs`(7). **남음**: 실행 테이프 해시 사슬(harness 도구 로그 소비)·외부 재-fetch 자동화.<br>2026-10-17 ③: **#2·#1 추가** — 출처 해석 순수 판정 훅 `sourceChecks`(notfound→REJECTED·error→REVIEW), 단 **실제 해석·받기는 sanctioned 고리**(`augment fetch`/수신함)로 — dbtool 네트워크 직접 금지(governance ①). `verify-run <transcript> --handoff`(서브에이전트 실제 도구 호출 vs 주장 대조, 값·읽음인데 열람 0 깃발 — TASK-001 transcript 로 WebFetch3·WebSearch3·Read4 추출 확인). **한계**: 실행 기록은 내 세션 서브에이전트 한정·harness 내부 형식(best-effort), 외부 작업자·인용 원문 대조·해시 사슬 테이프·받기 고리 배선은 미구현. 테스트 7→9.
