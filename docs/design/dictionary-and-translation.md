# 사전·번역기 — 기계어 ↔ 사람말 (표현 층 1급화)

> 기계가 읽고 쓰는 **정준어**(ID·통제 토큰·구조 레코드)와 사람이 읽는 **자연어** 사이를, 흩어진 채로 이미
> 하는 번역을 **하나의 검증된 사전 + 번역기**로 승격한다. 핵심 한 줄: **번역기는 조회(lookup)하지 추론
> (infer)하지 않는다.** 기원: 2026-10-16 토의 — "너가 보기 쉬운 기계어로 쓰고, 사전으로 스스로 번역"
> → "영어·한국어 병기, 중심부는 영어" → "의미도 영어로" → "수만 단어 쌓이면 SQL?".
> 아직 **설계 단계**(코드 착수 전). 이 문서는 합의를 세션 휘발 전에 못박는다.

## 0. 왜 — 문제·동기

- **세션 휘발 + 토큰.** 산문 설명은 세션을 넘겨 다시 읽기 비싸고, compaction 에 약하다. 압축된 기계 레코드는
  살아남고 싸다. 효율 이득은 거의 전부 여기서 나온다.
- **수만 단어로 성장.** 정의항·관찰·한계·사전 항목이 수만 규모로 자란다 — 산문 중심이면 유지·질의 불가능.
- **학술 가치.** 중심부(키·용어 정의)가 **영어이고 외부 온톨로지에 대조**되면 인용·재현 가능해진다.

## 1. 현황 — 이미 뼈대다 (greenfield 아님)

| 조각 | 지금 있는 것 | 증거 |
|---|---|---|
| **사전** | `{label·aliases·note}` = 기계 키 ↔ 사람말 | `vocab.js` 전 항목 (예: `:288–294` gap 타입) |
| **키(정준 신원)** | **이미 영어·불변** (`Kinetic_Gap`·`FINDING`·D000113) | `vocab.js`·`judicial/fault.js` |
| **번역기 원형** | D번호 → 사람 글 | `core.js` mapText·contextText·mechanismText·patternText |
| **보고서 번역기** | 원본 JSON → 마크다운 (+SVG 예정) | `judicial/evidence_report.js` (build-plan 12) |
| **표현 층** | 번호 → 화면 | `viewer.html`=`index.html` |
| **관문 강제** | 미등록 통제 토큰 거부 | gap 타입·fault 채널이 통제 어휘로 등록됨 |

→ 할 일은 **흩어진 사전·번역기·뷰를 하나의 1급·통합·검증된 시스템으로 승격**하는 것.
보고서 번역기(12)는 이 번역기의 **특수 사례** — 사전·번역기가 그것을 일반화한다.

## 2. 두 레지스터 — 무엇이 번역되는가

번역 대상은 두 종류이고, 섞으면 안 된다.

| | **R1 — 통제어 (열거 가능)** | **R2 — 추론 서술 (자유어)** |
|---|---|---|
| 예 | D/T/S/O/L 번호 · gap 타입 · fault 채널 · symptom 키 · observable · expect 어휘 | 왜 · 근거 · 지문 · 인과 이야기 · 1차 문헌 해석 |
| 사전이 할 수 있나 | **완벽히** — 키 → 라벨/의미 순수 테이블 조회 | **못 한다** — 토큰에 없는 정보를 담음 |
| 번역 성질 | **결정론·감사 가능** (같은 레코드 → 같은 글, 비트 안정) | 원문 **통과(pass-through)**, 생성 아님 |
| 효율 이득 | **여기서 거의 다 나옴** | — |

## 3. 핵심 규칙 — 번역기는 조회하지 추론하지 않는다

R2 를 토큰에서 **생성**하려 들면, 토큰에 없는 근거·추론을 **환각으로 메운다** → 이 프로젝트가 지키는 것
(근거·지문·1차 출처)이 가짜로 대체된다. 그래서:

- **R1**: 번역기가 사전을 **조회**해 사람 글을 만든다 (결정론·검증 — 비트정확·사법 재검증 철학과 정합).
- **R2**: 한 번 사람이(근거 달아) 쓰고 **그대로 저장**, 번역기는 **원문을 통째로 끼워 넣기만** 한다 (생성 금지).

이 한 줄이 번역을 **생성형(믿어줘)이 아니라 사법적(검증됨)** 으로 만든다. vocab.js 가 미등록 토큰을 관문에서
거부하듯, **사전 자체가 데이터이고 관문이 지킨다.**

## 4. 사전 항목 정준 형태

```
{ key,                 // 영어, 불변, 정준 신원 (이미 그러함)
  label_en, label_ko,  // 병기 — 번역 테이블 한 자리에만 (레코드마다 손으로 쓰지 않음)
  meaning_en,          // 통제 용어의 의미: 영어 정준 (외부 표준 대조 or 우리가 신중 저술)
  meaning_ko,          // 읽기 글로스
  xref,                // 외부 온톨로지 (UniProt·ChEBI·GO·MeSH) — meaning_en 검증 앵커
  aliases[], since }   // 이명·버전 (라벨이 바뀌어도 옛 레코드가 번역되게)
```

- 버전(`since`)·이동(`moved`)·철회(`retracted`) 규율을 **사전 항목에도** 적용한다 (값 층과 같은 불변 기록).
- 병기는 **이 한 자리**에만 산다. 번역기가 청중에 따라 `ko`·`en`·`en (ko)` 를 골라 렌더 — "한 소스, 여러 뷰".

## 5. 언어 정책 — 라벨·의미 두 층 모두

전제: "한글이 고맥락이라 불완전"보다 더 단단한 이유는 — **용어(terms of art)는 전 세계가 공유하는 단 하나의
지시 대상이 필요하고, 과학에서 그 지시체는 영어로 유지된다.** 한자병기가 "정확한 지시는 한자·읽기는 한글"
이었던 그 구조 그대로, **한자 자리에 검증된 영어**를 둔다.

| 대상 | 정준 언어 | 근거 |
|---|---|---|
| 키 (정준 신원) | **영어·불변** | 이미 그렇고, 외부 온톨로지·인용에 붙음 |
| 사전 라벨 | **병기 (en 검증 + ko)** | 번역 테이블의 자연스런 자리 |
| 통제 용어의 **의미** | **영어 정준** — 외부 표준 **대조**, 없으면(우리 고유 개념) 우리가 **신중 저술** · 한글 글로스 | 용어 모호성 제거 = 학술 가치 |
| 과학 D항의 의미 | 외부 온톨로지 영어에 **정렬**(저술 아님) · 한글 파생 | 정의의 권위가 외부에 있음 |
| 추론 서술(R2) · CLAUDE.md · 교과서 · 내부 문서 | **한글/병기 그대로** | 뉘앙스·인과가 사는 곳, 영어화는 비용뿐 |
| 형식 주장 · 프로토콜 질문 · 논문 대면 보고 | **영어(병기 가능)** | 리뷰어가 읽는 면 |

**영어의 가치는 느낌이 아니라 검증.** 외부 온톨로지에 대조되거나 우리가 표준 제정 주체일 때만 값이 있다.
**자유 작문 영어는 한글과 신뢰 차이가 없다** — 지어낸 영어는 안 된다(키처럼 번역도 검증된 것만).

## 6. 저장·규모 — 권위는 정준 텍스트, SQL 은 파생

수만 단어 규모에서도 **권위(source of truth)는 정준 직렬화 텍스트로 유지한다.** 신뢰 전체가 거기 걸려 있다:

- `legislative/clerk.mjs:28` `serialize = JSON.stringify(db, null, 2)+'\n'` · `:65` `sha(text)≠db_sha256 → 거부`.
  봉인·git diff·결정론·사법 재검증이 **정준 JSON 직렬화 + sha256** 에 매여 있다.
- **SQL(SQLite)을 권위로 삼으면 이 봉인이 깨진다.** 그래서 **build-plan 16**은 SQLite 를 **파생 색인**
  (`node:sqlite`, "색인 삭제 후 재생성 동일")으로 둔다 — 질의 속도용 캐시이지 권위가 아니다.
- **사전은 자체 JSONL** 후보 (`data/preregistrations.jsonl`·`data/log/events.jsonl` 선례 — 추가·줄diff 친화).
  수만 항목도 JSON/JSONL 로 감당(지금 db.json 660K/22,751줄). 규모 검증은 **build-plan 19**(20만 합성 db).

한 줄: **정준 텍스트 = 권위(봉인·감사) · SQLite 색인(16) = 파생 질의 · 뷰어(19) = 렌더.** 셋을 섞지 않는다.

### 6′. 색인·비용 실측 (2026-10-16, `tests/bench_index.js`)

"효율 그대로는 못 간다"는 우려를 직감이 아니라 숫자로. 지금은 매 콜드 명령이 db.json 을 통째 읽어
`JSON.parse → normalize → index(db)` 를 다시 한다 (O(전체 db)). 합성 N× 로 곡선을 떴다:

| 규모 | senses | 크기 | parse+index | normalize(1회) | 조회 |
|---|---|---|---|---|---|
| 지금(1×) | 212 | 0.66 MB | **4.1 ms** | 16.9 ms | 1.7 µs |
| 10× | 2,120 | 2.7 MB | 24.8 ms | — | (규모 무관) |
| 50× | 10,600 | 13 MB | 126.7 ms | — | — |
| 외삽 문턱 | **≈16,800** | **≈51 MB** | **200 ms** | — | — |

읽어낸 것:
- **지금 아무것도 안 박살난다** (4.1 ms). 영속 색인은 이 규모에선 오버헤드가 안 갚아짐 — **전체 파싱이 최적.
  색인 계층(15–19)을 지금 켜면 오히려 느려진다** → 측정 문턱으로 게이트하는 결정이 숫자로 옳다.
- parse ≈ index ≈ **50:50** → 영속 색인(파생·sha 도장)이 약 절반, 오프셋/샤딩(건드린 것만)이 파싱 대부분을 되돌린다.
- **`normalize` 가 숨은 범인** (16.9 ms > parse+index). O(n)·매 `loadDB()`. 규모에서 지배적 → 색인 계층 켤 때 함께 본다.
- **진짜 가드**: 수만으로 빨리 자라는 건 **사전**인데, 핫패스 monolith(db.json)에 넣으면 매 명령 고정 비용을
  문턱으로 끌어올린다. 그래서 **사전은 자체 JSONL + 자체 지연 색인**이어야 한다(§6 결정을 실측이 확증).
- **문턱 트리거**: `tests/bench_index.js` 로 parse+index(+normalize)가 ~200 ms 를 넘기 전에 색인 계층 착수.

## 7. 번역기 설계

- 단일 진입 `translate(record, {audience}) → markdown` : R1 토큰은 사전 조회, R2 필드는 원문 통과.
- `core.js` 의 mapText·contextText·mechanismText 를 이 뒤로 모은다 (**군더더기 금지** — 중복 번역 경로 제거).
- 읽기·표현만 (행정/사법 권한 밖). 쓰기·판정 없음.

## 8. 방어 테스트 (실패 모드를 막는 것)

1. **R1 왕복**: 기계 레코드 → 사람 글 → (재파싱) → 기계 레코드 **동일**.
2. **R2 통과**: 저장 원문 → 렌더 출력 **바이트 동일** (모델 생성이 아님을 증명).
3. **미등록 토큰 거부**: 사전에 없는 키 → 관문 거부 픽스처 (`tests/fixtures/rejections/` + `EXPECT.json`).

## 9. 범위·비용 (정직하게)

- **고레버리지 영어 면은 작다**: 통제 용어 **수십 개**(gap 8 · fault 6 · observable 6 · expect · 기타) — 수천 아님.
  과학 D항은 **저술이 아니라 외부 정렬**이라 새로 영어로 쓸 게 아니다.
- **뼈대 빌드 = 중간 규모**, 반경 `vocab`·`core`·`viewer`·`dbtool`.
- **하지 말 것**: 한계 115개·db 서술문을 **영어로 일괄 이관 금지**(반경 크고 신뢰 이득 작음) · 병기를 레코드마다
  손으로 뿌리지 않음(drift).

## 10. 위에 얹히는 것 (순서)

이 사전+번역기가 **상위 뼈대**다. 그 위에 매달리는 것:

- **가(Gap) 스키마 구조 필드**: `symptom`(정량 key-value) · `downstream_blocked`(D목록) · `resolution_trigger`
  (통제 키). 한계의 `requirement.text` 설명문은 **남기고**(R2 = 지문·근거), 구조 필드를 **추가**한다. `resolution_trigger`
  만 `limitations --detect` 에 배선(재검토 가능 한계 자동 표면화). `prohibited_bypasses` 는 **저장만**, 관문 강제
  보류(의도 탐지 불가 — 진짜 탐지기 생기기 전엔 문서로서만).
- **보고서 렌더러(12)** 가 이 번역기 위에서 일반화된다.

## 11. 단계

1. **뼈대**: 사전 항목 정준 형태 + 단일 번역기 + 방어 테스트 3종. core.js 조각 통합.
2. **가 스키마 구조 필드** 를 뼈대 위에 (`symptom`·`downstream_blocked`·`resolution_trigger`).
3. **이관은 점진** — 새 레코드부터 적용, 기존은 닿을 때. 일괄 이관 금지.
4. (규모가 가까워지면) SQLite 색인(16)·뷰어 조각(19) 와 합류.

## 12. 지문

- **이미 하던 것을 못박는 일.** 번역·사전·뷰는 흩어진 채 이미 돈다 — 새로 만드는 게 아니라 **1급·검증**으로 올린다.
- **lookup-not-infer 가 전부를 가른다.** 번역을 생성이 아니라 사법적 조회로 두는 한 줄이, 이 프로젝트의 신뢰
  철학을 **프로젝트 자신의 문서에까지** 적용한다.
- **영어는 검증될 때만 가치.** 중심부를 영어로 두는 이유는 "학술적 느낌"이 아니라 **외부 온톨로지 대조로
  검증 가능**해지기 때문. 자유 작문 영어는 한글과 다를 바 없다.
