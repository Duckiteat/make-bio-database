# 외주화와 MCP 분리 — 무엇을 밖에 맡기고, 무엇을 안에 두나 (설계, 2026-10-23)

> 사용자 결정(2026-10-23): 전문 받기를 맡을 에이전트를 사용자가 따로 만든다. 외주화가 가능한 부분은 전체적으로 외주화한다. 이 문서는 그 경계를 정한다.
> 근거 문서: `docs/PROMPTS.md` §3·§3′(다른 AI·수집가·통합가), `work-verification.md`(자기 보고 불인정), `tripartite-governance.md`, `direction.md` §5(자동화 궤적), `post-build-directions.md` §1(MCP 분해 네 제약), `structure-realignment.md`(7부).

## 0. 한 줄 원칙

**만드는 일은 외주화하고, 판정하는 일과 쓰는 일은 안에 둔다.** 밖에서 온 것은 모두 신뢰하지 않는 입력이다. 그런 입력이 들어오는 문은 셋뿐이다 — **수신함**(`data/fetched/`, 원본 그대로), **핸드오프**(`workspace/handoff/`, 후보), **관문**(패치·원장 추가, 봉인 뒤 서기). 문을 지나면서 안쪽이 독립으로 다시 확인한다. 이 규칙이 있어서 외주화가 안전하다(direction §5: "검증 척추가 자동화를 안전하게 만든다").

## 1. 왜 지금

| 무엇 | 근거 |
|---|---|
| 정량 수집이 매번 "전문 필요"에서 멈췄다 | TNF mRNA(TASK-001), IκBα, 텔로미어(TASK-004) 셋 다. 수신함이 초록만 받기 때문이다. IκBα 후보 8편 중 공개 전문(XML) 1편, PMC 무료 열람 4편이 있었는데 읽지 않았다. 그중 O'Dea 2007(PMC2673708, 공개)에는 "free IκB half-lives 5–10 min"(생쥐 MEF)이 있었다 |
| 사람과 통합가의 시간이 병목이다 | 자동결정률 임계 아래에서는 사실마다 사람이나 Opus가 확인한다(direction §1). 수집·받기·초안을 밖에 맡겨야 통합가가 판정에만 쓴다 |
| 실행 기록을 도구가 써야 한다 | work-verification 의 남은 일: "실행 테이프는 도구 런타임이 써야 하고, 하네스 기록은 best-effort". MCP 도구는 자기 호출을 스스로 기록할 수 있어서 이 공백이 닫힌다 |

## 4. MCP 분리 — 효율 기준 (2026-10-23 측정)

### 4.1 잰 값 (이 컨테이너, 4 코어)

| 무엇 | 값 | 뜻 |
|---|---|---|
| Node 부팅 (`node -e 0`) | 174 ms | CLI 호출마다 낸다 |
| db 정규화 + 색인 | 45 + 7 ms | 호출마다 다시 한다 |
| 조회 명령 (`map`·`assume uses`) | 146–190 ms | 거의 전부 부팅·정규화 비용 |
| `status` · `attest` | 766 · 1 121 ms | 증명 도장 재검증이 대부분 — db 가 같으면 결과도 같다 |
| `validate` | 641 ms | |
| 운명 실행 1회 (텔로미어) | 64–77 ms, IR 5.8 KB → 원자료 **690 KB** (120 배) | 원자료가 입력보다 훨씬 크다 |
| 확률 앙상블 50회 | 출생–사멸 2.4 s (원자료 회당 0.49 MB) · 혼합 최적 **26.9 s (회당 5.9 MB → 약 290 MB)** | 길고 무겁다 |
| 일괄 보고 | `evidence --all` 5.4 s · `origin --all` 2.7 s | 묶음 작업 |
| Europe PMC 받기 | 검색 0.8 s · 전문 XML 1.9 s | 네트워크가 정한다, CPU 는 놂 |

### 4.2 나누는 기준 다섯

1. **상태**: db·색인·원장을 메모리에 두면 호출마다 약 220 ms(부팅 + 정규화·색인)가 빠진다 → 조회는 **오래 사는 서버 하나**에.
2. **자원의 종류**: 받기는 네트워크 대기(초 단위, CPU 0), 실행은 CPU(코어 전부) → **같은 프로세스에 두지 않는다**. 받기가 실행 대기열을 막거나 실행이 받기를 굶기지 않게.
3. **데이터 중력**: 원자료는 입력의 120 배이고 앙상블은 수백 MB → 실행과 검증은 **같은 기계**에, 밖으로는 판결·해시·요약(수 KB)만. post-build §1 ②·④ 그대로다.
4. **권한**: 권위 쓰기는 **단일 작성자** 하나, 수집 에이전트에는 보이지도 않게.
5. **무효화 열쇠 하나**: db sha256 + 가정·사전·사전 등록 원장 head. 작성자가 바꾸면 다른 서버는 다음 호출에서 다시 읽는다(664 KB sha 는 ms 단위). 도장 재검증 결과도 이 열쇠로 캐시한다.

### 4.3 구조 — 서버 셋 + 입출력기 하나 (2026-10-23 사용자 결정: 권한별로 서버를 나누지 않는다)

서버는 **자원 기준**(메모리·네트워크·CPU)으로만 나눈다. 권한은 서버가 아니라 **입출력기 `clerk`** 가 진다. 쓰기는 누가 하든 `clerk` 하나를 지난다 — 지금 저장소의 `clerk.put(구역, 파일)` 을 프로세스로 굳힌 것이다.

| 이름 | 한 줄 역할 | 하는 일 (도구) | 기다리는 것 | 쓰기 | 개수 |
|---|---|---|---|---|---|
| **`clerk`** (입출력기) | 저장소를 바꾸는 유일한 문 | 호출자 역할 확인 → 구역 확인 → **사법부 판정을 스스로 다시 돌림**(관문·봉인·원장 감사 — 다른 서버가 만든 봉인을 믿지 않는다) → 줄을 세워 하나씩 쓰기 → 새 무효화 열쇠 알림. 도구: apply_patch · register · assume_add · dictionary_add · attest · put_inbox · put_handoff · put_report | 거의 없음 (쓰기는 드묾) | **유일하게 운영체제 쓰기 권한을 가짐** | **정확히 1** — 해시 사슬은 순서가 하나 |
| **`query`** | 메모리에 띄운 저장소를 읽는 창구 | db·색인·원장·도장 결과를 메모리에 두고 조회(map·context·limitations·coverage·origin·assume uses·qualgraph…) · 후보 판정(verify-collection) · 보고서 **글** 생성(파일은 `clerk` 가 씀) | 메모리 | 없음 (저장소 읽기 전용) | 1 → 동시 호출 수에 따라 늘림 |
| **`fetch`** | 바깥 원천과 말하는 창구 | 공개 여부 판정 · 공개 전문·초록·DB 원본 받기 · 받기 기록 작성. 받은 원본은 `clerk.put_inbox` 로 | 네트워크 | 없음 (`clerk` 를 거침) | **1** — 상한은 상대 서버의 속도 제한. 안에서 비동기 동시 요청 + 원천별 제한 |
| **`lab`** | 계산과 검증의 작업장 | 컴파일 → 실행 → 사법부 검증 → 판결. 긴 일은 작업 대기열(제출 → 번호 → 상태 → 판결). 앞문은 조정자, 엔진 워커와 검증기는 같은 기계의 다른 프로세스 | CPU | 내용 주소 캐시만(아래) | 기계당 1, 워커 = 코어 − 1 (이 컨테이너 3) |

**`clerk` 를 따로 떨어진 프로세스로 두는 이유**: 외부 입력을 받는 서버 안에 검사 코드가 있으면 그 서버의 버그 하나가 우회로가 된다. 쓰기 권한을 운영체제 수준에서 `clerk` 만 가지면 우회할 코드 경로가 없다 — 신뢰가 아니라 구조로 막는다(PROMPTS §3′ B). 쓰기가 드물고 작아서(8일간 병합 26건) 따로 둬도 효율 손해가 없다.

**노출은 역할로 거른다**: 서버를 나누지 않고, 호출자 역할(수집가·통합가·사람)의 토큰에 따라 보이는 도구 목록을 거른다. `clerk` 는 요청마다 역할을 다시 확인한다 — 수집가 역할은 put_inbox·put_handoff 만, 권위 쓰기는 통합가·사람만.

**예외 하나 — `lab` 의 원자료 캐시**: 원자료는 수백 MB 라 `clerk` 를 지나면 데이터 중력(기준 3)이 깨진다. 그래서 `lab` 이 자기 기계의 **내용 주소 캐시**(파일 이름 = 내용의 sha256)에 직접 쓴다. 이름이 곧 해시라 위조하면 읽을 때 드러나고, 저장소의 사실이 아니라 언제든 다시 계산할 수 있는 파생물이다. 판결(작음)은 `clerk.put_report` 로 저장소에 남긴다.

**무효화 열쇠**: db sha256 + 가정·사전·사전 등록 원장 head. `clerk` 가 쓴 뒤 새 열쇠를 알리고, `query`·`lab` 은 다음 호출에서 열쇠가 다르면 다시 읽는다.

### 4.4 에이전트와 도구를 가른다 — 외주화의 효율 핵심

**외주화할 것은 "판단하는 머리"(무엇을 찾고, 무엇을 읽고, 무엇이 후보인가)이고, 실제 받기·기록은 우리 `fetch` 도구가 한다.** 외부 에이전트가 직접 받아서 파일을 넘겨주면, 그 파일이 진짜 그 URL 에서 왔는지 다시 받아 확인해야 한다(work-verification: 외부 행동은 표본 재-fetch — 비싸다). 받기를 우리 도구가 하면 받기 기록이 곧 증거라서 재확인이 필요 없다. 그래서:

- 사용자가 만드는 전문 에이전트 = `fetch`·`query` 도구를 부르는 클라이언트(역할: 수집가). 에이전트 안에 HTTP 코드를 두지 않는다.
- 에이전트가 쓰는 모델·위치는 자유(외주). 서버 셋과 `clerk` 는 저장소 곁(우리).

### 4.5 더 쪼개지 않는 이유

- 엔진마다(rate·fate·field) 서버를 두지 않는다 — IR·컴파일러·탐침 풀을 공유하고, 쪼개면 원자료가 프로세스 사이를 오간다(post-build §1 ①).
- 사법부 모듈마다 서버를 두지 않는다 — 판정 하나가 여러 모듈을 같은 원자료 위에서 부른다.
- `query` 와 `fetch` 는 합치지 않는다 — 기다리는 것이 다르다(메모리 대 네트워크). 둘 다 쓰기 권한이 없으므로 권한 때문에 나눈 것은 아니다.
- 권한 때문에 서버를 나누지 않는다 — 권한은 `clerk` 가 진다.

| 데이터 | 크기 | 판단 | 이유 |
|---|---|---|---|
| 사실 db `data/db.json` | 664 KB (정의항 212) | **나누지 않음** — `clerk`·`query` 가 메모리 사본을 듦(복사이지 나누기가 아님) | 번호로 서로를 가리키는 그래프라 관문 검사가 전체를 한 번에 본다. 쪼개기(15–19)는 정의항 약 1만 근처에서(`scaling-limits.md`) |
| 원장(가정·사전·사전 등록·로그) | 187 · 45 · 3 · 684 KB | **나누지 않음** — db 곁 | 추가만 하는 작은 사슬, db 와 같은 무효화 열쇠로 함께 바뀜 |
| **수신함 `data/fetched/`** | **14 MB**(db 의 20 배, git 에 있음 · uniprot 5.8 · consensus 6.5) | **나중에 떼어 냄** — 원본은 git 밖 **내용 주소 저장소**(이름 = sha256), 저장소에는 해시·받기 기록만 | 가장 빨리 자란다: 공개 전문 XML 한 편 약 68 KB → 1 000 편 68 MB · 1 만 편 680 MB. 한 번 쓰면 바뀌지 않으므로 해시로 이어도 연결이 약해지지 않는다. **시기: 전문 에이전트를 붙일 때** |
| 원자료 캐시 | 앙상블 하나 약 290 MB | 이미 떨어져 있음 — `lab` 기계에만 | 다시 계산할 수 있는 파생물(§4.3 예외) |
| 보고서·파생 문서 | 136 KB | 나누지 않음 | 사람이 읽는 기록, git 에 |

요약: 엔진과 db 는 크지만 서로 얽혀서 붙여 두고, 수신함은 크고 혼자 자라서 뗀다.

## 5. 전문 에이전트 명세 (사용자가 만들 것)

| 항목 | 내용 |
|---|---|
| 입력 | 과제 목록: PMID(또는 PMCID) · 무엇을 찾나(한계 L… 의 needs, 측정량·단위·종·세포) |
| 1. 공개 여부 | Europe PMC 조회 — `isOpenAccess`·`inPMC`·`pmcid` |
| 2. 공개 전문(OA=Y) | `fetch` 도구의 `fetch_fulltext` 를 부른다 — 도구가 `fullTextXML` 원본을 수신함 `data/fetched/europepmc/PMC-<id>.xml` 에 넣고 받기 기록을 남긴다. **에이전트 안에 HTTP 코드를 두지 않는다**(§4.4) |
| 3. PMC 무료 열람(OA=N, inPMC=Y) | **본문을 저장하지 않는다**(저작권). 읽고 찾은 문장만 인용으로, 원본은 sha256 만 |
| 4. 유료 | 받지 않는다. `RETRIEVAL_TASKS.md` 후보로 남겨 사람이 받아 올린다. **로그인이 필요한 곳(학교 계정 등)은 쓰지 않는다** — 하나의 예외: BRENDA 는 `fetch` 의 `brenda_kinetics`(계정은 환경 변수, 2026-10-25) |
| 출력 | 핸드오프 `.jsonl` 후보 — 값·단위·종·세포·불확도·반복 수 · 출처(PMID·PMCID) · **원문 인용 + 위치**(XML 절·표·그림 번호) · 접근 상태(OA·free·paywalled) · 받기 기록 |
| 금지 | db·원장·패치 쓰기 · 커밋 · 값 추정·환산(원문 숫자 그대로) · 그림에서 눈으로 읽은 값을 원문 숫자로 적기(적으면 "그림 전사"로 표시) |
| 성공 판정 | 에이전트의 보고가 아니라 **수신함 파일 + 받기 기록 + 인용–전문 자동 대조** |
