# 구조 재편 — 가정·판정·측정법을 1급으로 (설계, 미구현)

> 2026-10-23 사용자와 토의해 합의한 설계다. 할 일 목록과 상태는 `build-plan.md` 7부(49–57)에 있다. 이 문서는 **왜 그렇게 하는지**와 **무엇을 만드는지**를 적는다.
> 출발점은 토의 주제 넷이다. ① 검증 5번째와 순환 차단 ② 꼼수 방지 필드가 실제로 쓰이는 정도 ③ 차이 기원 분류(4축) ④ 열린 질문(C/D 분리, 철회 파급 범위, 재검토 감지). 여기에 "구조 전체를 계획 문서와 대조하고 저장 컨셉까지 점검하자"는 요청이 더해졌다.

## 0. 한 줄 요약

검증 기계는 촘촘하다. 그런데 **"맞음"이 실측 덕인지 우리가 정한 가상 숫자 덕인지 시스템이 구분하지 못한다.** 원인은 저장 컨셉의 가장자리다. 저장소는 **아는 것**(T·D·S·O·V·L)은 번호와 출처를 붙여 담는다. 반면 **가정한 것**, **판정한 것**, **어떻게 쟀는지**는 1급 기록으로 담지 않는다. 셋 다 북극성이 직접 재려는 것이다. 그래서 이 셋을 기록으로 세우고, 그 위에 입력 귀속(TIER A)과 불일치 원인 분류(24번)를 올린다.

## 1. 대조 기준 — 북극성 두 문장

- build-plan: "적분 장이 다른 시뮬레이터보다 나을 근거는 **임의 매개변수가 아니라 등급 자원에 매여 있다는 것** 하나뿐이다."
- direction: "현실 검증 — 시뮬레이션이 현실 위에서 기능한다." 방향값은 **자동결정률**(새 데이터 가운데 사람 없이 기계가 결정하는 비율)이다. 지배 원칙은 "검증이 능력을 gate 한다"이다.

아래 모든 항목은 이 두 문장에 무엇을 보태는지로 순서를 정했다(§9).

## 3. ① 가정 원장 `data/assumptions.jsonl` (G1·G4)

### 3.1 원칙

- **사실과 가정을 계속 분리한다.** db.json 에는 여전히 확인된 값만 둔다(CLAUDE.md "미확인 값 금지" 유지). 가정은 db 밖의 별도 원장에 둔다. 가정을 db 값으로 승격하는 길은 관찰(O…)을 거치는 것 하나뿐이다.
- **가정에 신원을 준다.** 가정 값 하나에 번호 `A…` 하나를 준다. 같은 숫자를 쓰는 시나리오 12개는 같은 `A…` 를 가리킨다.
- **기록은 바꾸지 않는다.** 사전(`dictionary.jsonl`)과 같은 추가 전용 해시 사슬로 쌓는다(seq·at·prev·root). 고칠 때는 새 번호가 옛 번호를 `revises` 한다. 옛 번호는 그대로 남으므로 그것을 가리키는 등록은 깨지지 않는다.

### 3.2 기록 모양

```json
{ "seq": 1, "at": "…", "id": "A000001",
  "slot": { "kind": "kinetics", "ref": "D000207/rule/turnover", "param": "half_life" },
  "value": 1200, "unit": "s",
  "origin": "assumed",
  "limitation": "L0000xx",
  "basis": "왜 이 숫자인가 — 한 문장 (모르면 '기록 없음')",
  "range": { "low": 300, "high": 4800 },
  "revises": null, "prev": "…", "root": "…" }
```

- `slot.kind`: `kinetics`·`amounts`·`thresholds`·`signals`·`buffered`·`volumes`·`stoichiometry`. 첫 장면 기원 감사(`judicial/scene_origin.js`)의 입력 종류와 같은 표다.
- `origin`: `abstracted`·`assumed`·`unrecorded`(scene_origin 분류 재사용). `measured` 는 원장에 없다 — 측정값은 db 의 값(V…)이다.
- `range`: 입력 귀속(§6)이 흔들 범위. 없으면 귀속은 등록부(`engine/coupling.js` 에 둘 귀속 배율)의 기본 배율을 쓰고, 그 사실을 보고에 적는다.
- `limitation`: `assumed` 면 필수(그 공백을 다루는 열린 한계). `unrecorded` 는 변환이 옛 값을 정직하게 들일 때만 쓰고, 새 기록에는 쓰지 못한다(관문 거부).
- **원장에 넣지 않는 것**: 수치 설정(dt_slow·event_tol·rtol·commitment)은 가정이 아니라 적분 선택이다. 시나리오와 결합점 등록부에 그대로 둔다.

### 3.3 시나리오가 가리키는 법

- 시나리오는 숫자 대신 번호를 쓴다: `"kinetics": { "D000207/rule/turnover": { "assume": "A000001" } }`, `"amounts": { "D000204|nucleoplasm": { "assume": "A000002" } }`.
- **컴파일러**(`compiler/ir_builder.js`, 순수)가 원장을 받아 번호를 숫자로 풀고, IR 에 `assumptions: [A…]` 목록을 싣는다. 엔진은 바뀌지 않는다 — 풀린 IR 은 지금과 비트로 같다.
- 사전 등록은 시나리오 해시와 **풀린 가정 내용 해시**를 함께 고정한다. 가정을 고치면 새 번호가 생기므로 옛 등록은 옛 번호를 그대로 가리킨다.
- 탐색 실행(미등록)은 숫자 직접 기입을 계속 허용한다. 다만 첫 장면 기원 감사가 그 숫자를 `unrecorded` 로 센다.

### 3.4 권력 배치

| 층 | 하는 일 |
|---|---|
| 입법 | 가정 초안(순수). 서기는 `registry` 구역에 `data/assumptions.jsonl` 을 더한다. 사전처럼 감사를 통과하고 봉인한 뒤에만 쓴다 |
| 사법 | `judicial/assumption_audit.js`(신설): 사슬, 슬롯 존재, 단위(`vocab.unitFactors`), 물리 범위(`vocab.physicalBounds`), `assumed` 의 한계 참조, revises 순환 없음, 같은 슬롯·같은 값 중복 금지 |
| 컴파일러 | 번호 → 숫자 풀기 + IR 에 목록 싣기 |
| 행정 | 바뀌지 않음 |

### 3.5 변환 (`migrations/012-assumption-ledger.mjs`)

- 미등록 시나리오 38개(시나리오 43개 − 등록 5개): 인라인 숫자를 슬롯·값으로 중복 제거해 `A…` 로 만들고, 시나리오를 번호 참조로 다시 쓴다. 전후 IR 해시와 궤적 비트가 같아야 한다.
- **등록된 시나리오 5개는 다시 쓰지 않는다**(해시가 바뀌면 등록이 깨진다). 원장 기록에 `seen_in` 으로 연결만 하고, 귀속은 내용 일치로 그 시나리오의 인라인 값을 찾는다.
- `origin` 은 지금 scene_origin 판정을 그대로 옮긴다(assumed 1,083·unrecorded 484·abstracted 39). 숫자를 새로 정하지 않는다.

### 3.6 금지된 우회

- 가정을 관찰 없이 db 값(V…)으로 옮기기
- 원장 기록을 고쳐 쓰기(revises 만 허용)
- 귀속 범위를 결론이 유지되도록 사후에 좁히기(범위는 등록 때 고정 — §6)

## 4. ② 판정 원장 `data/verdicts.jsonl` (G2)

### 4.1 무엇을 남기나 — 두 종류

| 종류 | 언제 | 칸 |
|---|---|---|
| `gate` | `augment apply`·`merge` 를 시도할 때마다(`validate` 단독 실행은 남기지 않음 — 잡음) | patch sha256 · 결과(accepted / rejected) · 거부 사유 코드 목록 · 결정자(`machine` 또는 사람 허락이 낀 경우 `human` — 예: `--allow-warnings`) |
| `validation` | 등록 규약 아래 `observe` 를 실행할 때 | 사전 등록 seq · 시나리오 sha256 · 가정 내용 해시 · IR 해시 · 관찰 O… · 결과(`vocab.qualOutcomes` 토큰) · 우연 기준선 · 음성 대조 결과 · 맥락 이전 깃발 · 의존 지문(`judicial/dependency.js`) |

해시 사슬이고 추가만 한다. 쓰기는 서기(`registry` 구역)만 한다. 내용은 조정자가 사법부 판결에서 옮긴다.

### 4.2 재현 검사

`verdicts --recheck`: 결정론이므로 `validation` 행은 다시 실행해 같은 결과가 나와야 한다(엔진 사법 원리 — 자기 보고를 믿지 않음). 다르면 그 행에 `revalidation_required` 를 붙이고, 원장을 고치지는 않는다.

### 4.3 이것으로 생기는 것

- **자동결정률** = `machine` 결정 / 전체 결정(gate 행 기준, 기간별). direction §1 의 방향값이 처음으로 숫자가 된다.
- **철회 파급**(§7)이 시나리오를 훑지 않고 판정 원장으로 결론에 바로 닿는다.
- 증거 색인(`evidence --all`)이 판정을 다시 계산하지 않고 원장을 읽는다.

## 5. ③ 측정법 통제 어휘 (G3)

- `vocab.assays`(신설, 라벨·의미는 vocab, en 은 사전): 첫 씨앗은 지금 관찰들이 실제로 쓴 방법만 넣는다(예: TRF 서던, 유세포 분석, 웨스턴, 효소 활성 측정). 지어내지 않는다.
- 관찰 두 모양 모두에 `assay` 칸을 둔다. 새 관찰에는 필수이고, 모르면 `unknown` 에 한계를 단다. 정량 관찰의 자유 문장 `method` 는 `note` 로 보존한다.
- 독립성: `chanceBaseline` 은 지금처럼 `experiment`·출처 단위로 묶는다. 여기에 **같은 읽을거리 + 같은 측정법을 공유하는 검증**에 "측정 공유" 깃발을 더한다(L000109 의 측정 축). 판정을 막지는 않는다.
- 변환 `migrations/013-assay.mjs`: 기존 관찰 28건은 원문을 확인한 것만 채우고, 나머지는 `unknown` 으로 둔다.

## 6. 입력 귀속 (TIER A, ①을 쓰는 첫 기능)

- **질문**: 이 결론은 실측 값에서 오는가, 가정 값에서 오는가.
- **방법**(조정자 → 사법부, 엔진 불변): 결론에 쓰인 IR 의 `assumptions` 목록에 있는 가정마다 `range` 의 양 끝으로 바꾼 파생 실행을 돌린다(교란 연산자와 같은 길 — `compiler/perturb.js` 에 `set_assumption` 추가). 그 뒤 판정을 다시 한다.
  - **강건**: 모든 가정을 범위 끝까지 흔들어도 정성 판정이 그대로다 → "이 결론은 가정 숫자에 기대지 않는다."
  - **민감**: 판정을 뒤집는 가정이 있다 → 그 가정 목록이 **다음에 실측할 표적**이다(수집을 겨냥한다).
- 범위와 판정 규칙은 **사전 등록 때 함께 고정**한다(사후에 좁히기 금지).
- 비용: 가정 k 개 × 2 실행. 텔로미어 시나리오는 실행 1회가 약 91ms라 수 초면 끝난다. 이것은 39번 Sobol(상호작용까지 보는 분산 분해)의 가벼운 선행이며, Sobol 은 39번에 그대로 남는다.
- 보고: 증거 보고서와 판정 원장 행에 `attribution { robust | sensitive, flips: [A…] }` 를 싣는다.

## 7. 불일치 원인 분류 (24번 L1 + 토의의 4축)

### 7.1 이름 하나로

토의의 A–D 축과 build-plan 의 오차 세 채널 A·B·C 는 **글자가 겹친다**(계획의 C 는 "예측 대 실측"이고, 토의의 C 는 "환경"이다). 그래서 글자를 쓰지 않고 토큰으로 정한다. **잔차**(예측 − 실측, 계획의 C 채널)는 관찰된 결과이고 원인이 아니다. 원인은 아래 여섯 가지 가운데에서 가린다.

| 토큰 (`vocab.discrepancyCauses`) | 뜻 | 가르는 방법 | 이미 있는 것 |
|---|---|---|---|
| `numerical` | 계산 오차 | 수렴 스윕(45), 허용 오차 1/1000 기준 실행 | `fault NUMERICAL`, `convergenceSweep` |
| `fluctuation` | 실제 분자 수 요동 | 앙상블, Fano | `stoch_audit.js` |
| `input` | 가정 값 탓 | 입력 귀속(§6)이 판정을 뒤집음 | 없음 → §6 |
| `context` | 세포·종·조건 차이 | **반사실 재실행**: 실험 쪽 맥락으로 바꿔 다시 돌려 판정이 뒤집히면 context. 그 맥락을 바꿀 손잡이가 모델에 없으면 → `structure` 후보 | V8 `contextTransfer`(표시만) |
| `structure` | 모델 추상화(빠진 단계·조절) | 위 넷을 배제한 뒤 남음 + 정성 그래프 "경로 없음·부호 섞임" | Structural·Regulatory_Gap |
| `data` | 관찰 쪽 문제(모순·철회) | 근거 대조, 다른 관찰과 충돌 | `DOMAIN_CONFLICT` |

### 7.2 규칙

- 불일치가 나면 기본값은 `undetermined`(원인 미정)다. 배제 검사를 통과한 원인만 이름을 얻는다. 이것이 24번의 끝나는 조건("분류 전 '원인 미정' 시험")이다.
- **C/D(맥락 대 구조)는 딱지가 아니라 개입으로 가른다.** 불일치 한 건만 보고는 원리적으로 가를 수 없다(식별 불가). 반사실 재실행이 유일한 근거다.
- 원인 판정은 판정 원장의 그 행에 `cause` 로 싣는다. 판정 자체를 고치지는 않는다.

## 8. 엔진 쪽 (7부 뒤쪽)

1. **두 갈래 차이 측정 먼저**: 같은 시나리오를 `simulateRate` 와 운명 엔진으로 돌려 궤적 차이를 잰다. 차이가 허용 오차 안이면 `simulateRate` 를 운명 엔진 위로 옮겨 하나로 만든다. 차이가 크면 어느 쪽이 해석해(44)에 맞는지로 정한다.
2. **엔진 경계**: 운명 엔진은 IR 만 받는다. 부분 구조(moiety) 표와 색인은 컴파일러가 IR 에 싣고, 조립은 조정자가 맡는다. 궤적 비트와 `rust_engine.test` 가 같아야 한다.
3. **LPS(L000113)**: 먼저 전체 모델을 벽시간 제한을 늘려 한 번 끝까지 돌릴 수 있는지 확인한다(축약을 인증할 기준해가 필요하기 때문). 돌아가면 47번 QSSA 를 운명 엔진에서 한다. 공간 엔진과의 묶음을 푼다. 기준해조차 못 얻으면 한계에 그 사실을 적고 멈춘다.

## 12. 열린 것

- 귀속 기본 배율(range 가 없을 때)의 값 — 수치 선택이라 결합점 등록부에서 정한다. 근거 없는 기본값은 보고에 "기본 배율 사용"으로 드러낸다.
- 정성 판정 말고 정량 판정(TOST)의 귀속은 정량 검증 관찰이 생긴 뒤에 한다(지금 0건).
- 판정 원장의 `gate` 행에 사람 결정을 어떻게 구별해 남길지 — 지금 확실한 신호는 `--allow-warnings` 하나뿐이다. 다른 사람 개입(대화로 승인)은 도구가 알 수 없으므로 `machine` 으로 셀 위험이 있다. 보수적으로 "기계 결정 = 관문이 경고 없이 통과/거부" 로만 정의한다.
