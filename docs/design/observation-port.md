# 관찰 포트 (Observation Port) — 설계 (2026-10-09 합의, 4단계에서 구현 — 완료: ① 형식(v10)·② 판정·⑥ `dbtool observe`)

> 하드웨어(HPLC·센서)는 아직 없다. 구현은 나중이어도 **들어오는 모양(계약)은 지금 정한다** — 핵심이 관찰을 받을 수 없는 모양으로 굳지 않게. 관찰이 장비·논문 표·공개 데이터셋 어디서 오든 같은 계약으로 들어온다.

## 1. 데이터 유입 원칙 — 지식은 손으로, 측정은 포트로

| 종류 | 길 | 이유 |
|---|---|---|
| 개념·기전·정의(T/D/S, 묶음, 규칙) | 직접 입력 — 에이전트 패치 → 관문 → 서기 (지금 그대로) | 맥락 판단·근거 구절·고정 번호·해상도 선택이 필요 |
| 측정값(HPLC·센서·데이터셋) | 포트만 — 원본 → 파서(해석만, 실행 안 함) → 관찰 연산자(해시) → 관찰 기록 초안 → 관문 → 서기 | 손으로 옮기면 오기·지어내기, 불확도·반복 수·보정이 빠짐. 양도 감당 못 함 |
| 속도 상수 | 문헌 값은 직접(근거와 함께). 포트 관찰에서의 추정은 나중 단계, 출처 표시 | 측정에서 나오지만 해석(단위·조건)을 거친 값 |

- 포트는 입법부를 우회하는 옆문이 아니다 — 변환을 자동화한 패치 생산기이고, 관문·서기를 똑같이 지난다 (`augment` 수신함 고리와 같은 모양).
- **추정에 쓴 관찰을 검증에 쓰지 않는다.** 관찰 기록에 용도 `estimation | validation`, 같은 관찰이 두 용도면 사법부가 거부한다.
- 원본 sha256 과 연산자 해시를 기록에 둔다 — 같은 원본은 같은 변환 해시.

## 1A. 다시 재지 않는다 — 측정 기록과 파생값의 분리 (구현: 4단계 ①, 형식 v10)

엔진·컴파일러·수치 선택·출력은 규모가 커지면서 바뀌어도 된다(데이터에서 다시 계산된다). **실측값은 바뀌면 안 된다** — 다시 재려면 실험이 필요하다. 실측값이 의미를 잃는 두 경로를 막는다.

| 경로 | 위험 | 막는 장치 |
|---|---|---|
| 값이 모델 표현에 묶여 저장 | 묶음 나열 → 규칙 기반(T2) 이행 때 "어떤 분자 상태에서 잰 값인가"를 잃음 | 관찰 기록에 조건(종·위치·온도·pH·**참여 분자의 부위 상태** `condition.states`)을 함께. 규칙의 상수는 `kinetics.from` 으로 관찰을 참조하는 파생값 — 표현이 바뀌면 파생값만 다시 계산 |
| 묶은 상수(힐 상수 등, 매개 단계 생략) | 기전을 세분하면 의미가 바뀜 | `lumped: true` + 원 관찰 참조 필수 — 다시 재지 않고 다시 맞춤 |

- 관찰 기록은 바뀌지 않는다: 바꿈·지움을 관문이 거부하고, 철회 표시(`retracted`)만 한 번 더할 수 있다.
- 형식 변환은 무손실: `migrations/009` 는 관찰 밖 필드가 바뀌면 변환하지 않고, 정규화는 관찰 기록에 멱등이다(`tests/observations.test.mjs` ⑤).
- 정의항의 `obs`(서열 길이·국재 같은 정의 속성)는 그대로 둔다 — 지금 수치 obs 2건(서열 길이·세포당 분자 수)은 불확도가 없는 정의 속성이다. 엔진·사법부가 쓰는 측정은 관찰 기록으로.

## 2. 계약 (`schemas/obs/observation.schema.json`, 4단계)

`[value]` 가 아니라 `[value, uncertainty, precision]` 이상:

| 필드 | 뜻 |
|---|---|
| observable | 측정량 ↔ 모델 양 대응(묶음 키·운명 비율·사건 시각 …) — 관찰 연산자 입력 |
| value · unit | SI 정준 단위 |
| uncertainty | 크기와 유형: `measurement`(장비) · `biological`(개체·세포 간) · `combined` |
| precision · detection_limit | 분해능, 검출 한계 |
| replicates | 반복 수 (분포 관찰이면 표본) |
| condition | 시나리오 대응(종·위치·시각·처치) |
| calibration | 보정(항등 · 선형 · 보정 표) — 비선형 측정은 포트가 흡수, 엔진은 모름 |
| provenance · use | 출처(원본 sha256) · `estimation | validation` |

## 3. 권력 배치

| 층 | 맡는 것 |
|---|---|
| 입법부 | 관찰 기록 저장(패치·관문·서기) |
| 컴파일러 | 관찰 연산자(보정 포함) — 순수 함수, 해시 |
| 행정부 | **관찰을 읽지 않는다** (읽으면 관찰에 맞추느라 결함을 덮는 순환 오류) |
| 사법부 | 모델 분포 ⊛ 측정 잡음 모형 ↔ 관찰 비교, 3 판정 |

## 4. 판정 — "너무 시끄럽다"가 아니라 "가를 수 없다" (구현: 4단계 ②, `judicial/obs_compare.js`)

| 판정 | 조건 | 결함 태그 |
|---|---|---|
| CONSISTENT | 가설 하나: 선언된 δ(근거 등급 parameter 이상) 안임을 동등성 검정(TOST)으로 보임 · 가설 둘: 이 가설만 기각되지 않음 (2026-10-15, M1 — 기각 못 함은 일치가 아님) | FINDING |
| CONFLICT | 밖 — 모델 오류 | DOMAIN_CONFLICT |
| INDISTINGUISHABLE | 이 오차 막대로 경쟁 가설(compare 의 Behavior-Changing 쌍)을 가를 수 없음, 또는 가설 하나인데 일치를 보이지 못함(δ 미선언·근거 등급 미달·정밀도 부족) | `Observation_Gap` (필요 정밀도를 requirement 에) |

- 잡음 모형은 최소 집합: 정규 · 로그정규 · 계수(포아송). 쓰이지 않는 분기는 넣지 않는다.
- 시험은 `hypothetical` 합성 관찰로만 — 실측값을 지어내지 않는다.
- 불확도 유형의 해석: measurement = 같은 양을 replicates 번 잰 평균(표준 오차 sd/√r), biological = 개체 r 개의 평균과 개체 간 퍼짐(확률 앙상블이면 F 검정, 결정론이면 "판정할 수 없음" 메모), combined = 합산 퍼짐(모델 퍼짐이 넘으면 모순).
- 모델 쪽 몬테카를로 오차(s²/n)를 더한다 — 필요한 정밀도를 계산할 때는 빼고 "앙상블을 늘려야 함"을 따로 알린다.
- 한 가설이 측정량을 내지 않으면(도달하지 않음) 관찰의 존재 자체로 가른다.
- 관찰 없이도 `design(o, A, B)` 로 두 가설을 가를 반복 수를 계산한다 — Observation_Gap 의 요구 사항.
